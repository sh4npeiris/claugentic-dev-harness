## Problem

The harness ships a **condensation discipline** but not its **trigger**, so in an adopter's repo the discipline is orphaned and the managed ledgers silently rot.

Concretely:

- `scripts/check_doc_budgets.py` — the only thing that emits a doc-budget **WARN** — is in `build_release.py`'s DEV-ONLY strip set (`scripts/build_release.py:53`). The comment there is honest about *why*: the caps are harness-tuned and the script "fail-louds on the harness-only INVARIANTS.md" — it would error in an adopter repo. So an **adopter's repo never receives the gate and can never produce a WARN.**
- Yet the SHIPPED seed `docs/claugentic-_DECISIONS.md:3` (copied by `init` to the adopter's `DECISIONS.md`, stripping the underscore — `skills/init/SKILL.md` step 7) tells the adopter: *"condense it periodically **when the doc-budget WARN fires**"* — a trigger their repo can't produce.
- The SHIPPED `docs/claugentic-WORKFLOW.md` → Definition of Done frames the whole condensation procedure (`docs/claugentic-WORKFLOW.md:159-167`) around *"A ≥90% doc-budget WARN is a do-it-now signal"* — again, orphaned for an adopter (the adopter-note at `:146` even says the script isn't present in their repo, which is exactly the contradiction).

**The discipline ships; its trigger doesn't.** In the harness's own repo the mechanism is sound: the gate runs, and `DECISIONS.md` is currently at **84.6% (50764/60000 bytes)** — under budget, gate green, **no WARN** (the condensation was applied + committed this session at `1a233b9`). The harness-self repo is *not* the motivation — it is healthy. The failure is entirely on the **adopter** side: in an adopter's repo there is no WARN surface at all, so a ledger grows unbounded until an agent happens to notice — the mechanism the harness advertises does not work in real-world adopter use. (This plan does **not** lean on a live harness-self WARN — there isn't one; it leans on the adopter-orphaned-trigger gap, which is fully verified and stands on its own.)

Two adjacent, smaller gaps ride along:

- The **escape valve is undocumented.** When condensation genuinely can't reach the band (all content is live), there is no honest, recorded ladder — an agent is left either over-cutting live constraints or stuck at the cap. `docs/claugentic-ROADMAP.md:42` parks sharding as the last resort but names no intermediate rung (promote-to-home; a recorded cap-bump).
- The **charter has no write-trigger.** `docs/claugentic-_CHARTER.md` ships and `init` seeds it, but charter population is 100% model-upheld with **no prompt anywhere** that fires when a slice chose a non-default methodology — so in practice the charter stays empty (the harness's own live `CHARTER.md` legitimately doesn't exist; an adopter's would silently never populate either).

**Maintainer's requirement:** *"condensation of all docs with budget cap needs a proper way to handle it in all scenarios so that in real-world use the harness can work."*

## Goals / Non-goals

- **Goal:** a robust, all-scenarios doc-lifecycle that works for **adopters**, not just the harness-self repo — a portable WARN surface, a first-class condensation operator, an honest escape-valve ladder, and a per-repo caps config that is the single source of truth for both. The caps config has **one** structural schema — a JSON map `{ "<relpath>": <max_bytes>, ... }` (relative path → integer byte cap; an absent key = that file is un-capped/skipped) — consumed by **both** the Slice-1 doctor read and the Slice-3 cap-bump, so the single-source is structural (a shared shape), not merely asserted.
- **Goal:** fix every orphaned "doc-budget WARN" reference in the SHIPPED set so no shipped copy points an adopter at a trigger their repo can't produce (upholds the `docs/claugentic-INVARIANTS.md` release-strips ⇒ nothing-dangles invariant, extended from *paths* to *triggers*).
- **Goal (folded-in):** give the engineering charter a reliable write-trigger so a chosen non-default methodology gets recorded — while keeping it defaults-safe (empty charter ≡ default behavior).
- **Non-goal — NO doc-budget pre-commit HOOK.** The only hook-enforced gate stays the architecture-tree check (`docs/claugentic-INVARIANTS.md`, CLAUDE.md). The portable surface is a **`/doctor` advisory**, read-only, never a hook.
- **Non-goal — NO ledger-sharding BUILD.** Sharding stays parked in `docs/claugentic-ROADMAP.md` as the last-resort scaling lever; a cap-bump preserves the single-scannable-record property for an append-style ledger, so sharding is not needed now (YAGNI).
- **Non-goal — NO mechanical "what-to-cut" decider.** Condensation is judgment; automating the cut would launder judgment into apparent mechanical fact and violate the honesty rules. The `/condense` skill is prose-orchestrated with no bundled agent and no cut-decider.
- **Non-goal — the charter stays OPTIONAL.** The write-trigger only strengthens *recording when a non-default approach was chosen*; it does not make the charter required, and an empty charter still ≡ default behavior.
- **Non-goal — do NOT ship the harness's own byte-caps to adopters.** The harness caps are harness-tuned (they live in `scripts/check_doc_budgets.py:47-56` as `DOC_BUDGETS` and fail-loud on adopter files — that is *why* the gate is stripped). The adopter caps are their **own** config (Slice 3), skip-when-absent.
- **Non-goal — NO second cap list (DRY boundary).** There is exactly **one** adopter-side caps list: the per-repo caps config (home: a `.claude/`-local file `.claude/claugentic-doc-budgets.json`, see Slice 3). The doctor budget read **never** reads `scripts/check_doc_budgets.py`'s `DOC_BUDGETS`; nothing hardcodes adopter caps in a second place. Any duplication of caps is a DRY defect the `maintainability-structure` lens must reject.
- **Non-goal — the doctor budget read NEVER fail-louds on an adopter.** With no caps config present, the read is **silently skipped** (`N-A`, no output, no error, no false WARN, no breach). It inherits the exact safety property that made the harness gate un-shippable in the first place.

## Approach

Split the concern into four distinct, DRY-connected pieces plus a dogfood:

1. **A portable trigger** (Slice 1) — a config-driven, read-only budget read inside `/doctor` that reads per-repo caps and surfaces a WARN advisory. This replaces the orphaned "the gate WARNs" trigger in an adopter's repo without shipping a gate or a hook.
2. **A first-class operator** (Slice 2) — a `/condense` skill that encodes the WORKFLOW condensation procedure as an executable, ordered, guarded operation with the anti-footgun classify-first step. Ships to adopters; reuses `/doctor`'s existing user-approved-diff apply path.
3. **An escape valve + the config** (Slice 3) — the recorded escalation ladder for genuinely-all-live content, and the single per-repo caps config (home: `.claude/claugentic-doc-budgets.json`, schema `{ "<relpath>": <max_bytes> }`) that both Slice-1's doctor read and this slice's cap-bump depend on (DIP). Slice 1 defines the reader's contract (schema + skip-when-absent); Slice 3 only adds the writer (cap-bump) + the escape-valve doc against that **same** schema, so the two slices cannot drift into two contracts.
4. **The charter write-trigger** (Slice 4) — a small Stage-4/Stage-9 prompt so a chosen non-default methodology reliably reaches `docs/claugentic-CHARTER.md`.
5. **Dogfood — verify/finalize** (Slice 5) — the condensation of the harness's own `docs/claugentic-DECISIONS.md` is **already applied + committed this session** (`1a233b9`; live file byte-identical to the vetted scratchpad proposal, now 84.6%). Slice 5 does **not** re-apply anything; it **verifies/finalizes** the already-applied dogfood — confirming the ledger is under-budget and that running Slice 2's new `/condense` procedure on the pre-condensation ledger reproduces the same shape (the executable proof of the Slice-2 skill on a real case). Gated on Slice 2 landing.

**Alternatives considered and rejected:**

- *Ship `check_doc_budgets.py` to adopters unchanged* — rejected: it fail-louds on adopter files (harness-tuned caps + the INVARIANTS.md row), which is the documented reason it is stripped (`build_release.py:53`, `docs/claugentic-INVARIANTS.md` release-contract entry).
- *Ship an adopter-tuned copy of the gate as a run-gate* — rejected: it re-introduces a harness-owned gate into the adopter's DoD (their DoD is *their* gates — `docs/claugentic-WORKFLOW.md:146`), and any gate invites the "why isn't it a hook" pressure the non-goal forbids. A `/doctor` advisory is the honest altitude: read-only, model-surfaced, no exit-code authority.
- *A dedicated pre-commit condensation hook* — rejected outright (non-goal; violates the one-hook rule; and 0035 already set the precedent of declining a new enforcement hook).
- *Build sharding now* — rejected (YAGNI; a recorded cap-bump preserves the single-scannable-record property for an append ledger).

## Architecture & holistic fit

**The four concerns are genuinely distinct (SoC) and connect through one config (DIP)** — this is the load-bearing architecture:

- **The trigger** (Slice 1: doctor's budget read) — *notices* a ledger is near its cap and *says so*. It is a **read-only advisory**, not an actor.
- **The operator** (Slice 2: `/condense`) — *does* the condensation when triggered. It is an actor, but a **prose-orchestrated, judgment-driven** one — no mechanical cut-decider.
- **The escape valve** (Slice 3: the ladder) — the *recourse when the operator can't reach the band*. A distinct concern from both noticing and doing.
- **The config** (Slice 3: per-repo caps) — the **single source of truth** the trigger reads and the cap-bump rung writes. It has **one structural schema** — a JSON map `{ "<relpath>": <max_bytes>, ... }` — at **one canonical home**: `.claude/claugentic-doc-budgets.json`. Both Slice-1's doctor read and Slice-3's cap-bump **depend on this one config against this one shape** (DIP: neither hardcodes caps; the shared schema is the abstraction both invert onto — single-source is structural, not asserted). This is the DRY spine — one file, one shape, holds "what this repo's caps are"; configurable-over-hardcoded is honored, and there is no second cap list anywhere.

**Codebase fit — layering / placement:**

- **Slice 1** extends `skills/doctor/SKILL.md`'s existing "deterministic gates" table with an **adopter-portable row** that is explicitly `[J]`-advisory (a byte count is `[D]`; "condense soon" is `[J]`; the row's Source column reads `[J] advisory (read-only — not a gate)`). It does **not** add a gate script, a hook, or an always-loaded doc — matching doctor's own "What doctor is NOT" contract (`skills/doctor/SKILL.md:191-199`). Doctor stays strictly read-only through Diagnose; the budget read is a Diagnose check. **Skip-when-absent is the adopter default:** when no `.claude/claugentic-doc-budgets.json` is present, the read is silently skipped (`N-A`, no output) — never an error, never a false WARN, never a breach. This is the whole reason the harness gate is stripped; the portable read inherits that safety.
- **Slice 2** adds `skills/condense/SKILL.md` — a new auto-discovered skill (ships to adopters; not in `build_release.py`'s strip set, so default-include ships it). It is **prose-orchestrated and spawns no bundled agent** (like `/doctor` itself — `skills/doctor/SKILL.md:7`). It reuses `/doctor`'s **existing** "apply a user-approved doc-condensation diff" treat-path (`skills/doctor/SKILL.md:162`) rather than duplicating an apply path (DRY) — the honesty framing there (*the approval IS the decision gate*) transfers verbatim.
- **Slice 3** places the caps config at a named canonical home: **`.claude/claugentic-doc-budgets.json`** — a small `.claude/`-local JSON file with the schema `{ "<relpath>": <max_bytes>, ... }`. *Justification (KISS + release/init fit):* a `.claude/`-local file (vs a fenced block inside the adopter's `CLAUDE.md`) keeps the config machine-parseable for the doctor read and the cap-bump writer without a fence-parsing step, and — being adopter-owned, not managed — it sits **outside** the release/init managed-set, so it creates no stripped-uncreated-path dangle and `init` need not recreate it (sidesteps the three-kinds managed-file contract entirely). It is the **one** source both the doctor read and the cap-bump use; **no second cap list exists** (the doctor read never consults `check_doc_budgets.py`'s `DOC_BUDGETS`). The escape-valve ladder is documented in `docs/claugentic-WORKFLOW.md` (Definition of Done → the condensation pass), extending the existing lever-order list with the "can't reach the band" cascade.
- **Slice 4** adds a small prompt to the Stage-4 (Spec) or Stage-9 (harvest) flow in `docs/claugentic-WORKFLOW.md` (the exact stage a spec decision) so a chosen non-default approach is written to `docs/claugentic-CHARTER.md`. Defaults-safe: no prompt fires when the default grain was used.

**Product fit — the adopter experience IS the whole point.** The job-to-be-done: *an adopter's managed ledgers stay lean over months of real use without the adopter having to know the harness's internal gate exists.* Today that job silently fails (no WARN surface). Slice 1 gives them the surface (`/doctor` becomes the portable "DECISIONS at 92% of your configured cap — condense soon"); Slice 2 makes the fix a **ramp, not a dead-end** (`/doctor` and the DoD OFFER `/condense` on a WARN/breach); Slice 3 gives the honest recourse when condensation legitimately can't win. This is not user-facing UI (no felt/visual craft bar — effort-dial: these are skill/doc/config surfaces), but it *is* the adopter's product experience of the harness.

**Quality dimensions to uphold** (each mapped to its real `docs/claugentic-standards/` module):

- **`docs-traceability`** — every shipped reference to a condensation *trigger* must resolve to something the reading repo can actually produce (the core fix); no orphaned pointers.
- **`product-ux`** — the adopter experience is the deliverable; the WARN→OFFER-`/condense`→escape-valve path must read as a coherent ramp, not a set of disconnected mechanisms.
- **`reliability-resilience`** — the `/condense` procedure must be **reliable for a non-expert agent**: the classify-first / absorb-landed ordering is the reliability contract (the "preserve landed records" inversion failed agents 3× this session — the skill must make that failure structurally hard).
- **`maintainability-structure`** — the caps config as single source of truth (DRY/DIP); no second cap list, no hardcoded caps in two places.
- **Trust surface → `honesty-reviewer` (Plan + Verify).** This change touches the `[D]`/`[J]` boundary directly: the doctor budget read must present the byte count as `[D]` and "condense soon" as `[J]`, and must **never** claim the read is a mechanical gate — it is an **advisory** (Source column reads `[J] advisory (read-only — not a gate)`). The `/condense` skill must never claim it *mechanically decides* what to cut — condensation is judgment; `/condense` classifies and proposes, the human approves. The design itself needs no change to satisfy this (the honesty posture is already right); the requirement is that the **Slice-1/Slice-2 specs carry the exact Source-column wording and the "no cut-decider / classify-first" contract verbatim**, so the honesty framing survives into implementation. The diverse panel (`synthesizer-gate` + `yagni-sentinel` + `honesty-reviewer`) is in-scope at both gates.

**Future-proofing (without building it now):** the caps config is the seam a future sharding lever would also read (it would consult the same caps to decide when a ledger is un-condensable) — so parking sharding in ROADMAP while landing the config keeps that door open without building through it (YAGNI). The escape-valve ladder is written as an ordered cascade so a future rung slots in without re-architecting.
