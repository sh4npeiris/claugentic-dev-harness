## Problem — the release/init contract is violated

**The principle (a new INVARIANT, user-stated 2026-06-25):** *"Whatever the release strips, init must (re)create so the harness works in the adopter's project context."* Refined: the release strips **two classes** —
- **Class A — harness-DEV tooling** (`build_release.py`, `check_versions_synced.py`, `check_doc_budgets.py`, `tests/`, `eval/`, `RELEASE_CHECKLIST.md`, `.github/`, `pyproject.toml`, configs, the harness's OWN plans): about building the *plugin*. Adopters correctly never get these.
- **Class B — adopter-relevant state/templates** (`DECISIONS.md`, `ROADMAP.md`, `ARCHITECTURE_TREE.md`, `INVARIANTS.md`, the plan `TEMPLATE.md`, `PRODUCT*`): the workflow produces/uses these in ANY repo. **init must recreate fresh ones, and nothing shipped may reference a Class-B file that isn't created — nor a Class-A (harness-self) gate without adopter-awareness.**

**Confirmed violations (systematic audit, 2026-06-25):**
1. **★ Plan `TEMPLATE.md` — Class B, stripped, NOT init-created, but referenced by shipped docs.** It lives under the `.claude/plans/` DEV_ONLY_DIR (stripped wholesale) and init never creates it — yet the **shipped** `docs/claugentic-WORKFLOW.md` (`:54,:93,:97,:184,:241`) + `skills/build/SKILL.md:294` say a plan is *"structured by `TEMPLATE.md`."* → an adopter's plan-drafting points at a file that doesn't exist. (Degraded, not a crash — the agent can fall back to WORKFLOW's inline structure — but a real dangling ref.)
2. **★ `check_doc_budgets.py` — Class-A (harness-self) gate leaking, with a NEW 0.3.0 fail-loud.** Its own docstring: *"same register as `check_versions_synced.py`"* (which IS stripped). It budgets the harness's OWN ledgers incl. `INVARIANTS.md`, and **fail-louds if a budgeted ledger is missing** — but init doesn't create `INVARIANTS.md` (lazy). 0024 added the INVARIANTS budget row, so a fresh 0.3.0 adopter who runs it hits *"INVARIANTS.md is missing"* where v0.2.4's 3-ledger version didn't. Plus the budgets (6 KB CLAUDE / 60 KB DECISIONS) are harness-tuned. **Referenced by:** `skills/doctor/SKILL.md:50` (doctor RUNS it), `docs/claugentic-WORKFLOW.md:135` (DoD lists it, NO skip-caveat — unlike version-sync at `:134`).
3. **Harness-self gates leak into adopter surfaces without adopter-awareness (the pattern).** `skills/doctor/SKILL.md:48,50` runs `check_versions_synced.py` + `check_doc_budgets.py` (both harness-self — version-sync checks the PLUGIN's two manifests an adopter doesn't have; doc-budgets as above). `.claude/agents/implementer.md:18` tells the adopter's implementer to run `check_versions_synced.py`. WORKFLOW handles version-sync (`:123,:134` skip-caveat) but NOT doc-budgets (`:135`). So `doctor` + `implementer` would run harness-self gates that error for an adopter.
4. **`INVARIANTS.md` — Class B, correctly lazy** (Stage-9: "create lazily, don't seed empty"). NOT a gap on its own — only via #2 (the doc-budgets gate hard-requiring it). Resolved once #2 is.

## Design — RESOLVED + refined (2026-06-25 conversation)

**FORK A — plan TEMPLATE → MOVE to `/docs/` as a managed template (NOT the carve-out).** Rather than teach `build_release` to "strip `.claude/plans/` EXCEPT TEMPLATE.md" (an exception that rots), **move `.claude/plans/TEMPLATE.md` → `docs/claugentic-PLAN_TEMPLATE.md`** (a repeated-use managed template, like `docs/claugentic-PRODUCT_SPEC_TEMPLATE.md` + `docs/claugentic-standards/_TEMPLATE.md`). It then ships normally (no strip special-case), init copies it like any managed doc, and the WORKFLOW/build-SKILL refs point at `docs/claugentic-PLAN_TEMPLATE.md`. The harness's own *plans* stay in `.claude/plans/` (all stripped); only the TEMPLATE moves out. The adopter reads the `/docs/` template and writes plans into their own `.claude/plans/` (no copy of the template into `.claude/plans/` needed).

**FORK B — `check_doc_budgets.py` is harness-self → strip it + make doctor/WORKFLOW/implementer adopter-aware.** ★ Correction: **`doctor` runs ALL THREE gates** — `claugentic-check_architecture_tree.py` (adopter-relevant — KEEP) **+** `check_versions_synced.py` **+** `check_doc_budgets.py` (both harness-self). Adopter-aware fix: doctor **detects an adopter repo** (simple signal: `scripts/check_versions_synced.py` is absent — it's stripped) and **runs only the tree gate**, marking version-sync + doc-budgets harness-self/N-A. Plus: strip `check_doc_budgets.py` from the release; add the WORKFLOW DoD doc-budget skip-caveat (mirror version-sync `:134`); reframe `implementer.md:18`'s version-sync line as harness-self.

**The managed-file model (the conversation's organizing principle — guides S1 + the follow-up):**
- **Full docs copied verbatim** (WORKFLOW, PLAYBOOK, ENGINEERING_STANDARDS, standards/*): source = ship = adopter copy. **No `_template` needed** (they're not seeds; renaming them would churn + force the harness to copy its own template to use it).
- **Templates/seeds where the harness's OWN copy diverges from the adopter's** → the `_template` source-of-truth pattern. Two sub-kinds, copied differently:
  - **Repeated-use templates** (plan template, standards `_TEMPLATE.md`, `PRODUCT_SPEC_TEMPLATE.md`): adopter KEEPS them as templates, copies one per use → stay `*_TEMPLATE.md`, **no rename.** ← the plan template joins this set (S1).
  - **One-time seeds** (DECISIONS, ROADMAP): adopter gets ONE file filled over time → `_X.md` **renamed to** `X.md` on copy. Currently these seeds are **prose buried in the init skill**, not files.

**FOLLOW-UP (NOT in 0027 — a separate, reviewed refactor):** migrate the one-time seeds (DECISIONS/ROADMAP, + the init-prose seed content generally) to `_template` FILES, standardize the naming convention, so init copies from files instead of embedding seed prose. A real consistency win, but it touches init's seeding logic + the ledgers + needs its own tests, and does NOT block the release. KISS: 0027 unblocks the release; this refactor earns its own slice. _(Roadmap it at 0027 Land.)_
