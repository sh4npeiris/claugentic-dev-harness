## Problem

The 2026-06-11 multi-lens review (7 lenses, 47 agents; every high/medium finding adversarially re-checked by `finding-verifier` — 13 of 40 refuted) verified a single root weakness class: **the harness's choreography is specified in prose but upheld only as well as a model follows prose.**

Verified instances:
- The cross-model judge — the central trust mechanism — is named everywhere but operationally specified nowhere (`docs/WORKFLOW.md:37-39`); a fresh orchestrator cannot perform the `fable` spawn override from the docs alone, and fallback detection is itself model-upheld.
- The diverse panel "does not fire by itself" (`docs/WORKFLOW.md:36`) — convening is remembered, not executed.
- There is **no CI**, so the "deterministic gates" of the Definition of Done (`docs/WORKFLOW.md:112-117`) run only when a model remembers — the exact launder the honesty register forbids.
- The gate script has real bugs: non-ASCII filenames perma-red via git `core.quotepath` octal-escaping (`scripts/check_architecture_tree.py`, `_git` output never unquoted); the presence check is raw substring containment (a root `a.py` reads as indexed because `scripts/a.py` appears anywhere in the tree text); the Stop hook ignores `stop_hook_active` (no loop-breaker); `subprocess.run(text=True)` decodes with the locale codepage.
- ~1,500 lines of skill prose specify behavior to verbatim precision with zero prompt-level tests — model drift is detectable only by dogfooding.
- The harness reviews code as **text only**; nothing runs the product. "Is this product good" is unanswerable by the current Verify stage.

Meanwhile the platform now ships the `Workflow` tool: deterministic script orchestration (fan-out, pipeline, adversarial verify, budget caps, resume) with per-call `model:` and `agentType:` parameters. What the SKILLs uphold in prose can become code the model cannot forget to run.

The user's goal (recorded in DECISIONS → Harness v2): a harness any developer installs so different users/agents ship uniform, standards-upheld code; **build-to-green autonomy** (approve the spec, the loop iterates unwatched until gates + acceptance criteria pass, pause at release); a **product-gap review** ("is this product what it intended to be"); then complete the the team suite with it, starting with the an adopter pilot.

## Goals / Non-goals

- **Goal 1 — Choreography as code:** the audit pipeline (FIND→PRUNE→VERIFY), the Verify panel, and the build loop ship as Workflow scripts under `workflows/` in the plugin, invoked via `scriptPath` at the version-stamped plugin install path. Skills become thin triggers + the judgment prompts. The cross-model judge spawn becomes a literal `model:` parameter in script. **Spike-verified (2026-06-11, pre-slice — Review change #1):** in a Workflow run from a Fable-5 session, `agent(…, {model: 'opus'})` resolved to **Opus 4.8**, the default call inherited Fable 5, and an `agentType` whose frontmatter reads `model: opus` also resolved to Opus — evidence is the harness-injected model id each agent self-reported. The coded same-model detection remains the **per-run guard**: a run claims "cross-model" only on a confirming self-report; on fallback or a non-confirming report it carries the same-model tag. (DECISIONS entry at first land.)
- **Goal 2 — Deterministic trust-gates:** CI for this repo (pytest + both gate scripts, ubuntu + windows); fix the four verified gate-script bugs; `init` gains a CI-composition step (wire the tree-check + tests into an adopter's existing CI, or scaffold a minimal workflow where none exists — an adopter already has `ci.yml`; compose, don't replace).
- **Goal 3 — Earned autonomy ladder (a risk reduction, honestly scoped):** `build` gains **build-to-green** mode — *eligible* per-repo only when (a) CI runs the deterministic gates, (b) a test baseline exists for touched code, (c) the item traces to a spec with testable acceptance criteria. Inner loop: implement → gates → runtime-verify → fix → repeat until green; pauses only at release/irreversible. **Scope of the claim (Review change #2):** the unlock conditions gate *eligibility*, not a guarantee a bad change can't land; the script runs the gates mechanically *once invoked*, but invoking it is itself model-upheld; and the deterministic trust-gates DECISIONS records as **not built** (the land-gate hook · secret-scan · characterization-first hook) are not built by this plan either — build-to-green is **a reduction of unwatched-run risk, never their substitute**, and the superseding copy carries this scoping verbatim. Where conditions are unmet it declines exactly as `autopilot` does today, naming what's missing.
- **Goal 4 — Runtime verification (QA) workflow:** spin the app (docker compose for the suite stack; configurable run command otherwise), drive the spec'd flows with the platform's browser tooling (Playwright), check empty/loading/error states, capture screenshots, report findings in the same shape as `lens-reviewer` so they join the existing dedup→prune→verify path.
- **Goal 5 — Product layer:** a `product-spec` flow (Discuss-driven rebuild of `docs/PRODUCT_SPEC.md` with **testable acceptance criteria** per feature/flow) and a `product-gap` audit (intent vs. implementation → completion backlog into the existing `harness-audit:backlog` fence, same tags/verification).
- **Goal 6 — A measured harness:** one fixture repo with seeded defects + a recorded baseline (audit recall/precision/refute-rate) so prompt/model drift becomes measurable. Minimal: one fixture, one metric file, run manually as a release-checklist step (no CI-hosted LLM runs).
- **Non-goal:** rewriting the standards-catalog content (separate ROADMAP item — "Standards-catalog integrity pass").
- **Non-goal:** inverting copy-on-init distribution. Copied standards/docs are *good* for team visibility in a shared repo; only the **workflow scripts** are read from the plugin install path (new artifacts, never copied — no stamp/refresh surface added).
- **Non-goal:** multi-stack runtime adapters beyond (docker compose | a configurable dev-server command). No per-framework plugins.
- **Non-goal:** autonomous deploys. Build-to-green stops at "release-ready"; release remains a human act (irreversible hard-stop set unchanged).

## Approach

**The split that drives everything: judgment stays in prompts; sequence, fan-out, model selection, verification coverage, and budget move into Workflow scripts.**

- `workflows/audit.js` — the FIND→PRUNE→VERIFY pipeline as script: lens fan-out per `(module×dir)` cell at the dialed depth, dedup in code, `thorough`-only blindspot + yagni stages, **one `finding-verifier` per surfaced finding enforced by the script** (the "re-check every finding" claim becomes mechanical), judge spawns carry an explicit cross-model `model:` parameter with coded fallback + same-model tagging. `skills/audit/SKILL.md` shrinks to: trigger, Phase-1 inline overview (stays conversational — it needs the user), dial selection, invoke the script, render the backlog.
- `workflows/verify.js` — the Stage-7 panel: diff-scoped lens fan-out + `yagni-sentinel` + (trust-surface trigger) `honesty-reviewer` + `architect-reviewer` synthesis. The panel **always** convenes when the script runs; the effort dial selects script inputs, not whether stages exist.
- `workflows/qa.js` — runtime verification (Goal 4). Inputs: the acceptance criteria + how to run the app. Output: lens-shaped findings + screenshot artifacts.
- `workflows/build-item.js` — the per-item build-to-green engine (Goal 3): implement (worktree) → deterministic gates → `verify.js` → `qa.js` (when acceptance criteria exist) → fix loop until green or blocked. `skills/build/SKILL.md` keeps the triage/approval conversation (genuinely human-in-the-loop) and delegates the engine.
- Scripts live in `workflows/` in the plugin repo; skills invoke them via `scriptPath` at the **plugin install path**, resolved with the same plugin-root reference the skills already use for bundled docs (`${CLAUDE_PLUGIN_ROOT}`). **No plugin-manifest field exists or is needed for workflows — discovery is the skill passing the absolute path** (Review change #3; manifest edits in this plan are version bumps only). Cross-family `model:` resolution is spike-verified (Goal 1); **scriptPath-at-install-path invocation is the first act of Slice 2** — if it fails, scripts fall back to being copied like the other managed files (a one-line distribution change, recorded at Land). **Fallback honesty:** if the Workflow tool is unavailable in a session, skills state so and run the legacy prose path, tagging the run "prose-orchestrated" — never silently claiming script guarantees.
- **Pure decision logic is tested, not just inspectable (Review change #5):** each script keeps its pure helpers — dedup keys, tier mapping, the `MODELS` fallback chain, same-model detection — in a marked `// --- helpers ---` block; `tests/workflows/*.test.mjs` (run by `node --test`, wired into CI from Slice 2) extract and exercise that block. The thin control flow around them is pinned by dogfood runs + the eval fixture (Slice 7).
- Alternatives considered: *keep prose, add more discipline* — rejected: the review showed prose-upholding is the failure class itself. *Invert distribution entirely (read everything from plugin path)* — rejected for standards/docs (team visibility in-repo is a feature; copy-on-init just stabilized in 0010/0011); adopted only for scripts, which never existed as copies. *Ship eval harness as CI* — rejected for now: LLM-in-CI cost/flakiness; manual release-checklist run first.

## Risks & mitigations

- **Workflow tool availability varies by client/session** → every skill carries the honest fallback: detect, state, run prose path, tag the run. Never claim script guarantees on a prose run.
- **Invoking the script is itself model-upheld** (the platform doesn't auto-fire workflows) → never claim "the harness runs X automatically"; the honest verb is "the skill invokes the script, and the script then runs X mechanically." The copy register (Goal 3 scoping) carries this everywhere autonomy is described.
- **Workflow scripts run only inside the tool** → keep scripts thin (control flow only); pure decision helpers live in a marked `// --- helpers ---` block per script, unit-tested via `tests/workflows/*.test.mjs` (`node --test`, in CI); the remaining untested surface (the thin control flow) is pinned by the eval fixture run (Goal 6) + dogfooding this repo.
- **Model-id pins (`fable`/`opus`) rot** → ids live in ONE `const MODELS = {...}` block per script with a coded fallback chain; same-model runs tagged by code, not memory.
- **`qa.js` flakiness (app boot, ports, timing)** → bounded retries, explicit "could not run the app" finding class (never silent skip — a QA pass that didn't run reports that it didn't run), screenshots on failure.
- **Build-to-green burns tokens on a stuck loop** → per-item iteration cap + budget guard in script; on cap: stop, report state honestly ("not green; here's the residual"), never land partial (existing rule).
- **Scope creep toward the suite** → the an adopter pilot is a *separate plan in the an adopter repo* after slices 1–5 land here; this plan only builds the machine.
- **Honesty regression risk** (new claims like "the script enforces X") → `honesty-reviewer` joins Verify on every slice touching skills/docs/README (trust surfaces — the existing panel trigger already mandates this).

## Test strategy

- Gate-script fixes: hermetic characterization tests per bug + one real-git integration test (tmp repo, non-ASCII filename) marked `integration`.
- CI proves itself: the first green run on both OSes is the acceptance evidence for slice 1.
- Workflow helpers: `node --test tests/workflows/` green is a per-slice acceptance criterion for every slice that adds or changes a script (2 through 5b).
- Workflow scripts: dogfood runs on this repo (audit + verify) and the eval fixture (seeded defects found/refuted at recorded rates); resume behavior exercised by killing one run mid-pipeline.
- `qa.js`: a minimal compose fixture (tiny FastAPI+Next.js hello app in `eval/fixture-app/` or reuse of the defects fixture) driven end-to-end; failure modes (app won't boot, flow fails) produce the explicit finding classes.
- Honesty: `honesty-reviewer` pass over all changed copy per slice (panel rule).
