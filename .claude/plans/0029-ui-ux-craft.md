## Problem

The harness now forces the craft *question* at the standard layer — the landed `product-ux.md` "Aesthetic & motion craft" dimension (v0.2.0, `product-ux.md:76-83`) with the honest `[D]`-floor / `[J]`-ceiling split. But the craft mission is only half-wired, and the harness's own copy still frames itself around *correct + complete + accessible* rather than *loved*:

1. **No craft forcing-function in the *plan* or the *product-designer* flow.** The `product-designer` Elevate delta-bar (`product-designer.md:64-72`) has a "tell-a-friend test" for *value* but nothing that forces the **look-and-feel / motion** question — which single surface a user would screenshot for how it *looks and moves*, and where the product's *feel* is differentiated. The `PLAN_TEMPLATE.md` architect-pass forces an *architecture* bar to exist but not a *felt/visual craft* bar, so a user-facing plan can pass Stage 3 with craft never named.
2. **The user's #1 stated worry — "don't make everything look the same" — has no home.** The craft dimension raises a *quality floor*; without a **per-project design-language record** that floor risks reading as a uniform template. There is nowhere a project pins its own brand lane / voice / anti-references so the baseline is a floor, never a sameness-enforcing mould.
3. **The craft dimension's `[D]` floor is thin and its guidance is generic.** It cites Disney/Material/Apple/Refactoring-UI at the dimension level but carries no concrete, attributed anti-slop detectors or motion micro-decisions — exactly the largely-`[D]`-checkable material (from `impeccable`, Emil Kowalski, easings.net, taste-skill) that would enrich the floor while leaving distinctiveness on the `[J]` ceiling.
4. **The felt-experience runtime observation is an open question** the user has explicitly scoped as *opt-in, not baked in* (context-cost + unproven capability). The ROADMAP's slice (b) as originally worded ("widen `runtime-qa` posture to *observe-and-report* felt experience") reads as default-on; the user's decision reverses that — it must be user-requested, never automatic.

Why it matters: the harness's whole differentiator is *disciplined, honest craft*. "Correct + accessible" is table-stakes; "addractive" (earned pull by merit/delight — the honest side of `product-ux.md` → Ethical engagement, never dark-pattern addiction) is the mission. The remaining slices close the seam between *forcing the craft question* (plan + designer), *answering the anti-sameness worry* (design-language seam), *enriching the honest floor* (grounded sources), and *keeping runtime felt-observation opt-in* — with honesty everywhere: force the question, check the floor, route the taste verdict to a human, **never certify beauty**.

## Approach

Prose/doc edits across the harness's managed surfaces (six slices — the mechanical close-out is split from the craft-copy edit per the Review), each landing vertically complete. **No engine code, no new module, no new agent** — the two release footguns are avoided by design (edits to *existing* module + *existing* agent), and the one genuinely-new file is a *doc section*, not a gated artifact.

The unifying design is the **architect-pass rail** already blessed in DECISIONS ("Craft is first-class") for first-classing any hard-to-gate concern: **template/standard forces the bar to EXIST (`[D]`-presence) · `synthesizer-gate` reviews it's genuinely reasoned (`[J]`) · `yagni-sentinel` guards over-build**. Every craft forcing-function this plan adds rides that rail rather than inventing a new mechanism (DRY).

**Design-language siting decision (KISS — resolved here, not left to build):** the per-project design-language record **extends `docs/claugentic-PRODUCT.md`** with a dedicated `## Per-project design language (the anti-sameness record)` block (disambiguated from the existing `## The design language (every surface inherits these)` at `PRODUCT.md:17` — see the heading-collision guard in Affected files), rather than a new top-level doc or a `product-ux.md` bloat. Rationale: `PRODUCT.md` is *already* the durable "who it's for + what 'good' feels like" home authored by `product-designer` at Discover (`PRODUCT.md:17-30` already carries a repo-wide "design language" list — the harness's own instance of exactly this per-project pattern), it is read-on-demand (not always-loaded context tax), and it is the natural sibling the ROADMAP names. A new always-loaded doc would tax every session for a per-project record most sessions don't touch — YAGNI. The block is **project-owned, model-upheld, never a gate**; its whole purpose is to make each project establish its OWN voice so the craft floor is a quality floor, never a uniform template. *(Alternatives rejected: (a) a new `docs/claugentic-DESIGN.md` — extra managed file, extra `init` surface, extra tree entry, for content that fits PRODUCT.md; (b) a `product-ux.md` section — wrong layer, the standard is universal-conformance, the design-language is per-project taste, and bloating the always-relevant module taxes every UI change.)*

**Sources are distilled, credited, never copied wholesale** (licensing + we keep our own honest standard). The enrichment extracts *principles* (ease-OUT for entrances; no bounce/elastic; the named anti-slop detector families; the tunable-dials + infer-from-brief idea) and **attributes** them in the dimension's Sources line — it does not reproduce `impeccable`'s 45 detectors verbatim or lift taste-skill's config schema.

**Runtime felt-observation stays a ROADMAP note (opt-in), not a built slice.** Per the user decision, 0029 does *not* touch `runtime-qa.md` / `engine/qa.js`. Slice 6 rewrites the existing ROADMAP craft-track sub-bullet (b) from "widen posture to observe felt experience" (reads default-on) to an explicit **user-requested, opt-in** framing, and records the reversal in DECISIONS — capturing the decision without building it (YAGNI until the user asks + the capability is proven).

## Architecture & holistic fit

- **Codebase fit.** This is entirely **managed-doc + agent-prompt** work in the harness's own repo — no runtime layer, no engine, no schema. It sits in the *standards/agent/template/README* layer that ships to adopters (managed docs are subtractive-strip-only, so edits ship verbatim — the cross-cutting constraint). Placement respects the harness's existing separation: the **universal-conformance standard** (`product-ux.md`) owns "is this a finished, humane, accessible, *and now crafted* surface" for ALL projects; the **per-project taste record** (`PRODUCT.md` design-language block) owns "what THIS project's voice is"; the **forcing functions** (`product-designer` Elevate, `PLAN_TEMPLATE` architect-pass) force the craft question to be *asked*; the **README** carries the mission copy. Each concern stays in its right home (SoC): standard = universal bar, PRODUCT.md = per-project truth, agent = the pass that runs it, template = the plan-time forcing function. No layer duplicates another (DRY) — the design-language block *points at* `product-ux.md` for conformance and only records the per-project *intent* the universal standard can't hold.
- **Product fit.** Directly serves the harness's stated user (a capable non-engineer driving an AI dev team — `PRODUCT.md:9-15`) and their **#1 worry** ("don't make everything look the same"): the design-language seam makes each project pin its OWN voice, so the craft floor lifts quality without homogenising. The signature-moment forcing-function serves the "loved, not just correct" mission the whole track exists for. All of it honours the "In control · Trustworthy · Never surprised" design language (`PRODUCT.md:167-179`) — it forces the question and routes the taste verdict to the *user*, never auto-deciding taste.
- **Quality dimensions to uphold** (the in-scope `docs/claugentic-standards/` modules that FRAME this plan — forward-pointer to each slice's Spec *In-scope dimensions*):
  - **`product-ux`** — the primary lens; this plan *edits* its craft dimension and adds forcing-functions that route to it. The bar: the enriched dimension keeps the honest `[D]`-floor / `[J]`-ceiling split intact, never letting an anti-slop detector read as a beauty certificate.
