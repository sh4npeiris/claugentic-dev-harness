This repo builds the **`claugentic-dev-harness`** Claude Code plugin. The only executable code is `scripts/check_architecture_tree.py`; everything else is harness docs, specialist roles, the plan template, and config.

## Root

- `README.md` — what `claugentic-dev-harness` is + the concrete value it delivers (the three commands: init · audit · build), how it installs, how it works (init → audit → build the reviewed pipeline), and an honest status section.
- `CLAUDE.md` — lean, generalized guidance for agents working in THIS repo: engineering principles, harness discipline, workflow pointer, and a one-line Definition-of-Done pointer to `docs/WORKFLOW.md` (the canonical gate list).
- `.gitignore` — ignores local junk + build artifacts; **shares** `.claude/agents/`, `.claude/plans/`, `.claude/settings.json` (ignores only `.claude/settings.local.json`).
- `.gitattributes` — normalizes line endings (`* text=auto eol=lf`; scripts forced LF) for a cross-platform plugin.
- `LICENSE` — Apache License 2.0 (the repo is public; © 2026 Shan Peiris).
- `pyproject.toml` — minimal pytest config (`testpaths=["tests"]` + the `integration` marker) so `python -m pytest` runs the gate's test suite.

## .github/ — CI

- `.github/workflows/ci.yml` — GitHub Actions CI: on push/PR to `main`, runs the test suite (`pytest`, ubuntu + windows, Python 3.12), the workflow-script helper tests (`node --test`, Node 22, ubuntu + windows), and the two deterministic gate scripts (the architecture-tree + version-sync checks) — the DoD's deterministic gates, now machine-run unconditionally.

## .claude/agents/ — specialist role library

- `.claude/agents/plan-reviewer.md` — adversarially critiques a draft plan (Stage 3): soundness, sizing/completeness, risk, YAGNI, harness impact; edits only the plan's Review section. A gate/refute judge — spawned with the `fable` model override (cross-model: a different model family than the builder, a shared-blind-spot-risk reduction; opens `RUNNING AS:`; same-model runs tagged); frontmatter stays `model: opus` (the honest fallback).
- `.claude/agents/implementer-architect.md` — implements one approved, spec'd slice to standard in an isolated worktree (Stage 6); lands code + tests + docs with no debt.
- `.claude/agents/architect-reviewer.md` — owns the Verify gate (Stage 7): audits the diff against in-scope `docs/standards/` modules in **solo** mode (small changes) or **synthesizes** lens-reviewer + yagni-sentinel findings in **fan-out** mode; read-only. A gate/refute judge — cross-model (a different model family than the builder, a shared-blind-spot-risk reduction; opens `RUNNING AS:`; same-model runs tagged); **script runs** pin the model explicitly via `workflows/verify.js`, **prose runs** use the orchestrator's override per WORKFLOW Principles; frontmatter stays `model: opus` (the honest fallback).
- `.claude/agents/product-designer.md` — product/UX discovery + design lens (Stage 1, user-facing work): user, job-to-be-done, flows, states, "what good feels like"; applies `product-ux`, persists to `docs/PRODUCT.md`.
- `.claude/agents/lens-reviewer.md` — audits a **diff (Verify) or an audit-scope (the `audit` skill)** against ONE named `docs/standards/` module; two modes (Verify-diff / Audit-scope), invoked per-lens in a fan-out; in Audit-scope reads at the orchestrator-passed **`depth`** — the 3-rung ladder `focused`/`deep`/`exhaustive` (the dial's only lever, never which lenses run); read-only, returns per-dimension findings for the synthesizer.
- `.claude/agents/yagni-sentinel.md` — the anti-over-engineering skeptic: argues a plan/diff is too much (speculative abstraction, premature infra, gold-plating); read-only, returns a cut-list. (Also the audit's `thorough`-only adversarial prune over consolidated findings.)
- `.claude/agents/finding-verifier.md` — the audit's adversarial-verify counterpart to `lens-reviewer`: given ONE surfaced audit finding (claim + `file:line`, never the finder's rationale), independently reads the cited code and tries to **refute** it → `Verified` / `Refuted` / `Unconfirmed`; invoked on **every** finding the audit is about to surface (all tiers, every dial level), after the prune; read-only. A gate/refute judge — spawned with the `fable` model override (cross-model: a different model family than the builder, a shared-blind-spot-risk reduction; opens `RUNNING AS:`; same-model runs tagged); frontmatter stays `model: opus` (the honest fallback). A false-confidence reduction, not a deterministic gate. (Structural/clean-context independence of the input contract is a separate, accurate claim.)
- `.claude/agents/blindspot-reviewer.md` — the audit's **cross-cutting / between-the-modules** sweep (the `thorough` dial's diverse blind-spot finder): its lens is the *whole scope*, red-teaming for the risk **no single module-lens owns** (emergent architectural smells, integration gaps at the seams, systemic cross-cutting issues); always `exhaustive` depth, read-only, opus. **FINDS only** (re-checked by `finding-verifier` like any finding) and returns the **same per-finding shape** as `lens-reviewer`, so the dedup → prune → verify path is unchanged.
- `.claude/agents/honesty-reviewer.md` — the harness's **claims / over-claim** lens: refutes **copy** (not code), flagging text that launders model-or-human-upheld judgment into apparent mechanical fact (the verb discipline · `[D]`/`[J]` label integrity · dimension-scoped success claims · `cross-model ≠ independent`); the bar is **embedded in the prompt** (no standards module — promote when a 2nd consumer appears). Part of the diverse panel at Plan + Verify on trust/honesty surfaces; read-only. A gate/refute judge — cross-model (a different model family than the builder, a shared-blind-spot-risk reduction; opens `RUNNING AS:`; same-model runs tagged); **script runs** pin the model explicitly via `workflows/verify.js`, **prose runs** use the orchestrator's override per WORKFLOW Principles; frontmatter stays `model: opus` (the honest fallback). A reduction of false confidence, not a deterministic gate (does **not** mechanically cross-check).

## skills/ — harness entry points (the `/claugentic-dev-harness:*` family)

- `skills/init/SKILL.md` — the 9-step scaffold, **version-aware**: upserts the managed set to the installed plugin version (four verdicts — create / refresh-on-drift-or-old-stamp-format / leave-current-untouched / skip-user-file via the genuine-managed predicate, which keys on the **stable** `claugentic-dev-harness@<semver> managed — do not edit` prefix + path-in-set, trailing clause version-variable; a REFRESH migrates the stamp; no RESTAMP), generate ARCHITECTURE_TREE via the gate's file-list, set `INCLUDE_GLOBS`, merge the tree-check hook, **refresh-inside-fence** the CLAUDE.md `harness:managed` block + Current-scope, git-init, seed ROADMAP/DECISIONS, detect+record tooling; every write detect→upsert-to-installed/refresh-in-fence→report, **never-clobber user content** (stop-if-ambiguous is the safety net; re-run converges to the installed version, true no-op only when already at it — model-upheld, dogfood-checked).
- `skills/audit/SKILL.md` — thin trigger: Understand (conversational) + invoke `workflows/audit.js` + render the backlog. Phase 1 = inline overview + audit-plan + dial selection (retained conversational); Phase 2 = **invoke the script** (`${CLAUDE_PLUGIN_ROOT}/workflows/audit.js`, repo-local `./workflows/audit.js` when dogfooding) with the audit-plan as args — `quick`/`standard` only; Phase 3 = render the structured return as the tiered/tagged `harness-audit:backlog` fence (status block + 2-line legend with the not-a-guarantee caveat + one verification tag per item + the "architecturally sound" terminal signal + the verbatim go-button). Carries the **prose-orchestrated fallback** (Workflow tool unavailable, OR `dial = thorough` until Slice 3b — the legacy 9-step pipeline, tagged "prose-orchestrated" in the run report; never claims script guarantees on a prose run).
- `skills/build/SKILL.md` — the backlog **go-button**: a thin orchestration layer that drives `harness-audit:backlog` items through the `docs/WORKFLOW.md` pipeline (plan → review → spec → **your approval** → implement → verify → land) in **checkpoint mode** (the only live mode), pausing per item at exactly three decisions (the spec before any code · before land · before any irreversible action). **Two paths:** a single named item = the fast path (no triage); **the full-backlog loop** = multi-item triage (pick items and/or tier shortcuts → confirm the ordered worklist → "start now?") then work it item-by-item, each through the per-item engine, with a **scoped re-audit over the touched `(module×dir)` cells** after each item (honest scope — cross-file fallout owned by the closing full audit, no "dependents" claim) that **pauses to re-triage on any new Tier-1/2** else auto-continues, ending in **one `standard` full audit** → the verbatim "sound on the audited dimensions" terminal signal (or the remainder surfaced for a final triage). **Batch spec-approval (on request):** if the user says *"spec everything first,"* prep every item (steps 2–4, no code), run **one roster-first approval sitting** (= Stage 5 satisfied per item up front — scannable roster, full triad beneath, approve/adjust/drop; approve flips the plan to `Status: Approved`), then run the loop with each item's spec pause pre-satisfied — a **file-level spec-currency check** before each item (overlap with files landed since the sitting → a currency pause; not semantic, no dependency graph) + the interruption-honesty copy at the ask and echoed at the sitting close (sunk-cost once at the ask); absent the ask, as-we-go behaves exactly as before (the passive tip line is the only addition). The **resume contract derives the worklist** from the backlog fence + plan files (a batch run can leave SEVERAL in-flight; a done item's plan is removed at Land — git history keeps it), plus the three batch states (`Spec'd`=awaiting sitting · `Approved`=build when reached · unchecked boxes=in-flight; **approval never inferred**) — no new state store; order re-confirmed. Spawns the existing pipeline subagents (`plan-reviewer` + the diverse panel, `implementer-architect`, `architect-reviewer` + lenses, the audit's `lens-reviewer`/`finding-verifier` for the re-audit); tag→discipline + the Verify dial + the DoD point at WORKFLOW (no restatement). `autopilot` is a named mode whose ONLY behavior is an honest decline naming what's missing (the deterministic trust-gates; the cross-model judge is wired) — no scaffolding. Guardrails: the irreversible hard-stop set (incl. push-to-`main`), no-invented-scope, the honesty register (completed-beat narration, never an ETA).

## workflows/ — executable choreography (Workflow-tool scripts)

- `workflows/verify.js` — the Stage-7 Verify panel as an executable Workflow script: validates args at the boundary, logs the derived roster, fans out one `lens-reviewer` per in-scope `docs/standards/` module + `yagni-sentinel` + (trust-surface) `honesty-reviewer`, dedups lens gaps in code, then an `architect-reviewer` synthesis — judges spawned with the `model: MODELS.judge` (`opus`) cross-model param (one no-override respawn on error, force-tagged same-model; second failure throws). The verdict is passed through from synthesis (never overridden); the cross-model claim/same-model tag is computed in code from the judges' self-reports. Pure decision logic lives in the marked `// --- helpers ---` block (unit-tested by `tests/workflows/verify.test.mjs`). Read-from-install-path (`${CLAUDE_PLUGIN_ROOT}/workflows/verify.js`), never copied to adopters; gate-enforced via the widened `INCLUDE_GLOBS`.
- `workflows/audit.js` — the audit pipeline (FIND → PRUNE → VERIFY) as an executable Workflow script (Slice 3a: `quick`/`standard`; `thorough` rejected at the boundary → the SKILL's prose path until Slice 3b). Validates the audit-plan args (fail loud), enumerates `(module×dir)` cells, applies the `maxCellsPerRun` cap (PARTIAL + exact done/pending cell lists for deterministic resume), fans out one `lens-reviewer` per module batch at `depthForDial(dial)`, dedups by normalized `issueClass` (weakest-confidence-wins), runs a synthesis self-review prune (the `missing-test-baseline` key **never** pruned — coded exception), then **exactly one `finding-verifier` per surviving finding** (judge-pinned `model: MODELS.judge`, clean-context `buildVerifierInput` — never the finder's rationale; one no-override respawn, then `deferred`). `applyVerdicts` maps Verified/Refuted/Unconfirmed → verified-tag/dropped/unconfirmed (no-verdict → deferred); the run claims cross-model only on all-confirming-different-family self-reports. Returns a structured object (items with verification tags, done/pending cells, verification summary, COMPLETE/PARTIAL — no timestamps; the orchestrator stamps the date and renders the fence). Pure logic in the marked `// --- helpers ---` block (unit-tested by `tests/workflows/audit.test.mjs`); the `MODELS`/`SAME_MODEL_TAG`/`sameModelTag`/`parseArgs` block is copied verbatim from `workflows/verify.js`. Read-from-install-path, never copied; gate-enforced via `INCLUDE_GLOBS`.

## scripts/ — tooling

- `scripts/check_architecture_tree.py` — deterministic (no-LLM) gate enforcing that this index lists every in-scope source file (presence), references no deleted file (staleness), and **detects glob drift** (flags — does not auto-fix — when `INCLUDE_GLOBS` watches no files while the repo contains non-harness-managed source, the zero-coverage rot); `--hook` / `--hook-write` modes wired in `.claude/settings.json`. `INCLUDE_GLOBS` is the only per-repo knob for presence/staleness (set by `init`); the valid-extension set `EXTS` is derived from it. Drift detection uses a separate, stable `SOURCE_EXTS` allow-list + the `claugentic-dev-harness@` managed-stamp exclusion (no per-repo knob).
- `scripts/check_versions_synced.py` — deterministic (no-LLM) version-sync gate: `.claude-plugin/plugin.json`'s `version` is the single source of truth; FAILS LOUD (exit 1, plain message) if `.claude-plugin/marketplace.json`'s plugin entry `version` disagrees, or on any broken input (missing file / garbled JSON / absent `version`). Scope = the two manifest versions only — no stamp scan. A DoD run-gate (like `pytest`), not hook-wired. The two files are parsed independently (one broken cannot mask the other).
