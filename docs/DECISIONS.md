## 2026-06-08 — Trust & correctness core (shareable v0.1.2)

- **The audit now independently verifies its high-stakes findings.** After the YAGNI prune, a new **`finding-verifier`** agent (opus, read-only) takes each Tier-1 (correctness/security/data-loss) and security finding and **tries to refute it against the code** — `Verified` (proof attached) / `Refuted` (dropped as a false positive, reported) / `Unconfirmed` (kept, flagged). One rule on every dial (Tier-1 + security); deeper per-dial scaling is deferred to ROADMAP. **It is a *reduction* of false confidence, NOT a deterministic trust-gate** — same model class, clean-context + adversarial; distinct from the deferred deterministic Trust track (see 2026-06-05 trust-first).
- **Independence is enforced structurally by the input contract:** the verifier receives only `{claim, file:line, source module, confidence, exclude-set}` + a refute-first posture — never the finder's rationale, and a lens never verifies its own finding. A clean-context subagent given only the claim+location ⇒ independence is structural, not promised.
- **`finding-verifier` is a separate agent, not a third `lens-reviewer` mode** — `lens-reviewer` *finds gaps through a lens*; the verifier *refutes one specific claim against code* (different responsibility, input shape, posture). Mirrors `yagni-sentinel` as a standalone counterweight.
- **Verdict surfacing = one status axis per item, plain-English, no badge/legend.** Confidence (`deterministic`/`judgment` = *could a gate prove this*) and verification (*was it checked + outcome*) are different axes; a verified-scope item shows its verification tag (which supersedes the confidence label), an out-of-scope item keeps its confidence label, no item shows both. Verdicts **persist in the backlog fence** and are **not re-verified on resume**; Refuted findings aren't persisted (regenerate-don't-accumulate), so a fresh re-run may legitimately re-refute.
- **`check_architecture_tree.py`: `STALE_PATTERN` eliminated → `EXTS` derived from `INCLUDE_GLOBS`.** Staleness now compares a tree-referenced path's **whole last-dot extension** against the extension set derived from the single `INCLUDE_GLOBS` knob — structurally killing the `ts`-before-`tsx` truncation bug class (the 98 false positives in the an adopter dogfood) **and** the `INCLUDE_GLOBS`↔`STALE_PATTERN` sync-footgun. One per-repo knob; `init` now emits extension globs only. *(Supersedes the STALE_PATTERN guidance in 2026-06-05 "Tree-check is language-incidental".)*
- **The gate now has a test baseline** — 28 hermetic characterization tests (mode dispatch + exit codes, presence, staleness incl. the `.ts/.tsx` regression, `--hook-write` stdin); `python -m pytest` is now a Definition-of-Done gate. Closes the harness's own Tier-1 audit item.
- **Real-app dogfood: done.** `/claugentic-dev-harness:audit` produced a sharp, accurately-cited backlog on an adopter (892-file multi-tenant app) — which surfaced both the `STALE_PATTERN` bug and the gap that the audit asserted-but-didn't-prove its findings; this trust-core is the response.

## 2026-06-05 — Audit right-sizing (v0.1.1)

- **The `/claugentic-dev-harness:audit` dial auto-sizes, but a named level always wins.** A named level (`quick` / `standard` / `thorough`) takes precedence; otherwise the dial **auto-picks from the Understand phase's repo sizing** — small/simple → `quick`, larger / many candidate modules / monorepo → `standard` — and **reports the chosen level up front** so the user can override. It's a rough size judgment, not a scoring formula (KISS). `thorough` is a deferred forward-pointer (behavior not invented; running it falls back to `standard` and says so).
- **A post-dry YAGNI prune is a synthesis discipline, not a fan-out.** After the audit loop goes dry, one right-sizing pass over the consolidated findings keeps real-impact items and cuts marginal nice-to-haves — **never manufacturing a finding to fill a tier** (a sound codebase legitimately yields few or none). It runs *after* dry-detection so it can't affect loop termination (termination is guaranteed by the finite cell set + max-rounds + max-cells-per-run caps). The full adversarial `yagni-sentinel` sweep over findings is deferred to `thorough`.
- **"Architecturally sound" is an explicit terminal signal.** When Tier 1 + Tier 2 both come back empty, the backlog says so plainly — *"Sound on the audited dimensions — what remains is optional polish; you don't need to keep re-auditing"* — giving the user a stop signal instead of leaving them to infer one (scoped to covered cells on a `PARTIAL` run). The audit is a periodic snapshot, not a treadmill: the backlog regenerates rather than accumulating.

## 2026-06-05 — Managed-stamp + fence conventions (the `/update` input contract)

- **Every copied file carries a managed-stamp on its first line:** markdown `<!-- claugentic-dev-harness@<semver> managed — do not edit; run /claugentic-dev-harness:update to refresh -->`, Python `# claugentic-dev-harness@<semver> managed — …`; `<semver>` = `plugin.json.version`. The greppable token **`claugentic-dev-harness@<semver>`** is the contract: `init`'s copy-if-absent detects an already-managed copy by `claugentic-dev-harness@`; `/claugentic-dev-harness:update` regexes the semver to compare versions. Source modules stay pristine (unstamped, editable upstream); the stamp is added **on copy**.
- **Stable fences mark replace-only-inside regions, human-owned outside.** The adopter's `CLAUDE.md` carries a `<!-- harness:managed:start -->…:end -->` fence (the managed pointer block, refreshed by `/update`); `/claugentic-dev-harness:audit` writes a `harness-audit:overview` and a `harness-audit:backlog` fence into the adopter's `docs/ROADMAP.md`. **No volatile content (timestamps, counters) goes inside a managed fence** → a re-run with identical inputs is byte-identical, so the "zero diffs on the 2nd run" idempotency guarantee holds. Per-repo, editable, never-overwritten content (Current scope, detected tooling) lives **outside** the fences.

## 2026-06-05 — Copy standards on init

- **The standards catalog is COPIED into each adopter repo on init; re-synced via `/claugentic-dev-harness:update`** — *not* read from the plugin at runtime. Verified against official Claude Code docs: a plugin's **subagents cannot read bundled files via bare relative paths** in an adopter repo (they resolve to the adopter's project root), and `${CLAUDE_PLUGIN_ROOT}` — though it expands in agent prompt bodies — doesn't cover the **parameterized `lens-reviewer`** (module chosen at runtime). Copy-on-init is reliable, needs **no agent changes** (agents keep reading the local `docs/standards/`), and matches the proven Agent-OS pattern.
- **Two-tier model:** global = copied + version-stamped + headed "managed — do not edit" (hand-edits are lost on the next `/update`); local = the per-repo Current scope + `CANDIDATES.md` + lessons in `CLAUDE.md` / `DECISIONS.md`, which never propagate. Drift is handled by the version stamp + `/update` overwrite.
- **Characterization-first is a hard precondition.** A `refactor` item on untested behavior-bearing code can't start until its Tier-1 "establish a test baseline" item is done; until the durable `PreToolUse` characterization hook lands (first trust-gate item), this is upheld by the implementer stopping-and-asking + the Verify gate, not yet automatically.

## 2026-06-05 — Tree-check is language-incidental

- **The architecture-tree check needn't match the project's tech.** It's harness tooling the agent runs to get a file list (it never parses project source), so its language is incidental — **`check_architecture_tree.py` stays Python; no per-language port.** The only project-specific parts are **`INCLUDE_GLOBS` + `STALE_PATTERN`** (set in pairs by the `init` skill to the adopter's source layout — the staleness check is dead if they drift apart). Runtime availability is the only real constraint (Python is broadly present; `init` verifies it and the agent can fall back to `Glob`).
- **Code-analyzing gates compose, not reimplement.** Gates that inspect project source (complexity, dead-code, secrets, layering) lean on the project's *own* linters/analyzers (ESLint, tsc, …) rather than being rebuilt per language.

## 2026-06-05 — Trust-first: deterministic gates are deferred, and that's the #1 known gap

- **The harness's #1 risk is *false confidence*** — the same model class grading its own work. The honest mitigation is an **independent, deterministic Trust & Verification track** (a `PreToolUse` characterization-tests-first hook, a secret-scan gate, a behavioral-baseline equivalence oracle), built on signals that don't depend on the grading model.
- **Today these gates are model-upheld, not yet deterministic** — the workflow + agent review + the audit's honest confidence labels are the current bar, and a `[D]` check only truly proves something when the adopter has the relevant tool wired. The deterministic gates are the next major phase (see `docs/ROADMAP.md`), and the harness states this gap honestly rather than overclaiming verification it doesn't yet have.
