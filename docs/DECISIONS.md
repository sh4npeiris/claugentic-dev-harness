## Streamlined audit dial — FIND→PRUNE→VERIFY, depth-per-lens, universal re-check (plan 0004, Slice 1 · 2026-06-09)

- **The audit collapses to ONE uniform pipeline at every level: FIND → PRUNE → VERIFY → surface.** The dial scales on a single axis — **depth-per-lens**: all relevant lenses run at *every* level (a lens is **never** dropped to make a level cheaper); the level sets a **`depth`** the orchestrator passes each `lens-reviewer` — `quick` = `focused` (clear gaps from a direct read), `standard` = `deep` (call-chains, edge cases, subtle issues). `quick` shows the clear issues fast, `standard` digs for the subtle ones. *(Rejected forks: scale lenses-by-relevance — knowingly skipping a relevant lens undermines trust; scale dirs — arbitrary/budget-driven, the tree already maps everything.)*
- **VERIFY is now universal — and this SUPERSEDES the prior Tier-1+security scoping.** After the prune, the audit **attempts to refute every surfaced finding, all tiers, on every dial level** (one `finding-verifier` per finding, clean-context, refute-first). This **supersedes** the *Trust & correctness core* decision's "Tier-1 + security only, no per-dial scaling" rule **and** subsumes ROADMAP #2's (and *Audit right-sizing*'s) deferred verification sub-items ("standard additionally verifies `deterministic`-labeled" / "thorough verifies all") — universal re-check is the simplest, most honest rule, and the set is small because PRUNE runs first. The `finding-verifier` is unchanged (same model class, same input contract); only *which findings it sees* widened. A ROADMAP tuning-lever is logged if cost ever bites (narrow Tier-3).
- **Loop-until-dry is RETIRED — with the honest recall caveat on the record.** Each `(module × dir)` cell is audited **exactly once**; no re-sweep, no `max-rounds` cap, no cross-round seen-set (single-pass dedup + the citation-guard + the cell model + status block + `PARTIAL`/resume all stay). **Honest trade-off:** same-lens re-runs mostly reproduce themselves, but a *fresh round-2 lens can* surface what round-1 missed — so `standard` is now a **single deep pass**, and the high-value *second-angle* look (a diverse blind-spot sweep) is reserved for `thorough` (Slice 2). The skill states this plainly rather than papering over it.
- **Verb discipline (honesty, non-negotiable):** the audit **"attempts to / tries to re-check"** every finding and **"tags the outcome"** — never "verifies / arrives with proof / carries proof." The collapsed Phase-3 legend (now the most-read trust line) carries the **not-a-mechanical-guarantee caveat**; README lines 8/19 carry the verbatim re-check copy (no "arrive/carry proof"). It is a reduction of false confidence by the same kind of model, not a deterministic gate.

It bounds the run's cost/time, keeps the **orchestrator's synthesis** within its own context, and enables `PARTIAL`/resume — **not** to bound any single subagent's context (each has its own 1M).
- **`thorough` stays HONESTLY DEFERRED this slice** — naming it runs a `standard`-depth pass and says the deeper `thorough` pass (a diverse blind-spot sweep + an adversarial `yagni-sentinel` prune) lands next release. Status block stays `level: quick|standard`; auto-dial still picks `quick`(small)/`standard`(larger); `thorough` named-only. It flips live in Slice 2.

### Slice-2 addendum — `thorough` LIVE, the `blindspot-reviewer`, the 3-rung depth ladder, two dials stay two (plan 0004, Slice 2 · 2026-06-09)

- **`thorough` is now LIVE** (no more "deferred"): naming it runs **`exhaustive`** depth + the **blind-spot sweep** + the **adversarial `yagni-sentinel` prune**. The dial is reframed as **ONE thoroughness slider, three stage-responses** (not three pipelines): **FIND** responds by depth (`focused`→`deep`→`exhaustive`) and at the top *also* steps back for the cross-cutting sweep; **PRUNE** responds by *who* cuts (synthesis self-review → an independent skeptic at the top); **VERIFY is flat at every notch** (the honesty floor — every surfaced finding re-checked, even on `quick`). - **New agent `blindspot-reviewer`** — a read-only adversarial **cross-cutting / between-the-modules** finder: its lens is the *whole audited scope*, red-teaming for the risk **no single module-lens owns** (emergent architectural smells, integration gaps at the seams, inconsistently-applied cross-cutting concerns, systemic issues). - **Designed REUSABLE.** The Audit-scope posture is built now (always `exhaustive`), but the agent is written to **generalize to a Verify-diff mode later** (mirroring `lens-reviewer`'s two-mode "infer from input" shape — "what does the per-lens view miss?" is just as valid on a slice's diff). The diff mode is **not** built (YAGNI); wiring it into the dev-workflow Stage-7 Verify is ROADMAPed.
- **The depth ladder is 3 rungs** (`lens-reviewer` `depth` contract): **`focused`** (clear gaps from a direct read) → **`deep`** (call-chains, edge cases, subtle issues) → **`exhaustive`** (`deep` + self-skeptical: questions its own conclusions, chases every ambiguous lead, adversarial per-dimension). `thorough`'s FIND runs `exhaustive`. *(Supersedes the Slice-1 `focused`/`deep` binary.)*
- **Where depth saves — honest scope.** Each lens already targets its reads via `ARCHITECTURE_TREE.md`, so depth trims the *variable* cost (call-chain chasing + reasoning), not the base read. `quick`'s biggest wins are on **small repos** (auto-picked there) + **triage noise** (fewer, clearer findings) — **not** a dramatic big-repo token cut; the copy must not over-claim `quick` as "much cheaper everywhere."
- **Two dials stay two (decision, not an oversight).** The **audit dial** (`/claugentic-dev-harness:audit` — `quick`/`standard`/`thorough`) targets *existing code* and outputs a *backlog*; the **dev-workflow Stage-7 Verify dial** (`architect-reviewer` solo vs fan-out) targets a *slice's diff* and outputs a *pass/fail gate*. They **share the same agent library** (`lens-reviewer`, `yagni-sentinel`, and — once it gets a Verify-diff mode — `blindspot-reviewer`) but have **different targets and outputs**, so they are **kept separate, not merged.**
- **Version bumps sync `marketplace.json` with `plugin.json`.** Both `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` carry the plugin version; the marketplace catalog is install-facing, so a bump must update **both** (Slice-2 Verify caught a `0.1.3`→`0.1.5` drift after only `plugin.json` was bumped). Treat the two version stamps as one source of truth on every release.

## Trust & correctness core

- **The audit independently verifies its high-stakes findings.** After the YAGNI prune, a **`finding-verifier`** agent (opus, read-only) takes each Tier-1 (correctness/security/data-loss) and security finding and **tries to refute it against the code** — `Verified` (proof attached) / `Refuted` (dropped as a false positive, reported) / `Unconfirmed` (kept, flagged). One rule on every dial (Tier-1 + security); deeper per-dial scaling is deferred to ROADMAP. **It is a *reduction* of false confidence, NOT a deterministic trust-gate** — same model class, clean-context + adversarial; distinct from the deferred deterministic Trust track (see *Trust-first: deterministic gates are deferred, and that's the #1 known gap*). *(**Superseded** by *Streamlined audit dial* (plan 0004, Slice 1) — VERIFY is now universal: every surfaced finding, all tiers, every level. The Tier-1+security scoping no longer applies; see the top entry.)*
- **Independence is enforced structurally by the input contract:** the verifier receives only `{claim, file:line, source module, confidence, exclude-set}` + a refute-first posture — never the finder's rationale, and a lens never verifies its own finding. A clean-context subagent given only the claim+location ⇒ independence is structural, not promised.
- **`finding-verifier` is a separate agent, not a third `lens-reviewer` mode** — `lens-reviewer` *finds gaps through a lens*; the verifier *refutes one specific claim against code* (different responsibility, input shape, posture). Mirrors `yagni-sentinel` as a standalone counterweight.
- **Verdict surfacing = one status axis per item, plain-English, no badge/legend.** Confidence (`deterministic`/`judgment` = *could a gate prove this*) and verification (*was it checked + outcome*) are different axes; a verified-scope item shows its verification tag (which supersedes the confidence label), an out-of-scope item keeps its confidence label, no item shows both. Verdicts **persist in the backlog fence** and are **not re-verified on resume**; Refuted findings aren't persisted (regenerate-don't-accumulate), so a fresh re-run may legitimately re-refute. *(The verified-scope/out-of-scope **split is superseded** by *Streamlined audit dial* (plan 0004, Slice 1) — every item now shows one verification tag; the per-item `deterministic`/`judgment` label is no longer displayed.)*
- **`check_architecture_tree.py`: `STALE_PATTERN` eliminated → `EXTS` derived from `INCLUDE_GLOBS`.** Staleness compares a tree-referenced path's **whole last-dot extension** against the extension set derived from the single `INCLUDE_GLOBS` knob — structurally killing the `ts`-before-`tsx` truncation bug class **and** the `INCLUDE_GLOBS`↔`STALE_PATTERN` sync-footgun. One per-repo knob; `init` emits extension globs only. *(Supersedes the STALE_PATTERN guidance in *Tree-check is language-incidental*.)*
- **The gate has a test baseline** — hermetic characterization tests (mode dispatch + exit codes, presence, staleness incl. the `.ts/.tsx` regression, `--hook-write` stdin); `python -m pytest` is a Definition-of-Done gate.

## Audit right-sizing

- **The `/claugentic-dev-harness:audit` dial auto-sizes, but a named level always wins.** A named level (`quick` / `standard` / `thorough`) takes precedence; otherwise the dial **auto-picks from the Understand phase's repo sizing** — small/simple → `quick`, larger / many candidate modules / monorepo → `standard` — and **reports the chosen level up front** so the user can override. It's a rough size judgment, not a scoring formula (KISS). `thorough` is a deferred forward-pointer (behavior not invented; running it falls back to `standard` and says so). *(**Superseded** by plan 0004: `thorough` no longer "falls back" — `quick`/`standard`/`thorough` are **depth presets of one pipeline** (focused/deep/exhaustive); `thorough` goes live in Slice 2. The named level still always wins; auto-dial still picks `quick`/`standard`.)*
- **A post-dry YAGNI prune is a synthesis discipline, not a fan-out.** After the audit loop goes dry, one right-sizing pass over the consolidated findings keeps real-impact items and cuts marginal nice-to-haves — **never manufacturing a finding to fill a tier** (a sound codebase legitimately yields few or none). It runs *after* dry-detection so it can't affect loop termination (termination is guaranteed by the finite cell set + max-rounds + max-cells-per-run caps). The full adversarial `yagni-sentinel` sweep over findings is deferred to `thorough`. *(**Superseded** by plan 0004: loop-until-dry + max-rounds are **retired** — single look per cell; termination is now the finite cell set + one diverse-sweep batch + the shared cap. The adversarial `yagni-sentinel` prune is a `thorough`-only stage, built in Slice 2.)*
- **"Architecturally sound" is an explicit terminal signal.** When Tier 1 + Tier 2 both come back empty, the backlog says so plainly — *"Sound on the audited dimensions — what remains is optional polish; you don't need to keep re-auditing"* — giving the user a stop signal instead of leaving them to infer one (scoped to covered cells on a `PARTIAL` run). The audit is a periodic snapshot, not a treadmill: the backlog regenerates rather than accumulating.

## Managed-stamp + fence conventions (the `/update` input contract)

- **Every copied file carries a managed-stamp on its first line:** markdown `<!-- claugentic-dev-harness@<semver> managed — do not edit; run /claugentic-dev-harness:update to refresh -->`, Python `# claugentic-dev-harness@<semver> managed — …`; `<semver>` = `plugin.json.version`. The greppable token **`claugentic-dev-harness@<semver>`** is the contract: `init`'s copy-if-absent detects an already-managed copy by `claugentic-dev-harness@`; `/claugentic-dev-harness:update` regexes the semver to compare versions. Source modules stay pristine (unstamped, editable upstream); the stamp is added **on copy**.
- **Stable fences mark replace-only-inside regions, human-owned outside.** The adopter's `CLAUDE.md` carries a `<!-- harness:managed:start -->…:end -->` fence (the managed pointer block, refreshed by `/update`); `/claugentic-dev-harness:audit` writes a `harness-audit:overview` and a `harness-audit:backlog` fence into the adopter's `docs/ROADMAP.md`. **No volatile content (timestamps, counters) goes inside a managed fence** → a re-run with identical inputs is byte-identical, so the "zero diffs on the 2nd run" idempotency guarantee holds. Per-repo, editable, never-overwritten content (Current scope, detected tooling) lives **outside** the fences.

## Copy standards on init

- **The standards catalog is COPIED into each adopter repo on init; re-synced via `/claugentic-dev-harness:update`** — *not* read from the plugin at runtime. Verified against official Claude Code docs: a plugin's **subagents cannot read bundled files via bare relative paths** in an adopter repo (they resolve to the adopter's project root), and `${CLAUDE_PLUGIN_ROOT}` — though it expands in agent prompt bodies — doesn't cover the **parameterized `lens-reviewer`** (module chosen at runtime). Copy-on-init is reliable, needs **no agent changes** (agents keep reading the local `docs/standards/`), and matches the proven Agent-OS pattern.
- **Two-tier model:** global = copied + version-stamped + headed "managed — do not edit" (hand-edits are lost on the next `/update`); local = the per-repo Current scope + `CANDIDATES.md` + lessons in `CLAUDE.md` / `DECISIONS.md`, which never propagate. Drift is handled by the version stamp + `/update` overwrite.
- **Characterization-first is a hard precondition.** A `refactor` item on untested behavior-bearing code can't start until its Tier-1 "establish a test baseline" item is done; until the durable `PreToolUse` characterization hook lands (first trust-gate item), this is upheld by the implementer stopping-and-asking + the Verify gate, not yet automatically.

## Tree-check is language-incidental

- **The architecture-tree check needn't match the project's tech.** It's harness tooling the agent runs to get a file list (it never parses project source), so its language is incidental — **`check_architecture_tree.py` stays Python; no per-language port.** The only project-specific parts are **`INCLUDE_GLOBS` + `STALE_PATTERN`** (set in pairs by the `init` skill to the adopter's source layout — the staleness check is dead if they drift apart). Runtime availability is the only real constraint (Python is broadly present; `init` verifies it and the agent can fall back to `Glob`).
- **Code-analyzing gates compose, not reimplement.** Gates that inspect project source (complexity, dead-code, secrets, layering) lean on the project's *own* linters/analyzers (ESLint, tsc, …) rather than being rebuilt per language.

## Trust-first: deterministic gates are deferred, and that's the #1 known gap

- **The harness's #1 risk is *false confidence*** — the same model class grading its own work. The honest mitigation is an **independent, deterministic Trust & Verification track** (a `PreToolUse` characterization-tests-first hook, a secret-scan gate, a behavioral-baseline equivalence oracle), built on signals that don't depend on the grading model.
- **Today these gates are model-upheld, not yet deterministic** — the workflow + agent review + the audit's honest confidence labels are the current bar, and a `[D]` check only truly proves something when the adopter has the relevant tool wired. The deterministic gates are the next major phase (see `docs/ROADMAP.md`), and the harness states this gap honestly rather than overclaiming verification it doesn't yet have.
