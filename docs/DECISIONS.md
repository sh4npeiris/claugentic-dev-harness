# Decisions

The durable architectural record — the standing decisions behind the harness, kept so they aren't re-litigated. **Consult before revisiting a past choice** (see CLAUDE.md → Harness Discipline). For new decisions, **append a dated one-liner at the top of the relevant section** (or a new section); the full build history lives in git.

## Honesty positioning (the #1 rule)

- **Never let copy launder model judgment into apparent mechanical fact.** The current honest split: the **architecture-tree check is the only hook-enforced gate**; `check_versions_synced.py` + the test suite are **deterministic run-gates** (mechanical when run; running them is discipline); everything else — reviewer sign-offs, the diverse panel, the audit's finding re-checks, build mode's pauses — is **model-upheld** and said so.
- **Verb discipline:** the harness *"attempts to / tries to re-check"* and *"tags the outcome"* — never *"verifies / proven / arrives with proof / guaranteed."* Success claims are **dimension-scoped** (*"sound on the audited dimensions"*), never "bug-free/perfect."
- **The two senses of "independent":** claims of model-family independence about the judges are **forbidden** (same vendor → errors stay correlated; the honest claim is *"a different model family — a reduction of shared-blind-spot risk"*). The **structural** sense — clean-context input-contract isolation ("independently re-checks") — is accurate and **preserved**.
- **`[D]` vs `[J]`:** a deterministic-labeled check is only *proven* where the adopter has the relevant tool wired; otherwise it is reported as the model's judgment.

## The deterministic gates

- **2026-06-12 — per-stage duration bound for build-to-green (`caps.stageTimeouts`; plan 0013, v0.1.28).** The sandbox has no wall-clock, so the script can't time a stage; the only lever is the **Bash tool's `timeout` parameter** per command (a PER-COMMAND bound, never a stage total) — a shell `timeout` was ruled out as the mechanism (the prompts mandate the Bash-tool `timeout` parameter; Windows `timeout.exe` is a no-op delay, and CI runs Windows). Per-stage **distinct** defaults (`implement`/`gates` ⇒ 600s = the Bash-tool hard max `MAX_STAGE_TIMEOUT_SEC`; **`qaBoot` ⇒ `null` = unset**, so qa.js stays the sole 60s-default/300s-clamp owner — no literal duplicated, threaded pass-through-when-set). `validateArgs` rejects fail-loud (non-object, unknown key, non-integer/≤0, or > 600 — never silently clamped). **Three-way enforcement register** (the honesty line): **gates** = agent-applied timeout + a **mechanical red on the reported code** (a timed-out command → exitCode 124 → `gatesGreen` reads it red); **qaBoot** = a **mechanical clamp** in qa.js + agent-executed bounded probe; **implement/fix** = **instruction-only** (IMPLEMENT_SCHEMA has no exit-code channel — model-upheld, NOT fail-closed; a runaway is left to surface downstream — gates + the iteration cap — WHEN it manifests there, nothing in this stage bounds it). Residual: a single command > 600s can't be bounded-and-completed in one foreground call.
- **2026-06-12 — the tree-gate backtick tokenizer strips ```-fenced blocks first (v0.1.27; the first real-adopter regression).** The Slice-1 switch from substring to backtick-token matching used a sequential non-overlapping pair tokenizer (`BACKTICK_TOKEN_PATTERN.findall`). On the FIRST real adopter run (an adopter, whose `ARCHITECTURE_TREE.md` carries ~893 lines of ```-fenced ASCII directory diagrams), a fence's stray backticks flipped pairing parity for everything after it — ~456 correctly-formatted entries read as MISSING and diagram content read as live references. Fix: `_strip_fenced_blocks` removes fenced regions before BOTH the presence and staleness tokenizers (an index entry never lives inside a fence). **Lesson recorded: the gate's test corpus was unrealistically simple — no fixture carried a fenced block, so 98 green tests + a 10/10 eval missed a keystone-gate regression that broke on first contact with a real tree. Characterization fixtures must mirror real adopter docs, not minimal ones.** Surfaced by the user's own fresh-install end-to-end test of the harness — the decisive adopter-path exercise the v2 close-out flagged as unproven.
- **2026-06-11 — the workflow-helper test job invokes `node --test tests/workflows/*.test.mjs` (explicit glob), NOT the bare directory `tests/workflows/` (plan 0012, Slice 2).** The bare-directory test-discovery form is broken on Windows Node 22.20 (it tries to `require` the dir as a module → `MODULE_NOT_FOUND`, confirmed via shell-free `spawnSync`); the explicit file-glob is Node-globbed internally (cross-platform, no shell expansion) and discovers the same files. Following the plan's literal `tests/workflows/` would have red-ed the Windows half of the matrix the same slice mandates — the glob form achieves the spec's intent (all `tests/workflows/` helper tests run, both OSes) honestly.
- **2026-06-11 — CI runs the deterministic gates unconditionally (plan 0012, Slice 1).** `.github/workflows/ci.yml` runs pytest (ubuntu + windows, Python 3.12) + both gate scripts on every push/PR to `main` — the DoD's "deterministic" gates are now machine-run, not remembered. Four tree-gate fixes landed with it: presence/hook-write matching requires an exact backtick-delimited token (substring containment retired); `_git` runs `-c core.quotepath=false` with explicit UTF-8 decoding, and an undecodable filename re-raises on the same loud `RuntimeError` boundary as every git failure (the `--hook-write` never-block-a-write contract holds); `--hook` honours `stop_hook_active` as a loop-breaker; the real-git integration test is config-isolated (GIT_CONFIG_GLOBAL/SYSTEM + gpgsign/hooksPath/precomposeunicode pins) and NFC-normalized.
- **One gate, one invariant (SRP siblings):** the tree-check owns the file index (presence · staleness · zero-coverage glob-drift); `check_versions_synced.py` owns the `plugin.json` ↔ `marketplace.json` version pair (the two stamps are one source of truth — every bump moves both). New mechanically-checkable invariants get a sibling script, not an extension.
- **Fail loud, never fail-open:** every gate errors plainly on broken input (missing/garbled files, empty globs) — a gate that silently passes on its own breakage is the forbidden failure class. All gates carry hermetic characterization tests; `python -m pytest` is a Definition-of-Done gate.
- **The tree-check is language-incidental** — harness tooling that never parses project source; it stays Python with `INCLUDE_GLOBS` as the **single per-repo knob** (the valid-extension set is derived from it). Glob-drift detection uses a stable `SOURCE_EXTS` allow-list + the managed-stamp exclusion — **no per-stack registry** (an always-incomplete list re-introduces the rot it claims to kill). Detection is mechanical; the glob *reset* is model-upheld (init's terminating self-correction).
- **The deterministic trust-gates for unwatched runs** (a land-gate hook · a secret-scan · a characterization-tests-first hook) are **not built** — and the harness says so rather than claiming them (asserting "cannot land red" before such hooks exist would be the over-claim the harness forbids); build-to-green is **a reduction of unwatched-run risk, never a substitute** for these unbuilt gates, and its decline names exactly which unlock conditions are unmet (see Build mode → the 2026-06-12 ladder entry).

## Cross-model judges (the verify gates)

- **2026-06-12 — an unresolved judge family is reported AS unresolved, never asserted same-model fact (plan 0013; a THIRD disclosure state).** Previously, when a judge's self-reported family could not be recognized, the run was *labeled* same-model — asserting "the judge and the builder are the same model family here" when the truth was merely "could not resolve." The conservative trust floor (no cross-model claim) was right; the wording was an over-claim. Now `sameModelTag` returns three states: a **missing** self-report (null/empty — the deliberate forced-respawn / no-report floor) → `SAME_MODEL_TAG`; a **present-but-unrecognized** family (either side) → the new verbatim `UNRESOLVED_FAMILY_TAG` ("could not resolve the judge's model family on this run — no cross-model claim is made (treated as the same-model trust floor, not asserted as fact)."); a resolved-same match → `SAME_MODEL_TAG`; a confirmed different family → `null` (the sole cross-model case — **no behavior change to when cross-model is claimed**). `modelFamily`'s regex now derives from the one named `KNOWN_FAMILIES = ["fable","opus","sonnet","haiku"]` source (single source of truth — a new family is added there, not in a hand-built regex). The fold helpers thread the WHY: verify.js's `crossModelOutcome` returns the first non-confirming judge's own tag; audit.js's `verificationSummary` taints the run's disclosure to `UNRESOLVED_FAMILY_TAG` on any present-but-unresolved verifier (and `renderRunReport` substitutes the summary's computed tag — so an unresolved run never reads as same-model fact in the run report either); qa.js's fold does the same. Each control flow `log()`s a present-but-unrecognized self-report (observability — never silently degraded). Both new constants are copied byte-identical across verify/audit/qa **and** build-item (build-item carries them for `sameModelTag`/`modelFamily` byte-identity though it folds only confirm/not-confirm child signals); the cross-script drift pin (`tests/workflows/cross-script.test.mjs`) now covers `UNRESOLVED_FAMILY_TAG` + `KNOWN_FAMILIES`. Wording-and-observability-only trust improvement; out of scope: any change to the cross-model claim trigger; renderer wording beyond substituting the correct tag.
- **2026-06-11 — workflow scripts parse `args` at the boundary (`parseArgs`, plan 0012 Slice 2).** Observed runtime behavior: a `scriptPath` invocation delivers the `args` global as a JSON **string** (an inline `script` may receive the object). Every workflow script therefore normalizes through the pure `parseArgs` helper — string → `JSON.parse` failing loud, object → passthrough — before `validateArgs`. Later scripts (audit/qa/build-item) copy this convention with the `MODELS`/`sameModelTag` block.
- **2026-06-11 — an unrun lens is never read as clean (`coverageGaps` + `panelDegraded`, plan 0012 Slice 2).** A panel lens that returns null (skipped/errored) becomes an explicit deterministic could-not-run GAP fed to synthesis, and the result carries `panelDegraded` — a deliberate addition to the spec'd result shape (recorded here per the Verify pass-2 ruling). The same fail-loud-on-unrun-lens pattern is to be adopted by `audit.js` (Slice 3a), not left verify-only.
- **2026-06-11 — the audit choreography is now a script; `thorough` stays on the prose path; the never-prune-the-test-baseline exception is now CODED (plan 0012, Slice 3a).** `workflows/audit.js` runs FIND→PRUNE→VERIFY for `quick`/`standard` mechanically: lens fan-out per `(module×dir)` cell at `depthForDial(dial)`, coded dedup by normalized `issueClass` (weakest-confidence-wins), a synthesis self-review prune, and **exactly one `finding-verifier` per surviving finding** (the prose's "re-check every finding" claim, now enforced by the script — cross-model judge pinned via `model: MODELS.judge`). `thorough` is rejected at the boundary with a message naming Slice 3b and routes to the SKILL's prose-orchestrated fallback (also used whenever the Workflow tool is unavailable; both tagged "prose-orchestrated" — never claiming script guarantees on a prose run). The `applyPrune` helper **cannot drop a finding whose `findingKey === 'missing-test-baseline'`** — the prose's "never prune the test-baseline item" exception is now code, not memory. `deferredFindings` from a prior PARTIAL run are fed straight to VERIFY for a fresh re-check (their prior `deferred`/`⚠ not yet verified` tag does not exempt them); findings carrying a *resolved* verdict tag persist in the fence and are not re-passed. The script returns a structured object (no timestamps — the orchestrator stamps the date and renders the fence; the renderer-in-script arrives in Slice 3b). The `MODELS`/`SAME_MODEL_TAG`/`sameModelTag`/`parseArgs` block is copied verbatim from `verify.js` (single shared convention).
- **2026-06-11 — a per-call `model:` parameter resolves cross-family inside a Workflow run (plan 0012, Slice 2; n=1 self-report evidence).** A pre-slice spike from a Fable-5 session observed `agent(…, {model: 'opus'})` self-report **Opus 4.8**, the default call inherit Fable 5, and an `agentType` whose frontmatter reads `model: opus` resolve to Opus — evidence is the harness-injected model id each agent self-reported (n=1, claimed as exactly that, never laundered into "mechanical/proven"). So `workflows/verify.js` spawns its judges (`honesty-reviewer`, `architect-reviewer` synthesis) with the explicit `model: MODELS.judge` (`opus`) param — the cross-model spawn the prose used to uphold is now wired in code. **The coded same-model tag stays the per-run guard:** a run claims "cross-model" only when *every* judge returns a confirming different-family self-report (`crossModelOutcome`); on a forced no-override respawn or any non-confirming report it carries the verbatim same-model tag. The same `MODELS`/`sameModelTag`/tag-string convention is the single source of truth later workflow scripts copy.
- **The four gate/refute roles** — `plan-reviewer` · `architect-reviewer` · `honesty-reviewer` · `finding-verifier` — **spawn with the `fable` model override at the spawn sites** (the WORKFLOW panel bullet is the home; the audit/build skills point back). **Frontmatter stays `model: opus`** — the honest fallback default; a frontmatter `fable` line does not resolve (spike-tested), and a non-resolving value would be a false-wiring claim. Finders and the builder stay builder-class — verdicts are where de-correlation pays.
- **Every judge opens with a `RUNNING AS:` self-report naming its model family** (never the vendor alone, never its role); the orchestrator compares it to the builder family and, on **any same-family run**, applies the verbatim tag: *"same-model review on this run — the judge and the builder are the same model family here."* On a spawn error: respawn with the default + the tag — a gate role never becomes unspawnable. The comparison is model-upheld and stated as such.
- **`finding-verifier` independence is structural:** it receives only `{claim, file:line, source module, confidence, exclude-set}` + a refute-first posture — never the finder's rationale; a lens never verifies its own finding.

Fix: the skill re-passes prior resolved items as `priorItems`; `mergePriorItems` carries them into the regenerated fence unchanged (a re-surfaced findingKey supersedes its prior copy). Same smoke also fixed: init's empty-Refreshed headline claimed a refresh on true-no-op/create-only runs (now three honest branches), and the build copy's "engine isn't installed yet" went stale the moment 5b shipped it (now points at the Workflow-tool session precondition).
- **2026-06-11 — the thorough dogfood's Tier-1s, fixed at 3b's landing + a knowledge-boundary lesson.** (1) Resumed `deferredFindings` are normalized at the boundary (tier defaults 2, tag defaults refactor) and `toResultItem` tier-guards — a tier-less deferred finding silently vanished from the rendered tiers while the run-report still counted it (verified with the full mechanical chain). (2) The FIND thunks now run through `guardedAgent` (catch→null + log): the platform's `parallel()` already resolves a throwing thunk to null — the audit's verifier confirmed a "crash" from repo text alone because that contract lives OUTSIDE the repo; the guard makes the never-crash property local and auditable. **Lesson recorded: findings about tool-runtime semantics cannot be settled from repo text — the platform contract is now stated in-code where it is load-bearing.** (3) `check_versions_synced.py` reports an OSError as "could not be read" instead of misdiagnosing it as invalid JSON.
- **2026-06-11 — `thorough` is now scripted; the backlog fence is a unit-tested helper (plan 0012, Slice 3b).** All three notches run through `workflows/audit.js`: `thorough` adds a whole-scope `blindspot-reviewer` sweep as a pseudo-cell (`blindspot×(scope)` — enumerated last, capped/resumed like any cell, FIND-only, joins the same dedup→verify path) and an adversarial `yagni-sentinel` prune (a second `applyPrune` with the same never-prune-the-`missing-test-baseline` protection; a null sentinel after one retry throws — a thorough run must not pretend it ran its adversarial prune). The prose path is now the **Workflow-tool-unavailable fallback only**. The backlog fence body is built by a **pure `renderBacklogFence` helper** — the format's single source of truth (status line, verbatim 2-line legend, tiers, item format, terminal "sound" signal, run-report same-model replacement, verbatim go-button; `{{DATE}}` placeholder, no markers/heading — those stay SKILL-owned). Format drift is now a unit-test failure, not a model-discipline failure. **Format-compatible, explicitly NOT byte-identical** to a prose-era fence (a byte regression, if wanted, belongs to Slice 7's eval). *(Supersedes the Slice-3a entry's thorough-routes-to-prose and renderer-arrives-in-3b clauses below.)*
- **2026-06-11 — verification results ride WITH the finding, never in a parallel array (plan 0012, Slice 3a dogfood Tier-1).** The first dogfood `standard` audit of this repo caught (and the verifier REPRODUCED) a real bug in `audit.js` itself: after a Refuted finding was dropped, `verificationSummary` indexed the full results array against the shortened kept list — a false cross-model claim. Fix: `applyVerdicts` attaches each kept finding's own `verifierRunningAs`; the parallel-arrays seam is unrepresentable now, pinned by a production-shaped composition regression test. Same dogfood also landed: the cross-script drift pin (`tests/workflows/cross-script.test.mjs` — which immediately caught a real `SAME_MODEL_TAG` const-vs-inline divergence), a synthesis retry-once before the fail-loud terminal, and an explicit `verificationIncomplete` flag (a COMPLETE cell sweep with deferred findings says so mechanically).
- **One thoroughness slider, three notches** (`quick` · `standard` · `thorough`), one uniform pipeline at every notch: **FIND → PRUNE → VERIFY → surface.** All relevant lenses run at *every* level — a lens is never dropped to make a level cheaper; the slider sets the **depth** each lens reads at (`focused` → `deep` → `exhaustive`). `thorough` (named-only, never auto-picked) additionally runs the **blind-spot sweep** (`blindspot-reviewer` — the cross-cutting risk no single module-lens owns) and an **adversarial `yagni-sentinel` prune**; those are what FIND and PRUNE look like at max, not bolt-ons.
- **The re-check is universal:** after the prune, the audit attempts to refute **every surfaced finding, all tiers, every level** (one `finding-verifier` per finding). Every backlog item shows one verification tag; the legend carries the not-a-mechanical-guarantee caveat. A re-found false positive is still false — repeats can't substitute for adversarial re-checking, so identical re-sweeps were retired (**single look per `(module × dir)` cell**); recall rests on lens breadth + depth, honestly stated.
- **Deterministically bounded + resumable:** a finite cell set, one shared backstop `max-cells-per-run` cap (bounds cost and the orchestrator's synthesis context — not per-agent context), `PARTIAL` checkpoints with explicit done/pending cell lists. Findings are never count-capped or silently truncated.
- **Fences are regenerate-don't-accumulate:** the `harness-audit:overview` / `harness-audit:backlog` fences are replace-only-inside, human-owned outside; **no volatile content inside a fence** (byte-identical re-runs); all narration stays conversational. **"Sound on the audited dimensions"** is the explicit terminal signal when Tier 1+2 come back empty — a stop signal, not a treadmill.
- **The "Application source present" predicate is defined once** (audit Phase 1) and reused by `init` — a repo of only docs/config/harness scaffolding is "no application source" (the new-project on-ramp, not an audit target).

- **2026-06-12 — the engine's maiden run (plan 0013 dogfood) + the run-level cross-model mirror fix.** The first real build-to-green run implemented its whole item in the worktree (gates green, independently re-run by the orchestrator) and returned `new-tier12` — escalating a real pre-existing bug it found OUTSIDE the item instead of folding it in (the never-invent-scope contract firing on its own code, on its maiden run). - **2026-06-12 — the build-to-green engine ships (`workflows/build-item.js`; plan 0012, slice 5b): every pause is a return-to-orchestrator; the script never pushes.** The 5a ladder's engine is a Workflow script that iterates one approved item — implement (`implementer-architect` in a `worktree`, iteration 1) → deterministic gates (an agent runs `repo.gateCommands`; pass/fail is read from exit codes — the pass/fail DECISION is mechanical (`gatesGreen` keys off the reported exit codes, never the agent's opinion); the command execution itself is agent-performed; `gatesGreen` treats a missing/non-numeric exitCode as a failure, never fail-open) → the **Verify panel via the ONE-LEVEL `workflow({scriptPath}, …)` child call into `verify.js`** (single source of truth for the panel — an inlined copy would drift; DRY) → **QA via the `qa.js` child call** when machine-checkable acceptance criteria exist (`qaGreen` treats a could-not-run boot as failing — fixable in-loop, never a silent skip) → fix (the residual folded into the next iteration's brief) — until green or the iteration cap (default 3). **The script contains no push/merge/land/git step by construction — every terminal status is a return:** `green` (the before-land pause is the ORCHESTRATOR's; the close-out carries the register verbatim — "passed the deterministic gates and the reviewers' audit on this run — a reduction of unwatched-run risk, never a substitute for the unbuilt deterministic trust-gates"), `needs-irreversible` (the hard-stop), `new-tier12` (a finding outside the item → re-triage, never folded silently), `not-green` at the cap ("not green; here is the residual" — `residualReport`; nothing partial landed, the branch left for inspection), `blocked` (a `check:"manual"` criterion or criteria-with-no-`runApp` re-validated at the boundary — never an unwatched run that can't honestly complete). Tier-1/2 out-of-scope findings from the implementer (`outOfScopeTier12`) escalate as returns; the standing rules in both agent prompts forbid building out-of-scope and forbid any irreversible/external action (it's reported via `irreversibleNeeded`, never performed). No `MODELS` block — the script spawns no judge directly (the pins live in the `verify.js`/`qa.js` children); the `SAME_MODEL_TAG`/`modelFamily`/`sameModelTag`/`parseArgs` block is copied verbatim from `verify.js` (cross-script drift pin extended to build-item.js — minus `MODELS`, which would be dead code). The run-level `crossModel` claim (`crossModelClaim`) folds the children's judge self-reports; `confirmed` only on all-confirming-different-family.
- **2026-06-12 — the flat `autopilot` decline is superseded by the autonomy ladder** (plan 0012, slice 5a): checkpoint default → build-to-green requestable; eligibility = three unlock conditions checked as judgment-with-stated-evidence (CI runs the gates · a test baseline for the touched code · an approved spec with testable acceptance criteria) **plus** script-only execution (`workflows/build-item.js` — never prose); unmet → a verbatim decline naming exactly what's missing. Build-to-green is a reduction of unwatched-run risk, never a substitute for the unbuilt deterministic trust-gates.
- **A thin orchestration layer** over the WORKFLOW pipeline + the audit's backlog — no new pipeline, agents, or state stores. The plain-English ask is the interface; a single named item is the fast path (no triage ceremony).
- **Checkpoint is the default rung:** three routine per-item pauses — the spec before any code · before land · before anything irreversible — plus exception pauses (re-slice, item-failure with *"nothing partial landed"*, re-triage). **Build-to-green is the requestable rung** (see the 2026-06-12 ladder entry above): eligibility-checked per-repo with stated evidence, declines naming exactly what's missing when unmet, and runs only via `workflows/build-item.js` (the engine arrives in slice 5b — until then the engine line is named in the decline too). The cross-model judge is wired but is a risk reduction, not a guarantee.
- **The irreversible hard-stop set** (push to a shared remote **including `main`** — this repo admin-bypasses branch protection — deploy, data deletion, spend, external side-effects): stop, name the action + consequence, ask; never proceed on silence. **Never invent scope** — a discovered feature goes to the roadmap, not into the worklist.
- **The loop:** confirmed ordered worklist → per-item engine → a **scoped re-audit over the touched `(module × dir)` cells** after each landed item (file-level; cross-file fallout is owned by the closing full audit — the harness has no dependency graph and claims none) → **re-triage on any new Tier-1/2** (the chosen safety-over-fatigue trade) → one `standard` closing audit → the terminal signal.
- **Resume derives, never stores:** the worklist reconstructs from the backlog fence + plan files (`Spec'd` = awaiting a sitting · `Approved` = build when reached · unchecked boxes = in-flight, possibly several · removed at Land = done, git history keeps it); the picked *order* is re-confirmed (a 5-second re-confirm beats a third state store). **Approval is never inferred** — only an explicit `Status: Approved` counts.
- **Batch spec-approval is a requestable ask** (*"spec everything first"*), not a standing question — a passive tip line is the only as-we-go addition. The sitting is **roster-first** (a scannable one-line roster; full triads beneath to drill into; approve/adjust/drop, drop unjudged) — the defense against relocating decision-fatigue inside the sitting. Interruption-honesty at the ask **and echoed at the sitting close** (what batch does *not* remove); the sunk-cost fact once, neutrally; a **file-level spec-currency check** before each item pauses to re-confirm if landed work touched the spec's named files.

## The workflow & roles

- **The diverse-panel trigger** (stated once in WORKFLOW Principles): a contested design fork OR a trust/honesty surface convenes `plan-reviewer`/`architect-reviewer` + `yagni-sentinel` + `honesty-reviewer` — plus `product-designer` when user-facing — at **every gate the change passes** (Plan and Verify). Model-upheld: the orchestrator convenes it. A lone reviewer can bless what a diverse panel rejects.
- **Specialist roles are SRP-separate, never modes of each other:** `lens-reviewer` audits exactly one standards module; `blindspot-reviewer` audits the space between modules; `finding-verifier` refutes one claim; `yagni-sentinel` argues over-build; `honesty-reviewer` refutes copy (its bar embedded in the agent — no separate standards module). Agent prompts are **self-contained** — they cannot follow links at spawn, so the DoD gate list is deliberately duplicated inline in the builder/verifier agents (controlled duplication, not drift).
- **The Definition of Done lives canonically in WORKFLOW** (deterministic gates vs reviewer sign-offs — the split is the honesty line); CLAUDE.md and the pipeline table point to it. The Verify effort-dial reuses the Stage-0 "substantial" triggers — no scoring formula.
- **Stage 9 is a finite harvest checklist the orchestrator runs at Land** (a manual discipline, not automation), including the lesson→gate step: a manual/lens catch a gate could have made becomes a roadmap gate item, not just a record.
- **Audit-backlog tags select the execution discipline** (the WORKFLOW tag→discipline table): a `refactor` on untested behavior-bearing code is characterization-tests-first — upheld by the implementer stopping and asking (no mechanical hook enforces this; never imply one exists).
