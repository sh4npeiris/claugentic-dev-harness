# Decisions

The durable architectural record — the standing decisions behind the harness, kept so they aren't re-litigated. **Consult before revisiting a past choice** (see CLAUDE.md → Harness Discipline). For new decisions, **append a dated one-liner at the top of the relevant section** (or a new section); the full build history lives in git.

## Honesty positioning (the #1 rule)

- **Never let copy launder model judgment into apparent mechanical fact.** The current honest split: the **architecture-tree check is the only hook-enforced gate**; `check_versions_synced.py` + the test suite are **deterministic run-gates** (mechanical when run; running them is discipline); everything else — reviewer sign-offs, the diverse panel, the audit's finding re-checks, build mode's pauses — is **model-upheld** and said so.
- **Verb discipline:** the harness *"attempts to / tries to re-check"* and *"tags the outcome"* — never *"verifies / proven / arrives with proof / guaranteed."* Success claims are **dimension-scoped** (*"sound on the audited dimensions"*), never "bug-free/perfect."
- **The two senses of "independent":** claims of model-family independence about the judges are **forbidden** (same vendor → errors stay correlated; the honest claim is *"a different model family — a reduction of shared-blind-spot risk"*). The **structural** sense — clean-context input-contract isolation ("independently re-checks") — is accurate and **preserved**.
- **`[D]` vs `[J]`:** a deterministic-labeled check is only *proven* where the adopter has the relevant tool wired; otherwise it is reported as the model's judgment.

## The deterministic gates

- **One gate, one invariant (SRP siblings):** the tree-check owns the file index (presence · staleness · zero-coverage glob-drift); `check_versions_synced.py` owns the `plugin.json` ↔ `marketplace.json` version pair (the two stamps are one source of truth — every bump moves both). New mechanically-checkable invariants get a sibling script, not an extension.
- **Fail loud, never fail-open:** every gate errors plainly on broken input (missing/garbled files, empty globs) — a gate that silently passes on its own breakage is the forbidden failure class. All gates carry hermetic characterization tests; `python -m pytest` is a Definition-of-Done gate.
- **The tree-check is language-incidental** — harness tooling that never parses project source; it stays Python with `INCLUDE_GLOBS` as the **single per-repo knob** (the valid-extension set is derived from it). Glob-drift detection uses a stable `SOURCE_EXTS` allow-list + the managed-stamp exclusion — **no per-stack registry** (an always-incomplete list re-introduces the rot it claims to kill). Detection is mechanical; the glob *reset* is model-upheld (init's terminating self-correction).
- **The deterministic trust-gates for unwatched runs** (a land-gate hook · a secret-scan · a characterization-tests-first hook) are **not built** — and the harness says so rather than claiming them (asserting "cannot land red" before such hooks exist would be the over-claim the harness forbids); build-to-green is **a reduction of unwatched-run risk, never a substitute** for these unbuilt gates, and its decline names exactly which unlock conditions are unmet (see Build mode).

## Cross-model judges (the verify gates)

- **The four gate/refute roles** — `plan-reviewer` · `architect-reviewer` · `honesty-reviewer` · `finding-verifier` — **spawn cross-model** (a different model family than the builder): **script runs** (Stage-7 `engine/verify.js` + the audit/build engines) pin `model: MODELS.judge` (`opus`) in code; **prose runs** pass the `fable` override at the spawn site (the WORKFLOW panel bullet is the home; the audit/build skills point back). **Frontmatter stays `model: opus`** — the honest fallback default; a frontmatter `fable` line does not resolve (spike-tested), and a non-resolving value would be a false-wiring claim. Finders and the builder stay builder-class — verdicts are where de-correlation pays.
- **Every judge opens with a `RUNNING AS:` self-report naming its model family** (never the vendor alone, never its role); the orchestrator compares it to the builder family and, on **any same-family run**, applies the verbatim tag: *"same-model review on this run — the judge and the builder are the same model family here."* On a spawn error: respawn with the default + the tag — a gate role never becomes unspawnable. The comparison is model-upheld and stated as such. (A present-but-unrecognized family is reported as *unresolved*, never asserted same-model fact — the conservative trust floor; the wording lives once in `engine/*.js`'s `sameModelTag` + the `KNOWN_FAMILIES` source, pinned by `tests/workflows/cross-script.test.mjs`.)
- **`finding-verifier` independence is structural:** it receives only `{claim, file:line, source module, confidence, exclude-set}` + a refute-first posture — never the finder's rationale; a lens never verifies its own finding.

## The audit (`/claugentic-dev-harness:audit`)

- **One thoroughness slider, three notches** (`quick` · `standard` · `thorough`), one uniform pipeline at every notch: **FIND → PRUNE → VERIFY → surface.** All relevant lenses run at *every* level — a lens is never dropped to make a level cheaper; the slider sets the **depth** each lens reads at (`focused` → `deep` → `exhaustive`). `thorough` (named-only, never auto-picked) additionally runs the **blind-spot sweep** (`blindspot-reviewer` — the cross-cutting risk no single module-lens owns) and an **adversarial `yagni-sentinel` prune**; those are what FIND and PRUNE look like at max, not bolt-ons.
- **The re-check is universal:** after the prune, the audit attempts to refute **every surfaced finding, all tiers, every level** (one `finding-verifier` per finding). Every backlog item shows one verification tag; the legend carries the not-a-mechanical-guarantee caveat. A re-found false positive is still false — repeats can't substitute for adversarial re-checking, so identical re-sweeps were retired (**single look per `(module × dir)` cell**); recall rests on lens breadth + depth, honestly stated.
- **Deterministically bounded + resumable:** a finite cell set, one shared backstop `max-cells-per-run` cap (bounds cost and the orchestrator's synthesis context — not per-agent context), `PARTIAL` checkpoints with explicit done/pending cell lists. Findings are never count-capped or silently truncated.
- **Fences are regenerate-don't-accumulate:** the `harness-audit:overview` / `harness-audit:backlog` fences are replace-only-inside, human-owned outside; **no script-generated noise inside a fence** (byte-identical re-runs apart from the orchestrator-stamped audit date); all narration stays conversational. **"Sound on the audited dimensions"** is the explicit terminal signal when Tier 1+2 come back empty — a stop signal, not a treadmill.
- **Two backlog fences, each regenerate-independently (engineering + product):** the engineering audit writes `harness-audit:backlog`; product gap mode writes its **own** `harness-product:backlog` — running one **never** touches the other (the split fixes the cross-contamination where a `build` re-audit wiped the product backlog). The **renderer is reused, not forked** — both fences carry the same `renderBacklogFence` body (the criteria args-mode of `engine/audit.js`); only the target marker differs (DRY). The product fence is a **re-derivable projection of the spec against current code** (it regenerates, symmetric with the engineering fence as a projection of code against standards) — the **durable** product layer is `docs/PRODUCT_SPEC.md` + the human-owned ROADMAP area, **not the fence**. **Cross-fence dedup is model-upheld at `build` triage**, deliberately not mechanical: the two backlogs key findings in **different namespaces** (engineering code-location/`module×dir` vs product criterion-ids), so a mechanical key-match could never fire on a real overlap (overlap is inherently semantic) — model-upheld triage-dedup is the **only coherent** design, not a lazy deferral. Product is **backlog-only — no product `overview` fence** (deliberate asymmetry: the engineering `harness-audit:overview` stays the single repo overview).
- **Stage-9 lesson — fence-conventions are paired-or-explicitly-not:** a singular-"the backlog"/"the fence" assumption had leaked into PLAYBOOK + init + build-resume copy. Any future fence addition must check **every** singular "the backlog"/"the fence" reference and either pair it or record the asymmetry on purpose.
- **The "Application source present" predicate is defined once** (audit Phase 1) and reused by `init` — a repo of only docs/config/harness scaffolding is "no application source" (the new-project on-ramp, not an audit target).
- **The eval (`eval/`) is a seeded-defect drift detector, not a quality guarantee.** `eval/BASELINE.md` is the single source of truth for the measurement procedure; the intentional seeded defects (`eval/fixture-defects/app/` for the standard audit, `eval/fixture-app/` for the QA run) **MUST NOT be "fixed"** — fixing them disarms the exam. The no-peeking contract (the answer keys stay outside the run's scope) is **prompt-scoped + canary-backstopped**, never a filesystem sandbox; `eval/` is repo-local, never copied to adopters.

## Build mode (`/claugentic-dev-harness:build`)

- **A thin orchestration layer** over the WORKFLOW pipeline + the audit's backlog — no new pipeline, agents, or state stores. The plain-English ask is the interface; a single named item is the fast path (no triage ceremony).
- **Checkpoint is the default rung:** three routine per-item pauses — the spec before any code · before land · before anything irreversible — plus exception pauses (re-slice, item-failure with *"nothing partial landed"*, re-triage). **Build-to-green is the requestable rung:** eligibility = three unlock conditions checked as judgment-with-stated-evidence (CI runs the gates · a test baseline for the touched code · an approved spec with testable acceptance criteria) **plus** script-only execution (`engine/build-item.js` — never a prose loop); unmet → a verbatim decline naming exactly what's missing, then checkpoint is offered. The cross-model judge is wired but is a risk reduction, not a guarantee.
- **The build-to-green engine (`engine/build-item.js`) contains no push/merge/land/git step by construction** — every terminal status is a return-to-orchestrator (`green` → the before-land pause is the orchestrator's; `needs-irreversible`; `new-tier12` → re-triage, never folded silently; `not-green` at the cap → "not green; here is the residual", nothing partial landed; `blocked`). It iterates implement (`implementer-architect` in a worktree) → deterministic gates (an agent runs the gate commands; the pass/fail *decision* over the reported exit codes is the mechanical part — `gatesGreen`, never fail-open) → the Verify panel (the `engine/verify.js` child workflow) → QA (`engine/qa.js`, when machine-checkable criteria exist) → fix, until green or the iteration cap.
- **The irreversible hard-stop set** (push to a shared remote **including `main`** — this repo admin-bypasses branch protection — deploy, data deletion, spend, external side-effects): stop, name the action + consequence, ask; never proceed on silence. **Never invent scope** — a discovered feature goes to the roadmap, not into the worklist.
- **The loop:** confirmed ordered worklist → per-item engine → a **scoped re-audit over the touched `(module × dir)` cells** after each landed item (file-level; cross-file fallout is owned by the closing full audit — the harness has no dependency graph and claims none) → **re-triage on any new Tier-1/2** (the chosen safety-over-fatigue trade) → one `standard` closing audit → the terminal signal.
- **Resume derives, never stores:** the worklist reconstructs from **both backlog fences** (engineering + product) + plan files (`Spec'd` = awaiting a sitting · `Approved` = build when reached · unchecked boxes = in-flight, possibly several · removed at Land = done, git history keeps it); the picked *order* is re-confirmed (a 5-second re-confirm beats a third state store). **Approval is never inferred** — only an explicit `Status: Approved` counts.
- **Batch spec-approval is a requestable ask** (*"spec everything first"*), not a standing question — a passive tip line is the only as-we-go addition. The sitting is **roster-first** (a scannable one-line roster; full triads beneath to drill into; approve/adjust/drop, drop unjudged) — the defense against relocating decision-fatigue inside the sitting. Interruption-honesty at the ask **and echoed at the sitting close** (what batch does *not* remove); the sunk-cost fact once, neutrally; a **file-level spec-currency check** before each item pauses to re-confirm if landed work touched the spec's named files.

## The workflow & roles

- **The Product Excellence pass elevates the spec — `product-critic` proposes, the user decides.** Spec mode (`skills/product/SKILL.md`) gains an Excellence pass between draft and validate: the `product-critic` agent is the SRP **elevate** counterpart to `product-designer` (designer *surfaces* the user's truth; critic *elevates* it — never a mode of it). It is **generative/proposing → builder-class** (not cross-model: the user is the verdict-giver, nothing gates on its output — per *Cross-model judges*' finders-stay-builder-class rule). It critiques **by method, not a dimension checklist** (forcing functions, incl. a **mandatory premise-challenge**); it **points at** `docs/standards/product-ux.md` for conformance (no new standards module, no edit to it — the `honesty-reviewer` embed-the-bar precedent) and carries only the *delta* the standard doesn't own. **Voice is balanced/neutral** (surface the case for/against evenhandedly, don't advocate); **removals are encouraged.** Proposals are **questions, never spec content until adopted** (adopt/adapt/reject/defer) — this extends, never violates, the designer's never-invent-scope rule (invention only into a user-decided channel). **Rejected proposals + a declined-pass marker** are remembered in a user-owned fence in `docs/PRODUCT_SPEC.md` (read next refresh so a decided idea is never re-pitched). **Deep-research informs, doesn't certify:** the session `deep-research` skill grounds a benchmark round with citations on demand; unavailable → an honest decline + critique-only fallback where benchmark claims are tagged model-knowledge-not-verified (never claim research that didn't run). A **deferred** proposal lands in ROADMAP's human-owned area **outside** the regenerate-don't-accumulate audit fence — pickup is not automatic: the user names it, OR — once the user adopts it into the spec on a later refresh — a gap run regenerates it. The pass is **default-on every spec-mode run, skippable on ask**; honesty register throughout — it raises the bar, it never guarantees the spec is excellent.
- **The diverse-panel trigger** (stated once in WORKFLOW Principles): a contested design fork OR a trust/honesty surface convenes `plan-reviewer`/`architect-reviewer` + `yagni-sentinel` + `honesty-reviewer` — plus `product-designer` when user-facing — at **every gate the change passes** (Plan and Verify). Model-upheld: the orchestrator convenes it. A lone reviewer can bless what a diverse panel rejects.
- **Specialist roles are SRP-separate, never modes of each other:** `lens-reviewer` audits exactly one standards module; `blindspot-reviewer` audits the space between modules; `finding-verifier` refutes one claim; `yagni-sentinel` argues over-build; `honesty-reviewer` refutes copy (its bar embedded in the agent — no separate standards module). Agent prompts are **self-contained** — they cannot follow links at spawn, so the DoD gate list is deliberately duplicated inline in the builder/verifier agents (controlled duplication, not drift).
- **The Definition of Done lives canonically in WORKFLOW** (deterministic gates vs reviewer sign-offs — the split is the honesty line); CLAUDE.md and the pipeline table point to it. The Verify effort-dial reuses the Stage-0 "substantial" triggers — no scoring formula.
- **Stage 9 is a finite harvest checklist the orchestrator runs at Land** (a manual discipline, not automation), including the lesson→gate step: a manual/lens catch a gate could have made becomes a roadmap gate item, not just a record.
- **Audit-backlog tags select the execution discipline** (the WORKFLOW tag→discipline table): a `refactor` on untested behavior-bearing code is characterization-tests-first — upheld by the implementer stopping and asking (no mechanical hook enforces this; never imply one exists).

## Plugin identity & distribution

- **Engine scripts (`engine/*.js`) distribute by read-from-install-path, never copied.** Adopters invoke `${CLAUDE_PLUGIN_ROOT}/engine/<name>.js` — a runtime artifact class read in place, never copied into an adopter repo (no managed-stamp, no refresh surface); dogfooding this repo uses the repo-local `./engine/<name>.js` (the working tree IS the plugin source). **The dir is named `engine/`, not `workflows/`, specifically so Claude Code doesn't auto-register the scripts as `[dynamic workflow]` slash-commands** (an undocumented behavior of a plugin-root `workflows/` dir). The `INCLUDE_GLOBS` widening to `:(glob)engine/**/*.js` is **this-repo-only** and leaks to no adopter (init's body-compare excludes the `INCLUDE_GLOBS` line on both sides, so widening this repo's source value triggers no adopter REFRESH; adopters have no `engine/` dir to watch).
- **The genuine-managed predicate keys on the STABLE stamp prefix** `claugentic-dev-harness@<semver> managed — do not edit` (trailing clause version-variable; a REFRESH migrates it). Only **detection** loosens to the stable prefix — what `init` **writes** is unchanged (always the current full form). Both clobber-edge legs (path-in-the-managed-set + the full prefix on **line 1**, a bare token in prose not matching) stay mandatory, so never-clobber is not weakened.
- **`check_architecture_tree.py` is the one hybrid managed file (`INCLUDE_GLOBS` carve-out).** It is the **named exception** to "managed files carry zero user content": its `INCLUDE_GLOBS = [ … ]` assignment is the single per-repo knob (`init` writes it per-adopter, re-derives it on drift, invites refinement). So `init`'s body-compare **excludes that assignment on both sides** (an adopter with custom globs reads `CURRENT` when the rest matches — no false REFRESH), and a `REFRESH` **re-injects the adopter's existing globs** rather than resetting them. This keeps the never-clobber + idempotent-at-a-fixed-version claims true as written.
- **`init` is version-aware (upsert-to-installed, RESTAMP-free, prose-decided).** Re-running `init` converges the repo to the installed version: a managed file is `CREATE`/`REFRESH`/`CURRENT`/`USER_FILE` by `init`'s judgment (the genuine-managed predicate — path-in-set + exact stamp + parseable semver — guarded by stop-if-ambiguous; no oracle script). Content-identical managed copies are left byte-untouched (**no RESTAMP**). **Per-file upsert only — `init` never deletes.** **Non-goals:** no 3-way merge of a user-edited managed file (installed wins, git is the recovery net); user-owned docs (`ARCHITECTURE_TREE`/`ROADMAP`/`DECISIONS`) stay create-if-absent. Idempotency at a fixed version is **model-upheld, dogfood-checked, not a wired gate** — claimed as *"converges / true no-op only when already at the installed version,"* never *"provable/mechanical no-op."*
- **`init` requires no "fresh chat" — a skill cannot restart a session, and most of the setup is live at once.** Claude Code **hot-reloads `.claude/settings.json`** (file-watcher), so the architecture-tree hook is enforcing the moment `init` writes it — no restart. `CLAUDE.md` is read once at session start and a skill can't force a re-read, so the new harness instructions load on `/clear`/`/compact`/next-session. So `init` **adopts the workflow in-session** (it just scaffolded it) and **suggests** `/clear` for the cleanest standing setup (recommended before a big `audit`), **never mandating a restart** — the old "start a fresh chat" copy over-stated the requirement and ignored the hot-reloaded hook.
- **Plugin id `claugentic-dev-harness`**; skills `init` · `audit` · `build` · `product`; install via `/plugin marketplace add sh4npeiris/claugentic-dev-harness` → `/plugin install claugentic-dev-harness@sh4npeiris`. Public, **Apache-2.0**.
- **The standards/workflow docs are copied on init** (managed, version-stamped copies the agents read locally). Verified fact worth keeping: a subagent *can* read plugin-bundled files by absolute path, and the install path is version-stamped.
- **Every copied file carries a first-line managed stamp** (`claugentic-dev-harness@<semver> managed — do not edit`); stable HTML-comment **fences mark replace-only-inside regions** (the adopter's CLAUDE.md `harness:managed` block; the audit's ROADMAP fences). Per-repo editable content lives outside the fences. Source modules stay pristine — the stamp is added on copy.
- **Code-analyzing gates compose with the project's own linters/analyzers** rather than being rebuilt per language.
- **Bundled agents are spawned by their namespaced id `claugentic-dev-harness:<role>`** via the `nsAgent` helper (engine `*.js`) + namespaced spawn directives (skills `SKILL.md`); bare names resolve only when dogfooded with project-local `.claude/agents/`, so installed adopters crashed at the first agent spawn (`/audit` + `/build`). Built-ins (`general-purpose`, `Explore`, `Plan`) stay bare. A source-level test (`tests/workflows/agent-namespace.test.mjs`) pins it. (v0.1.34; surfaced by the AskBase pilot 2026-06-15.)
