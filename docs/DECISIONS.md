## 2026-06-04 — Plan-review, manifest spike, repo live (plan 0002 rev 3)

- **Plan 0002 → rev 3** after adversarial plan-review (verdict: CHANGES REQUIRED) + a completeness/innovation critique. All 8 required changes addressed (see the plan's Resolution section): S1 split into **S1a** (module contract — the gate) + **S1b** (migrate the 17 dimensions); S2–S6 are one module each, fanning out **only after S1a**; S8 split/trimmed (run-and-observe + judge-panel are designed-in-prose now, mechanized later).
- **Trust-first** — an independent, deterministic **Trust & Verification** track (deterministic gates + a **frozen behavioral baseline** as the equivalence oracle + **hook-enforced Definition-of-Done** + test-diff/mutation + pre-flight safety scan + a verified-vs-asserted scorecard) is foundational and built early (Phase 1). Rationale: the harness's #1 risk is *false confidence* from the same model class grading its own work; trust must rest on signals independent of it.

Collapses the sync/merge/clobber problem the reviewer flagged.
- **Skills over commands** (spike) — entry points (`init-harness`, `harness-audit`, `harness-explain`) are skills (`skills/<name>/SKILL.md`); plugin hooks live in `hooks/hooks.json` referencing bundled **Node** gates via `${CLAUDE_PLUGIN_ROOT}`; distribution via `.claude-plugin/marketplace.json`; validate with `claude plugin validate`.
- **High-frequency catalog first; capability family deferred (JIT).** Author the 5 modules this repo + a JS app exercise; author Redis/queues/storage/ML/search only when a real audit pulls one in (YAGNI).
- **Repo live:** `sh4npeiris/claugentic-dev-harness` (private), `main`, pushed via SSH. Added `.gitattributes` (`* text=auto eol=lf`) to normalize line endings for a cross-platform plugin.
- **Pre-flight safety scan dropped** (user) — the first dogfood target has no credentials; secret-hygiene stays in the `security` module + a Phase-1 secret-scan gate, and run-and-observe still stubs external side-effects, but there's **no separate safety-scan step/ceremony**.

Install: `/plugin marketplace add sh4npeiris/claugentic-dev-harness` → `/plugin install agentic-dev-harness@sh4npeiris`.

## 2026-06-04 — Re-scope to master plan 0002

- **Re-architected into master plan [`0002`](../.claude/plans/0002-harness-re-architecture.md); `0001` superseded** (its B1–B6 fold into 0002's Phases 2–7). Rationale: the standards/workflow/roles are the substrate the plugin compiles from, so package the *enriched* harness, not the skeleton. The harness's white-space (confirmed vs BMAD/spec-kit/Agent OS/SuperClaude/claude-flow/Cline/Cursor/Aider) is the intersection of: a learning loop, applying a standards catalog to legacy code, and multi-lens (not correctness-only) review.
- **Standards → full multi-lens catalog, restructured into scoped modules** (`docs/standards/`), anchored to **ISO/IEC 25010:2023**, loaded by relevance not all-at-once; highest-value subset becomes **executable fitness-function gates**. (Avoids context-bloat of one ever-growing file.)
- **Learning loop stays lightweight/manual for now** (Stage-9 prose + this file); mechanized version (retrospector agent + Lesson artifact + promotion/`harness-update` sync to solve copy-drift) is **designed-but-deferred** to a reserved roadmap item.
- **Product/UX lens added now** — `product-designer` role, `ux-reviewer` + parallel lens reviewers, a `product-ux` standards module, a product-discovery pipeline stage, and **run-and-observe verification** (you can't audit look-and-feel from prose).
- **Multi-lens review via fan-out + adversarial verify**, and **judge-panel** design exploration at Plan ("evaluate possibilities, take the best of all"). `architect-reviewer` becomes the synthesizer over lens findings.

- **Refinements (same session):** **(a) two-tier knowledge** — the global standards catalog grows + **syncs across all repos** via the plugin/`harness-update`; codebase-specific lessons stay local (`CLAUDE.md`/`DECISIONS`/Current-scope) and never propagate. **(b)** Catalog also carries **technology/capability modules** (Redis/caching, message queues/streams, object storage/CDN, third-party APIs, sidecars, ML/inference, search) — when-to-introduce + how-to-do-it-right + safety rails; the harness modernizes vibe-coded apps (introduce new tech), not just cleans code. **(c)** Audit yields **two backlog tracks** — behavior-preserving **refactors** (characterization-first) and **capability-upgrades** (new tech → feature pipeline w/ flag + dual-write/shadow + migration + rollback). **(d) Not Python-centric** — harness tooling/gates reimplemented in **Node/JS** (first target is a JS app); `check_architecture_tree` ports to Node. **(e)** Furnished: scoped review **effort dial** (anti-gold-plating), durable **`docs/PRODUCT.md`**, **compose-with-existing-tooling** on init, objective **UX signals** (Lighthouse/a11y/heuristics) + a per-repo quality **`docs/SCORECARD.md`**.

## 2026-06-04 — Bootstrap

- **Harness extracted from DistrictSync (PR #16) into a standalone repo.** The working harness lived as files inside the DistrictSync project (`docs/WORKFLOW.md`, `docs/ENGINEERING_STANDARDS.md`, `.claude/agents/*`, `.claude/plans/*`, `.claude/settings.json`, `scripts/check_architecture_tree.py`); copied out and **generalized** (stripped all project specifics) to seed `agentic-dev-harness`.
- **`init` = scaffold-only; audit is a separate `/harness-audit`.** Installing the harness (`/init-harness`) only scaffolds (docs, generate ARCHITECTURE_TREE, per-repo Current-scope, CLAUDE harness section, detect languages → set check globs) and is fast + idempotent. Gap-analysis of the codebase is a deliberately separate command so init stays cheap and re-runnable.
- **Audit → ROADMAP backlog; refactor per-item & gated (characterization-tests-first); no bulk auto-refactor.** `/harness-audit` writes a prioritized backlog to `docs/ROADMAP.md`; each item is brought to standard one at a time through the full pipeline, with the `refactor-item` workflow writing characterization tests *before* touching code and verifying behavior unchanged. The harness **never** does a mass/automatic rewrite of a codebase.
- **Packaged as a dedicated-repo plugin.** Shipped as a Claude Code plugin from this dedicated repo (`.claude-plugin/plugin.json` manifest + commands + agents + workflow docs), installable via a marketplace into any codebase — rather than copy-pasting harness files per project.
