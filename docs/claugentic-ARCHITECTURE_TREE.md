# Architecture Tree

> **Read this first.** This is the one-line-per-file index of the repo — your map. Use it to find the right file instead of reading the whole tree. Keep it current: every file add/move/remove updates this index (a hook enforces presence + staleness — see CLAUDE.md → Harness Discipline). Descriptions are authored by you/the agent that touches the file.

This repo builds the **`claugentic-dev-harness`** Claude Code plugin. Its executable code is the gate scripts under `scripts/` and the Workflow choreography under `engine/` (the v2 re-platform — the audit pipeline, the Verify panel, the QA runtime, and the build loop as scripts the skills invoke; named `engine/` not `workflows/` so the platform never registers them as `[dynamic workflow]` slash-commands); everything else is harness docs, specialist roles, the plan template, config, and the measurement fixtures under `eval/` (runnable targets, deliberately out of the gate's scope). `INCLUDE_GLOBS` watches only `scripts/**/*.py` + `engine/**/*.js`.

## Root

- `README.md` — what `claugentic-dev-harness` is + the concrete value it delivers (the three commands: init · audit · build), how it installs, how it works (init → audit → build the reviewed pipeline), and an honest status section.
- `CLAUDE.md` — lean, generalized guidance for agents working in THIS repo: engineering principles, harness discipline, workflow pointer, and a one-line Definition-of-Done pointer to `docs/claugentic-WORKFLOW.md` (the canonical gate list).

- `.gitattributes` — normalizes line endings (`* text=auto eol=lf`; scripts forced LF) for a cross-platform plugin.
- `LICENSE` — Apache License 2.0 (the repo is public; © 2026 Shan Peiris).
- `pyproject.toml` — minimal pytest config (`testpaths=["tests"]` + the `integration` marker) so `python -m pytest` runs the gate's test suite.

## .claude/agents/ — specialist role library

- `.claude/agents/plan-reviewer.md` — adversarially critiques a draft plan (Stage 3): soundness, sizing/completeness, risk, YAGNI, harness impact; edits only the plan's Review section. A gate/refute judge on the most-capable model (`model: opus`); opens `RUNNING AS:` (same-model review reported honestly). The safeguard is **structural** — a clean-context input contract, never the checked rationale — not model diversity.
- `.claude/agents/implementer-architect.md` — implements one approved, spec'd slice to standard in an isolated worktree (Stage 6); lands code + tests + docs with no debt.
- `.claude/agents/architect-reviewer.md` — owns the Verify gate (Stage 7): audits the diff against in-scope `docs/claugentic-standards/` modules in **solo** mode or **synthesizes** lens-reviewer + yagni-sentinel in **fan-out** mode; read-only. A cross-model gate/refute judge (a different family than the builder, a shared-blind-spot-risk reduction; opens `RUNNING AS:`; same-model tagged); script runs pin via `engine/verify.js`; `model: opus`.
- `.claude/agents/product-designer.md` — product/UX discovery + design lens (Stage 1, user-facing work): user, job-to-be-done, flows, states, "what good feels like"; applies `product-ux`, persists to `docs/claugentic-PRODUCT.md`.
- `.claude/agents/product-critic.md` — the **elevate** counterpart to `product-designer`: critiques a draft product spec by **method** (forcing functions incl. a mandatory premise-challenge), returns proposals the user decides on (adopt/adapt/reject/defer); builder-class, balanced voice, read-only.
- `.claude/agents/lens-reviewer.md` — audits a **diff (Verify) or an audit-scope (the `audit` skill)** against ONE named `docs/claugentic-standards/` module; two modes (Verify-diff / Audit-scope), invoked per-lens in a fan-out; in Audit-scope reads at the orchestrator-passed **`depth`** — the 3-rung ladder `focused`/`deep`/`exhaustive` (the dial's only lever, never which lenses run); read-only, returns per-dimension findings for the synthesizer.
- `.claude/agents/yagni-sentinel.md` — the anti-over-engineering skeptic: argues a plan/diff is too much (speculative abstraction, premature infra, gold-plating); read-only, returns a cut-list. (Also the audit's `thorough`-only adversarial prune over consolidated findings.)
- `.claude/agents/finding-verifier.md` — the audit's adversarial-verify counterpart to `lens-reviewer`: given ONE finding (claim + `file:line`, never the finder's rationale), reads the code and tries to **refute** it → `Verified`/`Refuted`/`Unconfirmed`; invoked on **every** finding after the prune; read-only, `model: opus`. The safeguard is **structural** (a clean-context input contract), not model diversity. A false-confidence reduction.
- `.claude/agents/blindspot-reviewer.md` — the audit's **cross-cutting / between-the-modules** sweep (the `thorough` dial's blind-spot finder): its lens is the whole scope, red-teaming the risk **no single module-lens owns** (emergent smells, seam gaps, systemic issues); always `exhaustive`, read-only, opus. **FINDS only** (re-checked by `finding-verifier`), same shape as `lens-reviewer`, so dedup→prune→verify is unchanged.
- `.claude/agents/honesty-reviewer.md` — the harness's **claims / over-claim** lens: refutes **copy** (not code), flagging text that launders model-or-human-upheld judgment into mechanical fact (verb discipline · `[D]`/`[J]` label integrity · `cross-model ≠ independent`); the bar is embedded in the prompt. On the diverse panel at Plan + Verify on trust surfaces; read-only. A cross-model gate/refute judge, `model: opus`.

## skills/ — harness entry points (the `/claugentic-dev-harness:*` family)

- `skills/init/SKILL.md` — the 9-step **version-aware** scaffold: upserts the managed set to the installed version (four verdicts — create/refresh/leave/skip — via the genuine-managed predicate keyed on the stable `claugentic-dev-harness@<semver> managed` stamp), generates ARCHITECTURE_TREE, sets `INCLUDE_GLOBS`, merges the tree-check hook, declares the plugin for teammates (5c), seeds ROADMAP/DECISIONS; **never-clobber user content**.
- `skills/audit/SKILL.md` — thin trigger: Understand + invoke `engine/audit.js` + write the rendered backlog. Phase 1 = overview + audit-plan + dial; Phase 2 = invoke the script (`thorough` adds blind-spot + yagni-sentinel); Phase 3 = write `result.renderedBacklog` between the `harness-audit:backlog` markers (replace-only) + replace `{{DATE}}`. **Format source of truth = `renderBacklogFence` + tests.** Carries the **prose-orchestrated fallback**.
- `skills/build/SKILL.md` — the backlog **go-button**: a thin layer driving items through the WORKFLOW pipeline in **checkpoint mode** (per-item pauses before code/land/irreversible). Triage reads BOTH backlog fences (engineering + product) into one tier-interleaved worklist; the loop works item-by-item via the per-item engine + a scoped re-audit over touched cells; build-to-green requestable per-repo. Guardrail: the irreversible hard-stop set.

- `skills/product/SKILL.md` — the **product layer** entry (`/claugentic-dev-harness:product`), two modes. **Spec mode** — `product-designer` drafts per the template, then the **Product Excellence pass** (`product-critic` proposals; rejected → the `rejected-proposals` fence), frozen-schema re-validate, write the user-owned PRODUCT_SPEC.md. **Gap mode** — `engine/audit.js` criteria mode (args mode, not a fork) → the `harness-product:backlog` fence.

## engine/ — executable choreography (Workflow-tool scripts)

- `engine/verify.js` — the Stage-7 Verify panel as an executable Workflow script: fans one `lens-reviewer` per in-scope standards module + `yagni-sentinel` + `honesty-reviewer`, dedups lens gaps, then an `architect-reviewer` synthesis (judges `model: MODELS.judge` cross-model). The cross-model disclosure tag is computed in code from judge self-reports — a **three-state disclosure**. Helpers tested by `verify.test.mjs`; gate via `INCLUDE_GLOBS`.
- `engine/audit.js` — the audit pipeline (FIND→PRUNE→VERIFY) as an executable Workflow script, all three notches (`thorough` adds the `blindspot` sweep + a `yagni-sentinel` prune). Fans `lens-reviewer` over `(module×dir)` cells, then **one `finding-verifier` per finding**; returns `renderedBacklog`. **Criteria mode is an args mode, NOT a fork.** Carries the `engine/verify.js` trust-surface block (**three-state disclosure**).

- `engine/build-item.js` — the build-to-green engine as an executable Workflow script (Goal 3): one approved item iterated **implement (`implementer-architect`) → gates (`gatesGreen`, mechanical, never fail-open) → Verify (`engine/verify.js`) → QA (`engine/qa.js`) → fix** until green or the cap. **NEVER touches git — every terminal status returns to the orchestrator.** Spawns no judge; carries the `engine/verify.js` trust-surface block.
- `engine/qa.js` — runtime verification (QA) Workflow script — **boot + flow-driving** (`boot-only` no criteria · `full` with criteria). A boot `agent` starts the app + probes `appUrl` on a bounded `readinessPlan` (a failed boot ⇒ a could-not-run **finding**). Full mode drives one `agent` per criterion → UX findings re-checked by **one `finding-verifier`** (the **three-state disclosure** tag). Carries `engine/verify.js`'s trust-surface block.

## scripts/ — tooling

- `scripts/claugentic-check_architecture_tree.py` — deterministic (no-LLM) gate: this index lists every in-scope source file (presence), references no deleted file (staleness), keeps each entry within the `MAX_ENTRY_CHARS` (450) one-line FORM budget (`_form_violations`), and **detects glob drift** (flags when `INCLUDE_GLOBS` watches no files while non-managed source exists). `--hook`/`--hook-write` wired by `init`; `INCLUDE_GLOBS` the one knob.
- `scripts/check_versions_synced.py` — deterministic (no-LLM) version-sync gate: `plugin.json`'s `version` is the source of truth; FAILS LOUD (exit 1) if `marketplace.json`'s plugin-entry `version` disagrees, or on broken input (missing file / garbled JSON / absent `version`). Scope = the two manifest versions only. A DoD run-gate (like `pytest`), not hook-wired; the two files are parsed independently (one broken can't mask the other).
- `scripts/build_release.py` — dev-only tool building the clean **release** from `main`: `classify()` (the testable core) splits tracked files ship-vs-strip via an explicit dev-only list (default-include so a forgotten file ships not vanishes). `--apply` rebuilds a local `release` branch (no push); `--dry-run` prints the split. `_dropped_merges`/`UPSTREAM_REF`: `--apply` REFUSES on a stale base (HEAD missing an `origin/main` merge).
- `scripts/check_doc_budgets.py` — deterministic (no-LLM) ledger byte-budget run-gate (NOT hook-wired): flags (never edits) a managed ledger exceeding its `DOC_BUDGETS` total-byte budget (CLAUDE.md 6000 · DECISIONS 40000 · ROADMAP 12000), naming the compaction fix. Independent fail-loud reads (missing/unreadable/over each surface); `main()` exits 1 on any breach. Run from the repo root in the DoD suite + CI.
- `scripts/claugentic-advisor.py` — deterministic (no-LLM) SessionStart ADVISOR (not a gate): derives ONE "where am I / what's next" line from the two `docs/claugentic-ROADMAP.md` backlog fences + in-flight `.claude/plans/*.md` (+ adopter-only CLAUDE.md managed-fence version, skipped when absent). Emits size-capped `{systemMessage, additionalContext}` JSON; silent + fail-safe exit 0. Bundled hook (plan 0022).

## eval/ — measurement fixtures (not gate-enforced, not vendored)

The harness's runnable targets: `fixture-app/` for runtime verification (`engine/qa.js`), and `fixture-defects/` — the seeded-defect baseline the audit re-takes as a drift detector. *(Out of `INCLUDE_GLOBS` — listed for the map; the fixture python (`eval/fixture-defects/app/*.py`) is OUT of `INCLUDE_GLOBS [scripts/**/*.py, engine/**/*.js]`, so the gate never presence/staleness-checks it AND the zero-coverage drift census never runs over it — `glob_drift` short-circuits whenever the globs already match ≥1 file, which they do here, so eval source is invisible to the gate by design. The fixture's deps are documented, not installed; `pyproject` `testpaths=["tests"]` keeps a bare pytest run out of `eval/`.)*

- `eval/fixture-app/main.py` — the minimal FastAPI list app `engine/qa.js` boots against: `GET /` serves the static page, `GET /api/items` returns an in-memory list, `POST /api/items` appends; seeds 3 items unless `FIXTURE_SEED=0` (the one knob the empty-state run flips). The `/api/item` typo route the seeded broken flow POSTs to does NOT exist — it 404s on purpose.
- `eval/fixture-app/static/index.html` — the page with **two permanent intentional seeded UX defects** (DO NOT "fix" — the flow-driving run's catch targets): a **broken add flow** (`ux-broken-flow`, the form POSTs the typo'd `/api/item`, 404s, swallows the error) and a **missing empty state** (`ux-missing-empty-state`, `load()` has no zero-data branch so `FIXTURE_SEED=0` renders a blank `<ul>`). The heading + add form are the pass surface.
