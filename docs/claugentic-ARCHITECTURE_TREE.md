# Architecture Tree

> **Read this first.** This is the one-line-per-file index of the repo — your map. Use it to find the right file instead of reading the whole tree. Keep it current: every file add/move/remove updates this index (a hook enforces presence + staleness — see CLAUDE.md → Harness Discipline). Descriptions are authored by you/the agent that touches the file.

This repo builds the **`claugentic-dev-harness`** Claude Code plugin. Its executable code is the gate scripts under `scripts/` and the Workflow choreography under `engine/` (the v2 re-platform — the audit pipeline, the Verify panel, the QA runtime, and the build loop as scripts the skills invoke; named `engine/` not `workflows/` so the platform never registers them as `[dynamic workflow]` slash-commands); everything else is harness docs, specialist roles, the plan template, config, and the measurement fixtures under `eval/` (runnable targets, deliberately out of the gate's scope). `INCLUDE_GLOBS` watches only `scripts/**/*.py` + `engine/**/*.js`.

## Root

- `README.md` — what `claugentic-dev-harness` is + the concrete value it delivers (the four commands: init · product · audit · build), how it installs, how it works (init → audit → build the reviewed pipeline), and an honest status section.
- `CLAUDE.md` — lean, generalized guidance for agents working in THIS repo: engineering principles, harness discipline, workflow pointer, and a one-line Definition-of-Done pointer to `docs/claugentic-WORKFLOW.md` (the canonical gate list).
- `.gitignore` — ignores local junk + build artifacts; **shares** `.claude/agents/`, `.claude/plans/`, `.claude/settings.json` (ignores only `.claude/settings.local.json`).
- `.gitattributes` — normalizes line endings (`* text=auto eol=lf`; scripts forced LF) for a cross-platform plugin.
- `LICENSE` — Apache License 2.0 (the repo is public; © 2026 Shan Peiris).
- `pyproject.toml` — minimal pytest config (`testpaths=["tests"]` + the `integration` marker) so `python -m pytest` runs the gate's test suite.

## .github/ — CI

- `.github/workflows/ci.yml` — GitHub Actions CI: on push/PR to `main`, runs the test suite (`pytest`, ubuntu + windows, Python 3.12), the workflow-script helper tests (`node --test`, Node 22, ubuntu + windows), and the two deterministic gate scripts (the architecture-tree + version-sync checks) — the DoD's deterministic gates, now machine-run unconditionally.

## .claude/agents/ — specialist role library

- `.claude/agents/plan-reviewer.md` — adversarially critiques a draft plan (Stage 3): soundness, sizing/completeness, risk, YAGNI, harness impact; edits only the plan's Review section. A gate/refute judge — spawned with the `fable` model override (cross-model: a different model family than the builder, a shared-blind-spot-risk reduction; opens `RUNNING AS:`; same-model runs tagged); frontmatter stays `model: opus` (the honest fallback).
- `.claude/agents/implementer-architect.md` — implements one approved, spec'd slice to standard in an isolated worktree (Stage 6); lands code + tests + docs with no debt.
- `.claude/agents/architect-reviewer.md` — owns the Verify gate (Stage 7): audits the diff against in-scope `docs/claugentic-standards/` modules in solo mode (small) or synthesizes `lens-reviewer` + `yagni-sentinel` findings in fan-out mode; read-only, cross-model gate/refute judge (pinned by `engine/verify.js` on script runs, orchestrator-overridden on prose; frontmatter `model: opus` fallback). Prompt + judge protocol in-file.
- `.claude/agents/product-designer.md` — product/UX discovery + design lens (Stage 1, user-facing work): user, job-to-be-done, flows, states, "what good feels like"; applies `product-ux`, persists to `docs/claugentic-PRODUCT.md`.
- `.claude/agents/product-critic.md` — the **elevate** counterpart to `product-designer`: critiques a draft product spec by **method** (forcing functions incl. a mandatory premise-challenge), returns proposals the user decides on (adopt/adapt/reject/defer); builder-class, balanced voice, read-only.
- `.claude/agents/lens-reviewer.md` — audits a **diff (Verify) or an audit-scope (the `audit` skill)** against ONE named `docs/claugentic-standards/` module; two modes (Verify-diff / Audit-scope), invoked per-lens in a fan-out; in Audit-scope reads at the orchestrator-passed **`depth`** — the 3-rung ladder `focused`/`deep`/`exhaustive` (the dial's only lever, never which lenses run); read-only, returns per-dimension findings for the synthesizer.
- `.claude/agents/yagni-sentinel.md` — the anti-over-engineering skeptic: argues a plan/diff is too much (speculative abstraction, premature infra, gold-plating); read-only, returns a cut-list. (Also the audit's `thorough`-only adversarial prune over consolidated findings.)
- `.claude/agents/finding-verifier.md` — the audit's adversarial-verify counterpart to `lens-reviewer`: given ONE surfaced finding (claim + `file:line`, never the finder's rationale), independently re-reads the cited code and tries to refute it → Verified/Refuted/Unconfirmed; invoked on every finding after the prune; read-only, cross-model gate/refute judge (`fable` override; `model: opus` fallback). Input contract + refute protocol in-file.
- `.claude/agents/blindspot-reviewer.md` — the audit's cross-cutting sweep (the `thorough` dial's blind-spot finder): its lens is the whole scope, red-teaming the risk no single module-lens owns (emergent smells, seam gaps, systemic issues); always `exhaustive` depth, read-only, opus. FINDS only (re-checked by `finding-verifier`) and returns `lens-reviewer`'s per-finding shape so dedup→prune→verify is unchanged. Red-team prompt in-file.
- `.claude/agents/honesty-reviewer.md` — the harness's claims / over-claim lens: refutes copy (not code), flagging text that launders model-or-human-upheld judgment into apparent mechanical fact (verb discipline · `[D]`/`[J]` integrity · cross-model ≠ independent). On the diverse panel at Plan + Verify on trust surfaces; read-only, cross-model gate/refute judge (`engine/verify.js`-pinned; `opus` fallback). Not deterministic. Criteria in-file.

## engine/ — executable choreography (Workflow-tool scripts)

- `engine/verify.js` — the Stage-7 Verify panel: fans out one `lens-reviewer` per in-scope standards module + `yagni-sentinel` + `honesty-reviewer`, then an `architect-reviewer` synthesis (verdict passed through). The canonical Verify panel (`engine/build-item.js` calls it as a child workflow, DRY). Pure helpers tested by `tests/workflows/verify.test.mjs`; gate-enforced. Roster, dedup, cross-model tag, and judge protocol in the file header.
- `engine/audit.js` — the audit pipeline (FIND→PRUNE→VERIFY), all three dial notches scripted: a `lens-reviewer` fan-out (`thorough` adds `blindspot-reviewer` + `yagni-sentinel`) then one `finding-verifier` per finding, returning the result + `renderedBacklog` (the pure `renderBacklogFence`). Product-gap criteria mode is an args mode. Helpers tested by `tests/workflows/audit.test.mjs`. Pipeline, fence source of truth, criteria seam in-file.

- `engine/build-item.js` — the build-to-green engine: iterates one approved item implement → gates → Verify (`engine/verify.js`) → QA (`engine/qa.js`) → fix until green or cap. `nextAction` makes the priority decision; the script NEVER lands/pushes/touches git — every terminal status returns to the orchestrator. Helpers tested by `tests/workflows/build-item.test.mjs`; gate-enforced. Loop, priority order, and the stage-timeout register in-file.
- `engine/qa.js` — runtime verification (QA): a boot vertical that starts the app and probes the bounded `readinessPlan` (a failed boot emits one evidence-carrying `qa-could-not-run-app` finding), plus full-mode flow-driving that drives one agent per criterion and folds each fail to a UX finding re-checked by a `finding-verifier`. Teardown ALWAYS runs in a `finally`. Helpers tested by `tests/workflows/qa.test.mjs`. Both modes in-file.

## scripts/ — tooling

- `scripts/claugentic-check_architecture_tree.py` — the deterministic (no-LLM) tree gate enforcing PRESENCE (this index lists every in-scope file), STALENESS (no entry points to a deleted file), GLOB DRIFT (flags zero-coverage rot), and the per-entry FORM budget (`MAX_ENTRY_CHARS`). `--hook`/`--hook-write` modes are wired by `init`; `INCLUDE_GLOBS` is the only per-repo knob. Mode/boundary/predicate rules in the module docstring.
- `scripts/check_versions_synced.py` — deterministic (no-LLM) version-sync gate: `.claude-plugin/plugin.json`'s `version` is the single source of truth; FAILS LOUD (exit 1) if `.claude-plugin/marketplace.json`'s plugin entry disagrees or on any broken input. Scope = the two manifest versions only (no stamp scan); parsed independently so one broken file can't mask the other. A DoD run-gate (like `pytest`), not hook-wired.
- `scripts/check_doc_budgets.py` — deterministic (no-LLM) ledger byte-budget run-gate (NOT hook-wired): flags (never edits) a managed ledger exceeding its `DOC_BUDGETS` total-byte budget, naming the compaction fix. Independent fail-loud reads; `main()` exits 1 on breach.
- `scripts/claugentic-advisor.py` — deterministic (no-LLM) SessionStart ADVISOR (not a gate): derives ONE "where am I / what's next" line from the two `docs/claugentic-ROADMAP.md` backlog fences + in-flight `.claude/plans/*.md` (+ adopter-only CLAUDE.md managed-fence version, skipped when absent). Emits size-capped `{systemMessage, additionalContext}` JSON; silent + fail-safe exit 0. Bundled hook (plan 0022).

## eval/ — measurement fixtures (not gate-enforced, not vendored)

The harness's runnable targets: `fixture-app/` for runtime verification (`engine/qa.js`), and `fixture-defects/` — the seeded-defect baseline the audit re-takes as a drift detector. *(Out of `INCLUDE_GLOBS` — listed for the map; the fixture python (`eval/fixture-defects/app/*.py`) is OUT of `INCLUDE_GLOBS [scripts/**/*.py, engine/**/*.js]`, so the gate never presence/staleness-checks it AND the zero-coverage drift census never runs over it — `glob_drift` short-circuits whenever the globs already match ≥1 file, which they do here, so eval source is invisible to the gate by design. The fixture's deps are documented, not installed; `pyproject` `testpaths=["tests"]` keeps a bare pytest run out of `eval/`.)*

- `eval/fixture-app/main.py` — the minimal FastAPI list app `engine/qa.js` boots against: `GET /` serves the static page, `GET /api/items` returns an in-memory list, `POST /api/items` appends; seeds 3 items unless `FIXTURE_SEED=0` (the one knob the empty-state run flips). The `/api/item` typo route the seeded broken flow POSTs to does NOT exist — it 404s on purpose.
- `eval/fixture-app/static/index.html` — the fixture page carrying TWO permanent, intentional seeded UX defects (DO NOT "fix" — they are the flow-driving run's catch targets): a broken add flow (`ux-broken-flow` — form POSTs to the typo'd `/api/item`, 404s, swallows the error) and a missing empty state (`ux-missing-empty-state` — `load()` has no zero-data branch, so `FIXTURE_SEED=0` renders a blank void). The heading + form are the pass surface.
