# Architecture Tree

> **Read this first.** This is the one-line-per-file index of the repo — your map. Use it to find the right file instead of reading the whole tree. Keep it current: every file add/move/remove updates this index (a hook enforces presence + staleness — see CLAUDE.md → Harness Discipline). Descriptions are authored by you/the agent that touches the file.

This repo builds the **`claugentic-dev-harness`** Claude Code plugin. Its executable code is the gate scripts under `scripts/` and the Workflow choreography under `engine/` (the v2 re-platform — the audit pipeline, the Verify panel, the QA runtime, and the build loop as scripts the skills invoke; named `engine/` not `workflows/` so the platform never registers them as `[dynamic workflow]` slash-commands); everything else is harness docs, specialist roles, the plan template, config, and the measurement fixtures under `eval/` (runnable targets, deliberately out of the gate's scope). `INCLUDE_GLOBS` watches only `scripts/**/*.py` + `engine/**/*.js`.

## Root

- `README.md` — what `claugentic-dev-harness` is + the concrete value it delivers (the three commands: init · audit · build), how it installs, how it works (init → audit → build the reviewed pipeline), and an honest status section.
- `CLAUDE.md` — lean, generalized guidance for agents working in THIS repo: engineering principles, harness discipline, workflow pointer, and a one-line Definition-of-Done pointer to `docs/claugentic-WORKFLOW.md` (the canonical gate list).
- `.gitignore` — ignores local junk + build artifacts; **shares** `.claude/agents/`, `.claude/plans/`, `.claude/settings.json` (ignores only `.claude/settings.local.json`).
- `.gitattributes` — normalizes line endings (`* text=auto eol=lf`; scripts forced LF) for a cross-platform plugin.
- `LICENSE` — Apache License 2.0 (the repo is public; © 2026 Shan Peiris).
- `pyproject.toml` — minimal pytest config (`testpaths=["tests"]` + the `integration` marker) so `python -m pytest` runs the gate's test suite.

## .github/ — CI

- `.github/workflows/ci.yml` — GitHub Actions CI: on push/PR to `main`, runs the test suite (`pytest`, ubuntu + windows, Python 3.12), the workflow-script helper tests (`node --test`, Node 22, ubuntu + windows), and the two deterministic gate scripts (the architecture-tree + version-sync checks) — the DoD's deterministic gates, now machine-run unconditionally.

## .claude/agents/ — specialist role library

- `.claude/agents/plan-reviewer.md` — adversarially critiques a draft plan (Stage 3): soundness, sizing/completeness, risk, YAGNI, harness impact; edits only the plan's Review section. A gate/refute judge — runs on the most capable available model (`model: opus` — the most-capable tier alias); opens `RUNNING AS:` (same-model review reported honestly). The safeguard is **structural** — a clean-context input contract, never the rationale behind what it's checking — not model diversity.
- `.claude/agents/implementer-architect.md` — implements one approved, spec'd slice to standard in an isolated worktree (Stage 6); lands code + tests + docs with no debt.
- `.claude/agents/architect-reviewer.md` — owns the Verify gate (Stage 7): audits the diff against in-scope `docs/claugentic-standards/` modules in **solo** mode (small changes) or **synthesizes** lens-reviewer + yagni-sentinel findings in **fan-out** mode; read-only. A gate/refute judge — cross-model (a different model family than the builder, a shared-blind-spot-risk reduction; opens `RUNNING AS:`; same-model runs tagged); **script runs** pin the model explicitly via `engine/verify.js`, **prose runs** use the orchestrator's override per WORKFLOW Principles; frontmatter stays `model: opus` (the honest fallback).
- `.claude/agents/product-designer.md` — product/UX discovery + design lens (Stage 1, user-facing work): user, job-to-be-done, flows, states, "what good feels like"; applies `product-ux`, persists to `docs/claugentic-PRODUCT.md`.
- `.claude/agents/product-critic.md` — the **elevate** counterpart to `product-designer`: critiques a draft product spec by **method** (forcing functions incl. a mandatory premise-challenge), returns proposals the user decides on (adopt/adapt/reject/defer); builder-class, balanced voice, read-only.
- `.claude/agents/lens-reviewer.md` — audits a **diff (Verify) or an audit-scope (the `audit` skill)** against ONE named `docs/claugentic-standards/` module; two modes (Verify-diff / Audit-scope), invoked per-lens in a fan-out; in Audit-scope reads at the orchestrator-passed **`depth`** — the 3-rung ladder `focused`/`deep`/`exhaustive` (the dial's only lever, never which lenses run); read-only, returns per-dimension findings for the synthesizer.
- `.claude/agents/yagni-sentinel.md` — the anti-over-engineering skeptic: argues a plan/diff is too much (speculative abstraction, premature infra, gold-plating); read-only, returns a cut-list. (Also the audit's `thorough`-only adversarial prune over consolidated findings.)
- `.claude/agents/finding-verifier.md` — the audit's adversarial-verify counterpart to `lens-reviewer`: given ONE surfaced audit finding (claim + `file:line`, never the finder's rationale), independently reads the cited code and tries to **refute** it → `Verified` / `Refuted` / `Unconfirmed`; invoked on **every** finding the audit is about to surface (all tiers, every dial level), after the prune; read-only. A gate/refute judge — runs on the most capable available model (`model: opus` — the most-capable tier alias); opens `RUNNING AS:` (same-model review reported honestly). The safeguard is **structural** — a clean-context input contract, never the rationale behind what it's checking — not model diversity. A false-confidence reduction, not a deterministic gate. (Structural/clean-context independence of the input contract is a separate, accurate claim.)
- `.claude/agents/blindspot-reviewer.md` — the audit's **cross-cutting / between-the-modules** sweep (the `thorough` dial's diverse blind-spot finder): its lens is the *whole scope*, red-teaming for the risk **no single module-lens owns** (emergent architectural smells, integration gaps at the seams, systemic cross-cutting issues); always `exhaustive` depth, read-only, opus. **FINDS only** (re-checked by `finding-verifier` like any finding) and returns the **same per-finding shape** as `lens-reviewer`, so the dedup → prune → verify path is unchanged.
- `.claude/agents/honesty-reviewer.md` — the harness's **claims / over-claim** lens: refutes **copy** (not code), flagging text that launders model-or-human-upheld judgment into apparent mechanical fact (the verb discipline · `[D]`/`[J]` label integrity · dimension-scoped success claims · `cross-model ≠ independent`); the bar is **embedded in the prompt** (no standards module — promote when a 2nd consumer appears). Part of the diverse panel at Plan + Verify on trust/honesty surfaces; read-only. A gate/refute judge — cross-model (a different model family than the builder, a shared-blind-spot-risk reduction; opens `RUNNING AS:`; same-model runs tagged); **script runs** pin the model explicitly via `engine/verify.js`, **prose runs** use the orchestrator's override per WORKFLOW Principles; frontmatter stays `model: opus` (the honest fallback). A reduction of false confidence, not a deterministic gate (does **not** mechanically cross-check).

## engine/ — executable choreography (Workflow-tool scripts)

- `engine/verify.js` — the Stage-7 Verify panel as an executable Workflow script: validates args at the boundary, logs the derived roster, fans out one `lens-reviewer` per in-scope `docs/claugentic-standards/` module + `yagni-sentinel` + (trust-surface) `honesty-reviewer`, dedups lens gaps in code, then an `architect-reviewer` synthesis — judges spawned with the `model: MODELS.judge` (`opus`) cross-model param (one no-override respawn on error, force-tagged same-model; second failure throws). The verdict is passed through from synthesis (never overridden); the cross-model claim/disclosure tag is computed in code from the judges' self-reports — a **three-state disclosure** (`SAME_MODEL_TAG` resolved-same · `UNRESOLVED_FAMILY_TAG` a present-but-unrecognized family, reported as unresolved not asserted same-model · `null` cross-model), `modelFamily`'s regex derived from the one named `KNOWN_FAMILIES` source, and an unresolved self-report is `log()`ged not silently degraded. Pure decision logic lives in the marked `// --- helpers ---` block (unit-tested by `tests/workflows/verify.test.mjs`). Read-from-install-path (`${CLAUDE_PLUGIN_ROOT}/engine/verify.js`), never copied to adopters; gate-enforced via the widened `INCLUDE_GLOBS`.
- `engine/audit.js` — the audit pipeline (FIND → PRUNE → VERIFY) as an executable Workflow script — **all three notches scripted** (`quick`/`standard`/`thorough`). Validates the audit-plan args (fail loud), enumerates `(module×dir)` cells (at `thorough`, appends the whole-scope `blindspot×(scope)` pseudo-cell last — capped/resumed like any cell), applies the `maxCellsPerRun` cap (PARTIAL + exact done/pending cell lists for deterministic resume), fans out one `lens-reviewer` per module batch at `depthForDial(dial)` (**at `thorough`, also one `blindspot-reviewer` over the whole scope** in the same `parallel()` — FIND-only, its findings join the same dedup path), dedups by normalized `issueClass` (weakest-confidence-wins), runs a synthesis self-review prune (the `missing-test-baseline` key **never** pruned — coded exception; **at `thorough`, also an adversarial `yagni-sentinel` sweep** over the consolidated set → a second `applyPrune` with the same baseline protection; a null sentinel after one retry throws), then **exactly one `finding-verifier` per surviving finding** (judge-pinned `model: MODELS.judge`, clean-context `buildVerifierInput` — never the finder's rationale; one no-override respawn, then `deferred`). `applyVerdicts` maps Verified/Refuted/Unconfirmed → verified-tag/dropped/unconfirmed (no-verdict → deferred); the run claims cross-model only on all-confirming-different-family self-reports. Returns a structured object **+ `renderedBacklog`** — the complete fence body built by the pure `renderBacklogFence` helper (status line · verbatim 2-line legend · tiers most-urgent-first with the documented item format · terminal "sound" signal when Tiers 1+2 empty · run report with the same-model replacement rule · verbatim go-button; `{{DATE}}` placeholder, no markers/heading — the fence format's single source of truth). **Product-gap (criteria) mode — an args mode, NOT a fork (Slice 6):** when `args.criteria` is present (a product-spec acceptance-criteria array), the SAME pipeline runs with the criteria as the lens source — `cellsFromCriteria` validates each criterion against the **FROZEN schema** (`id`/`feature`/`flow`/`expect`/`states`/`check`; throws naming the offending id on a missing/extra key, bad `check`/`states`, empty list, or duplicate id) and returns one cell per criterion (criterion ids ARE the cells — capped/resumed identically); `validateCriteriaArgs` makes modules/scopeDirs/dial unnecessary (the criteria list bounds FIND, depth fixed `deep`, level `gap`); `buildCriterionLensPrompt` instructs a **static** intent-vs-implementation read (locate code via `docs/claugentic-ARCHITECTURE_TREE.md`; does NOT run the app — that's `engine/qa.js`'s job); the one control-flow branch swaps the cell/find source, everything downstream (dedup → synthesis prune → one-`finding-verifier`-per-finding → `renderBacklogFence`) is byte-for-byte the standard path.
