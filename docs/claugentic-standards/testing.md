# Testing — does the suite actually prove the behavior, and will it catch the next regression?

> **Loads when:** tests are added, edited or deleted; a behavior change that *should* be tested; a refactor of legacy/untested code (characterization first); UI work (visual + a11y); flaky-test triage; coverage/CI-gate changes.
> Method, tags, honesty register: `README.md` → *Reading a module*.
> **Governing rule: trust the oracle, not the author's word.** "Tests pass" is necessary, never sufficient — ask *what would have to break for this test to fail?*

---

## Test pyramid (shape of the suite: unit / integration / e2e)

- **Auditor checks —** `[J]` Each behavior tested at the cheapest level that proves it, not pushed up into a slow/broad test for convenience. `[J]` No inverted pyramid (many e2e, few unit) signalling untestable design. `[D]` Suite wall-clock and per-tier counts, where the runner reports tiers. `[J]` Integration tests exercise the *real* seam (DB, serialization, HTTP contract), not a mock of the thing under test.

## Characterization tests & golden master (the equivalence oracle for legacy refactors)

- **Auditor checks —** `[J]` Characterization/approval tests land *before* a non-trivial refactor of untested code (visible in commit order or PR narrative). `[J]` They capture *actual* behavior — quirks and bugs included — not idealized behavior. `[D]` Golden-master baselines committed, diffable, regenerable by a documented command. `[J]` Throwaways later promoted to intent-revealing tests, or kept deliberately. `[J]` The baseline/oracle absorbed its adversarial pass **before** its first recorded run — the same fix afterwards is indistinguishable from tuning the exam toward a wanted result, and the artifact then owes a defect-versus-tuning rule *(0044 S1a)*.

## Mutation testing (are the tests real?)

- **Auditor checks —** `[D]` Mutation run on the changed critical module; score meets the agreed threshold (e.g. ≥80% on core logic). `[J]` Survivors triaged (gap → assertion; equivalent → justified suppression), not blanket-ignored. `[J]` Aimed at logic that matters, not vanity-run over trivial code. `[D]` Mutation config/CI step present where adopted. `[J]` For every **named central claim** — a test whose *name* asserts a structural property ("anchored to `__file__`, not the cwd" · "capped" · "byte-identical") — build the exact wrong implementation it forbids and **run it**: red? Four vacuity shapes recur (0041 S10a): **self-recompute** (the test recomputes the implementation's own expression) · **own-constant tautology** (asserted against the implementation's exported constant — remedy: an **independent literal** in the test, so a swapped, dropped, reordered or added element is a diff) · **ambient coincidence** (the one cwd / locale / timezone / **working-tree shape** where right and wrong agree — run the mutant in the shape the defect *inhabits*) · **inactive regime** (an overflow guard pinned only on inputs that never overflow) · **corpus-elsewhere** (the artifact carries the asserted string twice, so the mutant's target was never its only source). `[J]` Boundaries pinned from **both** sides (`n-1`, `n`, `n+1`) against a **fixed** reference — one side only lets `>` vs `>=` *and* a changed threshold survive.
- **Incident —** 0041 S3 (2026-08-13): three load-bearing pins asserted nothing. A `__file__`-vs-cwd pin recomputed its own expression and pytest runs from the root where both coincide (killed by a subprocess with `cwd=tmp_path` over a **decoy** manifest); a 30-day boundary fed boundary **+5s** let `>`→`>=`, `30`→`7` and `abs()` all survive (killed by a `(29,F) (30,F) (31,T) (-31,F)` table against a **fixed** `now`); a "byte-identical" promise was pinned only where the reserve never bites. One genuinely **equivalent** mutant (`.isdecimal()`→`.isdigit()`) was proven so over all 1,114,112 code points and kept with its proof.

## Declarative artifacts (CI workflows, manifests, config — and instruction files a human or agent executes) — assert the refusal, not the vocabulary

- **Good looks like —** Parse with a real parser; **scope** each assertion to the unit that owns the behavior (job · step · key); assert the **refusal or effect** (the `exit 1`, the `needs:` edge, the denied permission), never that a keyword appears. Cross-artifact parity is **derived** as a set relation plus a floor, never hand-typed. **This dimension owns the anchoring technique** for an instruction artifact with no parser (a runbook, a prompt/skill file, a template an agent executes): assert the anchor occurs **exactly once**, split on it, assert **inside that slice** — never an ordinal index, never the whole file. Fixtures are **extracted from the artifact's own bytes**; a hand-transcribed copy tests your reading of the prose, not the prose.
- **Auditor checks —** `[D]` Delete the guard clause the test names, re-run: red? (a whole-file substring survives on a neighbouring `echo`, comment or error message). `[J]` Each assertion anchored to its owning job/step/key, not searching the document globally. `[J]` It asserts the artifact *refuses* the bad case, not that it *mentions* the check. `[D]` Artifact parsed (YAML/JSON/TOML), not string-matched. `[J]` Cross-artifact parity derived, not hand-maintained. `[D]` Occurrences of the asserted literal **in the artifact itself**: >1 makes a whole-file assertion vacuous *by construction* — region-scope, then re-run the deletion mutant. `[D]` Every fixture for an instruction artifact derived from that artifact, not hand-transcribed.
- **Incident —** Three, same repo. (1) `/build` and `/condense` shipped across v0.4.0–v0.5.1 with **unparseable YAML frontmatter** — three releases loading with empty metadata, because nothing parsed them. (2) 0041 S2 (2026-08-12): **13 mutants, 9 alive** — deleting a lease comparison *and its `exit 1`* left the suite 26/26 green on a surviving `echo` in an adjacent step; closed by a `_step_run(job, name_fragment)` helper failing loud on 0-or-2 matches, plus `gate_scripts(ci) ⊆ gate_scripts(release)` replacing a hand-typed parity list. (3) 0041 S7 (2026-08-16), twice in one slice, the second inside the fix for the first: a whole-file substring pinned a path occurring eight times, so deleting the headline row left all 638 tests green; region-scoping (`text.count(anchor) == 1`, split, match inside) went red.

## Code the suite cannot EXECUTE, pinned as TEXT — assert the effect, and weigh the cost of moving the code

- **Good looks like —** Regions no test can call (below a module's seam, inside `__main__`, a shell body, import-time control flow) get a **text** pin under the declarative-artifact bar (*Declarative artifacts* above owns the anchoring technique), asserting the **effect the construct must produce**, never that it *exists*: *"a loop over the report is present"* is vocabulary, *"the loop's body reaches the log"* is the effect. Second half, the design cost: **relocating production code so a unit test can reach it changes the thing that ships** — pay it for **values** (an output over many inputs, an ordering, a format), never for **shape**.
- **Auditor checks —** `[D]` Run the mutant that **keeps the named construct and removes its payload** (keep the loop, delete the call inside it): red? `[D]` **A pin guarding a FORBIDDEN construct is mutated by CONSTRUCTION, not deletion — BUILD the forbidden implementation in a different syntax from the one the spec named, and run it.** A pin phrased in the spec's vocabulary (the wrapper's name, `.map(`) stays green against the same hazard written as an in-place `for` loop; state what the pin forbids as the **hazard** (what must not be swallowed, reshaped, spawned), never as today's construct. `[J]` The assertion names an effect — a value produced, a call reached, an order held — not a keyword satisfiable without the behavior. `[D]` Region-anchored, not whole-file. `[J]` Where the diff **moved** production code to make it testable: does the pin need values, or only shape? A move for a shape-only pin is production surface bought for nothing. `[J]` The region's untestability is recorded where the next author meets it (the seam's own index/doc entry).
- **Incident —** 0041 S10a (2026-08-17), both halves in one slice: a pin asserted a `for…of` loop **exists**, and the mutant that kept the loop and deleted the `log()` inside it survived — under a test whose own failure message names the defect. The same slice relocated **three** helpers "so they can be pinned"; one earned it, two bought ~two dozen lines of production surface each for defects a **one-line** region-anchored assertion already guards. *Recurred at S10b: a pin on a "fatal if ignored" trap asserted the guard's **vocabulary**, and the gate built **two** forbidden implementations green at HEAD.*

## Exemptions and allowlists inside a scan are themselves under test

- **Good looks like —** Every skip / exempt / allow branch is production logic: positive-only coverage proves the vocabulary is *live*, only the negative fixture proves the exemption is *narrow*.
- **Auditor checks —** `[D]` Every branch of the exemption vocabulary exercised, parametrized over a set **derived** from the scan's own source. `[J]` Per branch, a fixture where that exact token rides a real violation and the scan **still fires**. `[J]` Each admitted phrase read against the class the guard is named for — that class, or one that merely co-occurs with it? `[D]` Delete the exemption, re-run: which tests go red? (a guard nothing pins is decoration). `[J]` The exemption's measured **residual** is written down — what it knowingly lets through — not implied to be zero.
- **Incident —** 0041 S6 (2026-08-14/15), twice in one slice, in the guard that had just become the **sole** mechanical custody of a class of stale shipped copy: a "history is not a denial" contract shipped with a **forward** clause naming the next slice, exempting a line that made a false claim about today; the second member was a bare present-state negation ("is no longer *shipped*"). Both narrowed to their honest collocations and pinned in both directions.

## A scan's CORPUS is part of its contract — enumerate from the tracked tree, not the disk

- **Good looks like —** `git ls-files` with a fail-loud `check=True`, one enumeration convention per repo, plus a **floor pin** (`len(candidates) >= N`). **A working checkout is not the repo** — a walk also swallows vendored virtualenvs, tool caches, build output and **linked worktrees parked inside the checkout**, each a full second copy. **The same bar covers every DERIVED input, above all the scan's VOCABULARY:** a derivation is lossy by construction, so assert **completeness**, not non-emptiness — import the owner's cardinality contract rather than re-parsing the document a second time. **The corpus of a repo-wide content scan includes the slice that ADDS it** (plan record, ledger line, the pin's own docstring), and it sees the working tree, never git history — so a **commit message** is outside every such scan by construction (`docs-traceability.md` → *Change explainability* owns that half). *(0041 S11: an already-landed commit message carried three forbidden tokens and had to be amended; the amended-away copy stays in history, unscanned, permanently.)*
- **Auditor checks —** `[D]` No `rglob(` / `os.walk(` / repo-rooted recursive glob in the scanners or their tests, unless it walks a directory it owns outright. `[D]` Run the sweep in **both** shapes — maintainer's checkout and a fresh clone or linked worktree — corpus **sizes** must match. `[J]` Reuses the repo's one enumeration helper, rather than a second that will drift. `[D]` A corpus floor assertion exists. `[J]` The convention is recorded **at the call site** (do-not-revert comment), since no gate re-derives it. `[D]` For every DERIVED set, mutate the source so **one** member stops parsing (bold the cell, footnote it, re-case it): red, or does the set quietly shrink while the scan reports clean? `[D]` The derived set's size is pinned against a cardinality another file **owns**, not a floor / non-empty check that 1-of-N satisfies. `[J]` A docstring that claims a delegation is an assertion: make it mechanical or delete the claim.
- **Incident —** 0041 S9 (2026-08-17): a pin enumerated markdown with `Path.rglob`. In the maintainer's checkout, **129 `.md` files, 61 leaked from linked worktrees** under a gitignored `.claude/worktrees/`, against **60 files and zero leaks** via `git ls-files` — GREEN in a worktree, GREEN in CI (which clones fresh, so this class passes CI *by construction*), RED only where the land ran; with worktrees removed the walk still took 8 untracked `.md` from a vendored virtualenv and a tool cache. *Recurred at S11 (2026-08-18) on the derived-VOCABULARY half, in a slice whose spec CITED this dimension: a containment pin derived its token set by regex and asserted only non-emptiness, so bolding **one** cell dropped that token and republishing it elsewhere passed the entire suite — the sibling guard counted ROWS, the pin counted format-matching CELLS. Killed by importing the sibling's row-count contract and asserting equality.*

## A checker's VERDICT is part of its contract — what it measured decides, and a narrowed run says so

- **Good looks like —** A tool that emits a pass/fail owes two totalities. **Measurement:** every quantity the run collects either **enters the verdict** or is printed as *advisory* — a figure in the report while the exit code comes from a narrower set is a green light with the evidence for red already on screen. **Scope:** a run narrowed by a flag (`--only`, `-k`, a subset filter) prints **what it covered** and can never reach the unqualified verdict line.
- **Auditor checks —** `[D]` For each figure the tool prints, break what it measures and re-run: does the **exit code** move, or only the report? `[J]` No collected quantity is neither in the verdict nor labelled advisory. `[D]` Run each narrowing flag: the verdict line names the subset, and the unqualified line is unreachable from it. `[J]` A narrowed run's transcript is distinguishable from a full run's.
- **Incident —** 0044 S1a (2026-08-20), **three in one slice**, in an instrument whose whole job is emitting verdicts: a hazard probe printed a dead endpoint's connection attempts yet scored on *"still running at the bound"* alone, so a 24-attempt no-backoff retry storm scored AVOIDED; the calibration runner printed `12/13` held-out and **exited 0**, neither held-out nor spec-compliance drift reaching `problems`; and `--only <id>` printed the unqualified pass line off **1 of 13** cases. All three found by reading the report against the exit code, never by the suite.

## Forward promises need a tripwire (a strict expected-failure that fires when the promise is KEPT)

- **Good looks like —** When code **registers something ahead of its writer** — a manifest entry, an annotation, a contract vouching for an artifact a later change will produce — the promise carries a **mechanical expiry**, not only a comment. Cheapest form: a **strict** expected-failure (`@pytest.mark.xfail(strict=True)`, `it.failing`) asserting the **fulfilled** state, red today and red the moment the promise is kept, forcing whoever lands the later change to delete the marker. **Strictness is the whole point:** a lenient expected-failure passes in both worlds and guards nothing. *(Do-not-re-propose, 2026-08-14: pinning the strictness itself — a meta-test reading its own source for the decorator argument — guards against vandalism, not drift.)*
- **Auditor checks —** `[D]` Grep the diff for forward-looking registrations and comments (*will*, *once X lands*, *planned*, a TODO naming a future change) — each has a test that **changes state** when the future arrives. `[D]` The marker is **strict**. `[J]` The tripwire asserts the *fulfilled* state (flips on success), not today's state (flips on nothing). `[J]` The abandonment branch is written down — what the annotation becomes if the promised change is dropped.
- **Incident —** 0041 S4 (2026-08-13): a referential-closure gate accepted a new config path as an "init generates it" output while the init step writing it was a **later slice of the same plan**, and its own "if that slice is ever abandoned, re-annotate" instruction had **no mechanism behind it** — drop the slice and the gate vouches forever, green, for a file nothing produces. Closed by three lines **plus** the wording fix that stopped asserting a plan-order convention as a *property*; neither half works alone.

## Coverage of behavior, not vanity %

- **Auditor checks —** `[J]` Tests assert outcomes a caller cares about, not private internals and mock call-order. `[J]` No test executes code and asserts nothing (or only `not throws`) where a real outcome should be checked (diff-coverage gate: *Test-diff review*). `[J]` They would fail if the behavior silently changed — not only if the implementation is rewritten.

## Test-diff review (did the assertions/coverage get weaker?)

- **Auditor checks —** `[D]` Grep the diff for `skip`, `only`, `xit`, `xdescribe`, `@Disabled`, `@Ignore`, `pytest.mark.skip`, `todo`, commented-out assertions, widened tolerances. `[J]` Each removed/loosened assertion or regenerated snapshot has a stated, legitimate reason. `[D]` Diff-coverage shows changed lines didn't drop below threshold. `[J]` No expected value changed *to follow* the implementation (rubber-stamping a regression) rather than an intended behavior change.

## Failure-path & edge-case coverage

- **Auditor checks —** `[J]` Boundaries and invalid inputs tested, not only the typical case. `[J]` Every error branch / `catch` / fallback exercised and its *effect* asserted (not just "didn't crash"). `[D]` Branch coverage on the changed unit (catches untested error arms). `[J]` External-dependency failure modes injected (timeout/5xx/exception) and the degradation asserted.

## Determinism (no flaky tests)

- **Auditor checks —** `[D]` Grep for nondeterminism smells: `sleep(`, `setTimeout`-then-assert, unseeded `random`, `Date.now()`/`new Date()`/`time.time()` in assertions, order-dependent fixtures, `@Retry`/`flaky`/`rerun` annotations masking instability. `[J]` Async synchronized by await/poll on a condition, not a magic delay. `[D]` Suite passes under randomized order (`--shuffle`/`-p randomly`) and on repeat runs. `[J]` Known-flaky tests tracked and being fixed, not silently retried.

## Regression & snapshot tests

- **Auditor checks —** `[J]` Each bug fix carries a test that pins the corrected behavior and would have caught the original. `[D]` Snapshot files committed and present in the diff. `[J]` Snapshots scoped and meaningful, not sprawling captures rubber-stamped on update. `[J]` Any snapshot update is *justified by an intended change*, not a silent regression auto-accepted.

## Visual-regression & accessibility testing (UI)

- **Good looks like —** UI changes guarded by **visual-regression** diffs against an approved baseline across key viewports/themes (Playwright / Chromatic / Percy / Storybook), and by **automated a11y** checks (axe-core via Playwright/Cypress/Storybook, or `jest-axe`) failing the build on WCAG violations. Automated a11y is a **floor, not a pass** — axe-core detects roughly half of issues (Deque 2021: ~57% across 13,000+ pages; older tool estimates ~30%) — backed by keyboard-nav and screen-reader passes per `product-ux.md`.
- **Auditor checks —** `[D]` axe/jest-axe assertions on changed UI; build fails on new violations. `[D]` Visual baselines committed, diffs reviewed (not auto-accepted). `[J]` Critical states (loading/empty/error, focus, RTL, dark mode) captured, not just the happy render. `[J]` Automated a11y treated as a floor, with manual keyboard/SR coverage for what scanners miss.

## Contract testing (provider/consumer compatibility)

- **Auditor checks —** `[J]` Changes to a published API/event carry a contract test (pact, schema-compat, stored-response verification) rather than slow brittle end-to-end. `[D]` Provider verification / schema-back-compat runs in CI and passes; broker "can-I-deploy" green where adopted. `[J]` The contract is the genuine consumer expectation, kept in sync, not a stale hand-written stub. `[D]` Breaking-change detector (Buf/OpenAPI-diff) gates the published surface.
