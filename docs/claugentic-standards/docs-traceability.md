# Docs & Traceability — the change is explainable, the architecture is navigable

> **Loads when:** files are added, moved or removed (ARCHITECTURE_TREE); a non-trivial decision is made (DECISIONS); public APIs or non-obvious logic change (docstrings/comments); onboarding/runbook docs are touched.
> Method, tags, honesty register: `README.md` → *Reading a module*.

---

## Architecture-tree index currency

- **Auditor checks —** `[D]` the tree gate exits 0 where wired (`python` / `python3` / `py` — `scripts/claugentic-check_architecture_tree.py`) · `[J]` otherwise the tree verified by eye, and every file this change adds has an entry · `[J]` no entry — and no ledger line this change touches — RESTATES a value the file itself owns (a cap, a version, an enum list, a threshold): an index entry is a **LOCATOR**, a restated value is an ungated second source of truth, and the honest measure is how many places one change to that value must touch. The one exception, stated not silent: a count that is genuine reader-value in *pitch* copy ("9 specialist agents") may stay, deliberately and on the record; in an index or a ledger it is always a locator.
- **Incident —** 0041 S4 (2026-08-13): a user-approved cap bump had to be applied in **five** places — the config owning the value, a byte-exact test pin, the tree entry, a ledger line restating the number, and the dated record of *why* — while the slice's own copy called it "the same one-line edit". Locator-ising the tree entry and the ledger took it to three, the third a deliberate drift-detection pin that stays.

## Decision traceability (DECISIONS.md)

- **Auditor checks —** `[J]` non-trivial decisions in the diff are recorded · `[J]` the entry is dated and carries the rationale, not just the choice.

## Load-bearing invariant traceability (INVARIANTS.md)

- **Good looks like —** A constraint that *must stay true or something breaks*, whose rationale is non-obvious from the code, is a standing entry in `docs/claugentic-INVARIANTS.md`: the **invariant**, the **why** (rationale / blast radius), **dated provenance**. Lazily created. Distinct from `DECISIONS.md` (historical "what we chose and why"): an invariant is **live**, read every time code in its blast radius changes.
- **Honesty register —** This ledger is **user-owned documentation, not a gate**. Nothing mechanically verifies the invariants hold, deliberately: a stale or missing entry is a documentation gap, not a build failure. *(Do-not-re-propose.)*
- **Auditor checks —** `[J]` a non-obvious constraint this change established (an ordering dependency, a "these two must move together", an assumption a caller relies on) is captured with its why + dated provenance · `[J]` an existing invariant whose blast radius this change touched still holds, and its entry is still accurate · `[J]` each entry is genuinely load-bearing, not a style preference or a decision belonging in DECISIONS · `[J]` the constraint is not already held **where it bites** — a red-first pin plus a do-not-revert comment at the call site beats a ledger entry, and this ledger is for the ones no pin can hold (a cross-file ordering, a rationale with no code to attach to); prefer the pin and say you did · `[J]` an un-pinnable invariant is filed **even when the file sits at its band** — this is an admission test on the CONSTRAINT, never on free bytes, and the recourse is the condensation ladder, never a skipped entry.
- **Incident —** Load-bearing constraints (e.g. the two version manifests that must move together) were caught only by eye or in production, because the "or it breaks" rationale lived nowhere but the author's head. *(0041 S10b, 2026-08-17: the D6 trust-surface constraint was discharged as behavioural pins plus a call-site comment, ledger untouched — the rule behind that call had been living only in the plan file, which is deleted at plan close.)*

## Docstrings and inline comments

- **Auditor checks —** `[D]` public functions/classes carry docstrings, lint-enforced where available · `[J]` complex or counterintuitive logic carries an explanatory comment · `[J]` no comment merely restates the code.

## Forward promises in prose — future tense, a named owner, and a falsifier

- **Good looks like —** Any sentence describing a capability a **later change** will wire — docstring, comment, skill/README copy, index entry, ledger line, approval summary — rides the **future tense**, **names the change that makes it true**, and is backed by a **mechanical falsifier** (`testing.md` → *Forward promises need a tripwire* owns that half). An abandoned promise is rewritten, never left standing. **The mirror image fails the same way: a pointer to a ROUTING claims the routing EXISTS** — *"routed (backlog item N)"*, *"tracked as X"*, *"deferred to Y"* asserts a **present** fact about another file, so the referent is written before or in the same commit, never after.
- **Auditor checks —** `[D]` grep the diff's *prose* (docstrings, comments, `.md` copy, index entries, plan/approval text) for present-tense capability verbs — *is wired, consults, fires, surfaces, is visible at every* — and ask of each: true when this lands, in a fresh clone? · `[J]` if not, it is future-tense **and** names the change that wires it · `[D]` a falsifier exists for it · `[J]` one correctly-hedged site is a signal, not a clean bill — sweep every sibling saying the same thing · `[D]` every *routed / tracked / deferred-to* citation the diff ADDS resolves in the named target: pointer and referent land together, or neither lands · `[D]` when the diff EDITS a ledger, the neighbours of the touched line are re-read — a status/remaining-work line is exactly what a land falsifies, and the file is already open · `[D]` a hand-maintained field that an AUTOMATIC surface republishes (a header a hook reads, a status a dashboard prints) is DERIVED from the authoritative state or pinned — the staleness is *published*, not merely stored.
- **Incident —** 0041, three consecutive slices (S3 · S4 · S5, 2026-08-13/14): each shipped new copy describing, in the present tense, a mechanism a **later slice of the same plan** would wire — a compensating control that did not exist, four sibling registrations beside one correctly-hedged one, and a gate docstring claiming a warning "is visible at every commit" before anything chained that gate. Review caught all three, which is the evidence that the missing rule was an **authoring** rule. *(Live and unfixed: a plan's `Resumable from:` header is republished by `scripts/claugentic-session-advisor.py` into the SessionStart context an agent reads first, with no gate behind it — at 0041's closing commit it named Slice 10a while the plan stood at Slice 12b.)*

## Reach, not residence — where a capability LIVES is not where it is USABLE

- **Good looks like —** Every instruction to run, import or invoke something is scoped to where that thing is **in the reader's world**. **Distribution membership and repo-local presence are two facts** — in the package/image/payload vs on disk in the reading project — both stated wherever the difference is actionable, so a sentence can be present-tense-true about the payload and false for every reader. **Corollary: never invite a reader to substitute the tool's own copy** — a tool resolving its subject from its install location (`__file__`, `argv[0]`, the image workdir) measures **its** tree, so the honest design takes the subject as an argument and the verdict names what it measured. **The mirror direction SHRINKS work: where a defect LIVES is not who it REACHES** — classify every path the harm touches against the distribution boundary (what the payload carries, what the reading project receives, what a generator re-creates) before spec'ing the fix.
- **Auditor checks —** `[D]` every run/import instruction in reader-facing or shipped text resolves **from a fresh clone of the reader's project** · `[J]` payload membership and repo-local presence stated as two facts wherever a reader could act on the difference · `[J]` no copy suggests pointing the tool's own copy at another tree · `[J]` a stated failure **symptom** is the one the reader's deployment shape produces (installed vs dev checkout vs CI), not only the author's · `[D]` a correction applied "at all N sites" is a **class, not a count** — re-derive the list by grep after the fix and quote it · `[D]` the sweep closes on the **RETIRED STRING**, not your site list: name the exact phrase the change retires and assert **zero** across `git ls-files` · `[D]` frontmatter is IN that corpus — a skill's or agent's `description:` is a capability surface, not prose: the string a model reads to decide whether to load the tool, and it ships · `[J]` wrapped lines hide members from a line-scoped grep — normalize the wrap markers (blockquote `> `, list continuations) to one space before matching, then adjudicate by hand; that normalization is a **sweep you read, never a gate** (as a standing predicate its paragraph-scoped window fires on honest copy — measure the false-positive rate before proposing one) · `[J]` every **deictic** in shipped instruction text resolves in the **reader's** frame — *this repo, here, your, the current* and *above, below, the next section*; a block that MOVES carries its spatial deictics with it, so "move it verbatim" plus "place it after X" is jointly unsatisfiable and the spec says which wins.
- **Incident —** 0041 S6 (2026-08-14/15): a gate script was reclassified to ship, and **eight** shipped sentences then told adopters to run it. In a scratch adopter project the command exited **2, `can't open file`**, and the plugin's own copy returned a verdict **about the plugin's own tree**; the slice had implemented a spec line that was itself wrong, so a spec-conformant diff was no defense. *(S12a: six pointer sites were re-derived by grep; the seventh — `skills/condense/SKILL.md:3`, a shipped `description:` still crediting a relocated procedure, in a frontmatter that had already shipped unparseable across v0.4.0/v0.4.1/v0.5.0 — surfaced only from a zero-result grep on the retired phrase. S9: an adopter note reading "a few references below resolve to the installed plugin" was moved above the two lines it corrected — byte-faithful, and false. S11, reversed: a leak framed as adopter-facing touched only stripped-or-regenerated paths, deleting three deliverables from the slice before a line was written.)*

## Quantities in prose — the method, the boundary, and the arithmetic that closes

- **Good looks like —** Every measured number reaching a durable surface — CHANGELOG, ledger entry, acceptance criterion, review verdict, commit message — is **reproducible**: it names the **method** (the command, or the sum) and the **boundary** (base vs head vs the merge tree; which region; bytes vs characters). Measured **once and propagated**, never re-typed from memory at the next surface.
- **Auditor checks —** `[D]` every numeral the diff ADDS to a durable surface re-measures under its stated method — **a precise-looking figure with no stated method is itself the finding** · `[D]` any printed decomposition (`A = B − C + D`) evaluates, **signs** included · `[J]` each figure names its boundary — two figures for "the same" quantity are not automatically a contradiction, base and head are different boundaries · `[D]` every quantitative AC is feasible under the same spec's own *this stays* clauses: compute the ceiling first; if the target exceeds it **the spec is the defect** (`docs/claugentic-WORKFLOW.md` → Stage 7, the spec-amendment path), the diff delivers the ceiling, and no shipped surface claims the criterion was met · `[D]` an **ABSENCE is a measurement only if the search could have FOUND the thing** — before publishing a negative grep, prove the pattern against a **known-positive control** and confirm nothing truncated its input (`cut`/`head -c`, a line-scoped matcher over wrapped prose, a pattern that cannot cross the corpus's markdown emphasis) · `[J]` **default to a LOCATOR over a count** — the locator rule under *Architecture-tree index currency* above binds any durable prose restating a value another artifact owns; where the number is derivable, write the derivation.
- **Incident —** 0041 S12a (2026-08-18): a relocation published **"6,037 bytes"** to `CHANGELOG.md` and to a **permanent** decisions shard though no boundary of the change produces it — the measured net was **5,785** and the commit message already said so. Same review: a decomposition printed `6,556 − 792 − 21` for a term that had *shrunk* (correct: `+ 21`), and 4,108 vs 4,087 for one region were called contradictory when they were base and head. And the SPEC subtracted a 4,108 B region it also ordered to **stay**, making its `>=10,000 B` criterion unreachable by **3,444 B** — the second consecutive slice whose criterion, not whose diff, was the defect. *(S12b: a spec note asserted a phrase **absent** from a file where it sits verbatim, from **two independently sufficient mechanical causes** — a pattern that could not cross the file's markdown bold, run against a line already truncated by `cut -c1-300`. The class fired **five** times in that slice, right after the slice that harvested the rule; what the rule lacked was a **default**.)*

## Change explainability (commit and PR narrative)

- **Good looks like —** Conventional Commits, and the message explains **why**. **The message that LANDS is the one the shell delivered, not the one you typed** — a commit narrative is prose full of backticks, `$`, `!` and quotes, every one a metacharacter: inside double quotes a backticked span is *command-substituted away*, silently, with the commit still exiting 0. A mangled message is permanent and un-gated — a commit message is outside every file-corpus scan by construction (`testing.md` → *A scan's CORPUS is part of its contract*).
- **Auditor checks —** `[J]` messages conventional and explaining motivation · `[J]` the PR description covers what changed, why, and how to test it · `[D]` the message was delivered from a **file**, not an inline `-m` string containing a backtick, `$(`, `$` or `!` · `[D]` the landed message read back (`git log -1 --format=%B`) and diffed against the intended text — substitution damage is invisible at the call site and the exit status is 0 either way.
- **Incident —** 2026-08-18 (0041 S11): a land-stage commit message was handed to a shell inline and its backticked spans were command-substituted **out of the record** before git saw them — exit 0, found only by reading it back. A second message from the same slice landed carrying literal HTML entities from a different lossy hop. Neither is recoverable without a history rewrite, and no gate anywhere reads a commit message.
