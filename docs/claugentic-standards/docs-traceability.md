# Docs & Traceability — the change is explainable, the architecture is navigable

> **Loads when:** changes add, move, or remove files (ARCHITECTURE_TREE.md); introduce non-trivial decisions (DECISIONS.md); modify public APIs or non-obvious logic (docstrings/comments); or touch onboarding/runbook documentation.
> **ISO/IEC 25010:** maintainability · **Status:** draft
> Method, tags, honesty register: `README.md` → *Reading a module*.

---

## Architecture-tree index currency

- **Auditor checks —** If the architecture-tree gate is wired, run it (`python` / `python3` / `py` — `scripts/claugentic-check_architecture_tree.py`) and confirm exit 0 `[D]`; otherwise verify the tree by eye `[J]`. Either way, confirm any new file added in this change has a description entry `[J]`. `[J]` Does the entry — or any ledger line this change touches — RESTATE a value the file itself owns (a cap, a version, an enum list, a threshold)? An index entry is a **LOCATOR**; a restated value is an ungated second source of truth, and the honest measure is *how many places one change to that value must touch.* **The one exception, stated not silent:** a count that is genuine reader-value in *pitch* copy ("9 specialist agents") may stay — but it is kept **deliberately, with the drift risk accepted on the record**, never left standing by default; in an INDEX or a ledger it is always replaced by a locator.
- **Incident —** 0041 S4 (2026-08-13): a user-approved cap bump on one ledger had to be applied in **five** places — the config owning the value, a byte-exact test pin, the tree entry, a ledger line restating the number, and the dated record of *why* — while the same slice's copy called a bump “the same one-line edit.” Nothing compared the restatements to the source. Trimming the tree entry to a locator and replacing the ledger's numbers with a pointer took it to three, the third being a deliberate drift-detection pin that stays.

## Decision traceability (DECISIONS.md)

- **Auditor checks —** Review the diff for non-trivial decisions not yet recorded `[J]`; confirm `docs/claugentic-DECISIONS.md` entry is dated and includes the rationale, not just the choice `[J]`.

## Load-bearing invariant traceability (INVARIANTS.md)

- **Good looks like —** A constraint that *must stay true or something breaks*, whose rationale is non-obvious from the code, is a standing entry in `docs/claugentic-INVARIANTS.md`: the **invariant**, the **why** (rationale / blast radius), and **dated provenance**. The file is **lazily created** — a repo with no load-bearing invariant correctly has none. Distinct from `DECISIONS.md` (historical “what we chose and why”): an invariant is **live**, read every time code in its blast radius changes.
- **Honesty register —** This ledger is **user-owned documentation, not a gate**. Nothing mechanically verifies the invariants hold, and that is deliberate: a stale or missing entry is a documentation gap, not a build failure — wiring a check here would over-engineer a doc into machinery. *(Do-not-re-propose.)*
- **Auditor checks —** `[J]` Did this change establish a non-obvious constraint that future code could silently violate (an ordering dependency, a "these two values must move together," an assumption a caller relies on) — and if so, is it captured in `docs/claugentic-INVARIANTS.md` with its why + dated provenance? `[J]` Did this change *touch the blast radius of an existing recorded invariant* — and if so, does it still hold (and is the entry still accurate)? `[J]` Is each entry genuinely load-bearing (a real "or it breaks"), not a restatement of a style preference or a decision that belongs in `docs/claugentic-DECISIONS.md`? `[J]` **Is the constraint already held where it BITES?** A red-first pin plus a do-not-revert comment at the call site records a constraint inside the path a future change must edit; this ledger is for the ones **no pin can hold** — a cross-file ordering, a "these two must move together", a rationale with no code to attach to. Prefer the pin, and say in the slice that you did. **This is an admission test on the CONSTRAINT, never on the ledger's free bytes:** a genuinely un-pinnable invariant is filed even when the file sits at its band, and the recourse is then the condensation / escape-valve ladder, never a skipped entry.
- **Incident —** Load-bearing constraints (e.g. the two version manifests that must move together) were caught only by eye or in production, because the “or it breaks” rationale lived in nobody's head but the original author's; multiple adopter projects independently started a constraints log for exactly this. *(0041 S10b, 2026-08-17: the D6 trust-surface constraint was discharged as behavioural pins plus a call-site comment and the ledger stayed untouched — the rule that produced that call had been living only in the plan file, which is deleted at plan close.)*

## Docstrings and inline comments

- **Auditor checks —** Confirm public functions/classes have docstrings `[D]` (enforced by lint where available); flag complex or counterintuitive logic that has no explanatory comment `[J]`; flag comments that merely restate the code `[J]`.

## Forward promises in prose — future tense, a named owner, and a falsifier

- **Good looks like —** Any sentence describing a capability a **later change** will wire — docstring, comment, skill/README copy, index entry, ledger line, approval summary — rides the **future tense**, **names the change that makes it true**, and is backed by a **mechanical falsifier** (`testing.md` → *Forward promises need a tripwire* owns that half). The tense protects today's reader, the tripwire protects tomorrow's author. An **abandoned** promise is rewritten, never left standing. **The mirror image, and it fails the same way: a pointer to a ROUTING is a claim the routing EXISTS.** *“routed (backlog item N)”* · *“tracked as X”* · *“deferred to Y”* asserts a **present** fact about another file — so the referent is written **before or in the same commit**, never after. A citation that outlives its unwritten referent is a permanent dangling pointer no gate reads.
- **Auditor checks —** `[D]` Grep the diff's *prose* (docstrings, comments, `.md` copy, index entries, plan/approval text) for present-tense capability verbs — *is wired · consults · fires · surfaces · is visible at every …* — and for each ask: is it true **at the moment this change lands**, in a fresh clone? `[J]` If not, is it future-tense **and** does it name the change that wires it? `[D]` Does a falsifier exist for it? `[J]` **One correctly-hedged site is a signal, not a clean bill** — when a change hedges one forward reference, sweep every sibling that says the same thing. `[D]` For every *routed / tracked / deferred-to* citation the diff ADDS, open the named target and find the entry: pointer and referent land together, or neither lands. `[D]` **When the diff EDITS a ledger, re-read the neighbours of the line it touched** — a status/remaining-work line in the same file is exactly what a land falsifies, and you already have the file open, so the sweep is free. `[D]` **A hand-maintained field that feeds an AUTOMATIC surface needs a falsifier.** When a human-typed value is republished by a mechanism — a header line a hook reads, a status a dashboard prints — the mechanism gives it a reach the author never re-reads, so the staleness is *published*, not merely stored: name the field, name the surface it feeds, and either DERIVE the value from the authoritative state or pin it. *(The harness's own live case, stated plainly because it is unfixed: a plan's `Resumable from:` header is republished by `scripts/claugentic-session-advisor.py` into the SessionStart `additionalContext` an agent reads first. The docstring already calls it derived-for-convenience and the unchecked boxes authoritative — but **no gate enforces this today**, and at 0041's closing commit that line still named Slice 10a while the plan stood at Slice 12b, four slices stale.)*
- **Incident —** 0041, three consecutive slices (S3 · S4 · S5, 2026-08-13/14): each slice's brand-new copy described, in the present tense, a mechanism a **later slice of the same plan** would wire — a compensating control that did not exist; four sibling registrations beside one correctly-hedged one; a gate docstring and approval summary claiming a warning “is visible at every commit” when nothing had yet chained that gate. The review side caught it all three times — which is exactly the evidence that the missing rule was an **authoring** rule, so it is filed in a module the implementer self-applies before handing off. *(S10b: three fixes shipped “routed (ROADMAP, 0041 S10b)” into engine comments and a permanent ledger while that entry was still unwritten — written at Land, so the pointers resolve; had the obligation been dropped, four permanent sentences would cite nothing.)*

## Reach, not residence — where a capability LIVES is not where it is USABLE

- **Good looks like —** Every instruction to run, import or invoke something is scoped to where that thing is **in the reader's world**, not where it lives in yours. **Distribution membership and repo-local presence are two facts** — in the package/image/payload/monorepo vs on disk in the reading project — and both are stated wherever the difference is actionable. (Tense is *Forward promises* above; the axis **here** is location, so a sentence can be present-tense-true about the payload and false for every reader.) **Corollary — never invite a reader to substitute the tool's own copy.** A tool that resolves its subject from its own install location (`__file__`, `argv[0]`, the image workdir) measures **its** tree, not theirs; the honest output is “not present here”, the honest design takes the subject as an explicit argument, and the honest verdict **names the subject it measured**. **And the mirror direction, which SHRINKS work: where a defect LIVES is not who it REACHES.** Before spec'ing a fix, classify **every path the harm touches** against the distribution boundary — what the payload carries, what the reading project receives, what a generator re-creates there. A harm confined to stripped-or-regenerated paths has no audience outside the source repo, and the fix shrinks with it. Derive the blast radius **first**: a spec written from the *assumed* audience buys deliverables nobody receives, with the plan's approval already on it.
- **Auditor checks —** `[D]` For every run/import instruction in reader-facing or shipped text, resolve the path **from a fresh clone of the reader's project** — does it exist there? `[J]` Are payload membership and repo-local presence stated as two facts wherever a reader could act on the difference? `[J]` Does any copy suggest pointing the tool's own copy at another tree? `[J]` Is a stated failure **symptom** the one the reader's deployment shape produces (installed vs dev checkout vs CI), or only the one measured in the author's checkout? `[D]` A correction applied "at all N sites" is a **class, not a count** — re-derive the site list by grep after the fix and quote it. **And CLOSE the sweep on the RETIRED STRING, not on your site list** — a forward grep only reaches what its pattern reaches, so name the exact phrase the change retires and assert it returns **zero** across `git ls-files`. **Enumerate frontmatter in that corpus:** a skill's or agent's `description:` is a **capability surface, not prose** — it is the string a model reads to decide whether to load the tool at all, and it ships in the release payload, so a sweep that treats frontmatter as metadata misses it. *(0041 S12a: six pointer sites were re-derived by grep and quoted in the report; the seventh — `skills/condense/SKILL.md:3`, a shipped `description:` still attributing a relocated procedure to the file it had just left — was found only by the reviewer's zero-result grep on the retired phrase. That same frontmatter had already been a defect surface once, differently: it shipped unparseable across v0.4.0/v0.4.1/v0.5.0 and loaded with EMPTY metadata, silently.)* **Wrapped lines hide members from a line-scoped grep — normalize before matching** (join the wrap markers: blockquote `> ` and list continuations, e.g. `` `\s*\n\s*(?:>\s*|[-*]\s+)?` `` → one space) and adjudicate the hits by hand. That normalization is a **SWEEP you read, never a gate**: as a standing mechanical predicate over prose, the paragraph-scoped window it needs fires on honest copy — measure the false-positive rate before proposing one, and record the refutation so it is not re-proposed. `[J]` Resolve every **deictic** in shipped instruction text — both the *person* kind (*this repo*, *here*, *your*, *ours*, *the current*) and the *spatial* kind (*above*, *below*, *the next section*, *just before this*) — in the **reader's** frame — an agent executing the file binds it to the reader's project, not yours. Name the subject explicitly ("the harness's own load profile — not measurements of your repo") wherever the two differ. **A block that MOVES carries its spatial deictics with it, and they are not verbatim-safe:** a relocation instruction that says both *"move it verbatim"* and *"place it after X"* is jointly unsatisfiable the moment the block points at X, so the spec states which wins and what the internal words become. *(0041 S9: an adopter note reading "a few references below resolve to the installed plugin" was moved above the very two lines it was written to correct — the diff was byte-faithful and the sentence became false; resolved by authorizing one word, "below" → "in this doc".)*
- **Incident —** 0041 S6 (2026-08-14/15). A gate script was reclassified to ship in the release payload, and **eight** shipped sentences then told adopters to run it. Measured in a scratch adopter project: the shipped command exited **2, `can't open file`** (nothing copies the script into a project yet — a later change), and the plugin's own copy, run from that project, returned a verdict **about the plugin's own tree**. The slice faithfully implemented a spec line that was itself wrong, so a spec-conformant diff was no defense. One day later the corollary bit: the shipped symptom was only reproducible **in a dev checkout**, and the sweep that fixed “all four sites” left two standing. *(S11: the same axis reversed — a leak framed as adopter-facing touched only paths the build strips or regenerates, which removed a shipped-content pass, a copy change and a changelog entry from the slice before a line was written.)*

## Quantities in prose — the method, the boundary, and the arithmetic that closes

- **Good looks like —** Every measured number reaching a durable surface — CHANGELOG, ledger entry, acceptance criterion, review verdict, commit message — is **reproducible**: it names the **method** (the command, or the sum) and the **boundary** (base vs head vs the merge tree; which region; bytes vs characters). Measured **once and propagated**, never re-typed from memory at the next surface. A printed **decomposition evaluates** — the parts sum to the whole, signs included. And a **quantitative acceptance criterion is feasible under the same document's own constraints**: before the target is set, compute the ceiling its own *this stays* / *do not touch* clauses leave.
- **Auditor checks —** `[D]` For every numeral the diff ADDS to a durable surface, re-run the stated method and compare; **a precise-looking figure with no stated method is itself the finding** — you cannot adjudicate it, and neither can the next reader. `[D]` Evaluate any printed decomposition (`A = B − C + D`) — check the **signs**, not only the terms. `[J]` Does each figure name its boundary? **Two different figures for "the same" quantity are not automatically a contradiction** — base and head are different boundaries — and a figure with no boundary cannot be adjudicated in either direction. `[D]` For each quantitative AC, compute the maximum reachable under every constraint the same spec states; if the target exceeds it, **the spec is the defect** (`docs/claugentic-WORKFLOW.md` → Stage 7, the spec-amendment path) — the diff delivers the ceiling, says so plainly, and no shipped surface claims the criterion was met. `[D]` **An ABSENCE is a measurement only if the search could have FOUND the thing.** Before publishing a negative grep — *"the phrase does not appear", "zero hits", "no site restates it"* — prove the pattern against a **known-positive control**, and confirm nothing in the pipeline truncated its input (`cut`/`head -c`, a line-scoped matcher run over wrapped prose, a pattern that cannot cross the markdown emphasis the corpus actually uses). A zero-hit result from an unvalidated pattern is a claim about your command, not about the corpus — and it is the one wrong answer that reads as diligence. Sibling to *wrapped lines hide members from a line-scoped grep* under *Reach, not residence* above: the same failure, one on membership and one on magnitude. `[J]` **Default to a LOCATOR over a count.** The locator rule under *Architecture-tree index currency* above is **not scoped to index entries** — it binds any durable prose restating a value another artifact owns: a verdict's "N sites", a plan's blast-radius figure, a ledger's roster count, a test-pin enumeration. Where the number is derivable, write the **derivation** (the grep, or the file that IS the list) instead; a count survives only as that rule's stated exception — deliberately, on the record.
- **Incident —** 0041 S12a (2026-08-18). A relocation published **“6,037 bytes”** to `CHANGELOG.md` and to a **permanent** decisions shard. No boundary of the change produces it — the measured net was **5,785**, and **the commit message already said so**, so the honest number existed and simply failed to propagate. Same review: a decomposition printed `6,556 − 792 − 21` where that term had *shrunk* (correct: `+ 21`), and two figures for one region — 4,108 and 4,087 — were called contradictory when they were base and head. And the SPEC's own arithmetic subtracted a 4,108 B region the same spec ordered to **stay**, making its `>=10,000 B` criterion unreachable by **3,444 B** — the second consecutive slice whose **quantitative criterion**, not whose diff, was the defect. *(S12b, the same axis on vocabulary: a spec note asserted a phrase was **absent** from a file where it sits verbatim, and that assertion overturned a correct grounding pass — **two independently sufficient mechanical causes, neither an adjective:** the pattern could not cross the markdown bold the file actually uses, and it ran against a line already truncated by `cut -c1-300`. The class fired **five** times in that one slice, immediately after the slice that harvested the rule; four were fixed by deleting the number and writing the locator. The rule existed and was not enough — what it lacked was a **default**.)*

## Change explainability (commit and PR narrative)

- **Good looks like —** Conventional Commits, and the message explains **why**. **And the message that LANDS is the one the shell delivered, not the one you typed** — a commit narrative is prose full of backticks, `$`, `!` and quotes, every one a metacharacter: inside double quotes a backticked span is *command-substituted away* and its output pasted in its place, silently, with the commit still exiting 0. A mangled message is permanent and un-gated — a commit message is outside every file-corpus scan by construction (`testing.md` → *A scan's CORPUS is part of its contract*).
- **Auditor checks —** Confirm commit messages are conventional and explain motivation `[J]`; verify PR description covers what changed, why, and how to test it `[J]`. `[D]` Was the message delivered from a **file**, or as an inline `-m` string containing a backtick, `$(`, `$` or `!`? `[D]` Read the landed message back (`git log -1 --format=%B`) and diff it against the intended text — substitution damage is invisible at the call site and the exit status is 0 either way.
- **Incident —** 2026-08-18 (0041 S11): a land-stage commit message was handed to a shell inline; its backticked spans were command-substituted **out of the record** before git saw them — exit 0, found only by reading the message back. A second message from the same slice landed carrying literal HTML entities from a different lossy hop, and is still in history. Neither is recoverable without a history rewrite, and no gate anywhere reads a commit message.
