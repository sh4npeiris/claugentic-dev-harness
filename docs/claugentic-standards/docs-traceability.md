# Docs & Traceability — the change is explainable, the architecture is navigable

> **Loads when:** changes add, move, or remove files (ARCHITECTURE_TREE.md); introduce non-trivial decisions (DECISIONS.md); modify public APIs or non-obvious logic (docstrings/comments); or touch onboarding/runbook documentation.
> Method, tags, honesty register: `README.md` → *Reading a module*.

---

## Architecture-tree index currency

- **Auditor checks —** If the tree gate is wired, run it (`python` / `python3` / `py` — `scripts/claugentic-check_architecture_tree.py`), exit 0 `[D]`; otherwise verify by eye `[J]`. Either way, every file this change adds has a description entry `[J]`. `[J]` Does the entry — or any ledger line this change touches — RESTATE a value the file itself owns (a cap, a version, an enum list, a threshold)? An index entry is a **LOCATOR**; a restated value is an ungated second source of truth, and the honest measure is *how many places one change to that value must touch.* **The one exception, stated not silent:** a count that is genuine reader-value in *pitch* copy ("9 specialist agents") may stay — **deliberately, with the drift risk on the record**; in an INDEX or a ledger it is always a locator.
- **Incident —** 0041 S4 (2026-08-13): a user-approved cap bump had to be applied in **five** places — the config owning the value, a byte-exact test pin, the tree entry, a ledger line restating the number, and the dated record of *why* — while the slice's own copy called it "the same one-line edit", and nothing compared the restatements to the source. Locator-ising the tree entry and the ledger took it to three, the third a deliberate drift-detection pin that stays.

## Decision traceability (DECISIONS.md)

- **Auditor checks —** Non-trivial decisions in the diff not yet recorded `[J]`; the `docs/claugentic-DECISIONS.md` entry is dated and carries the rationale, not just the choice `[J]`.

## Load-bearing invariant traceability (INVARIANTS.md)

- **Good looks like —** A constraint that *must stay true or something breaks*, whose rationale is non-obvious from the code, is a standing entry in `docs/claugentic-INVARIANTS.md`: the **invariant**, the **why** (rationale / blast radius), and **dated provenance**. The file is **lazily created**. Distinct from `DECISIONS.md` (historical "what we chose and why"): an invariant is **live**, read every time code in its blast radius changes.
- **Honesty register —** This ledger is **user-owned documentation, not a gate**. Nothing mechanically verifies the invariants hold, deliberately: a stale or missing entry is a documentation gap, not a build failure. *(Do-not-re-propose.)*
- **Auditor checks —** `[J]` Did this change establish a non-obvious constraint future code could silently violate (an ordering dependency, a "these two values must move together", an assumption a caller relies on) — captured with its why + dated provenance? `[J]` Did it *touch the blast radius of a recorded invariant* — does that still hold, and is the entry still accurate? `[J]` Is each entry genuinely load-bearing (a real "or it breaks"), not a style preference or a decision belonging in `docs/claugentic-DECISIONS.md`? `[J]` **Is the constraint already held where it BITES?** A red-first pin plus a do-not-revert comment at the call site records a constraint inside the path a future change must edit; this ledger is for the ones **no pin can hold** — a cross-file ordering, a "these two must move together", a rationale with no code to attach to. Prefer the pin, and say in the slice that you did. **This is an admission test on the CONSTRAINT, never on the ledger's free bytes:** a genuinely un-pinnable invariant is filed even when the file sits at its band, and the recourse is the condensation / escape-valve ladder, never a skipped entry.
- **Incident —** Load-bearing constraints (e.g. the two version manifests that must move together) were caught only by eye or in production, because the "or it breaks" rationale lived nowhere but the author's head; multiple adopter projects independently started a constraints log for exactly this. *(0041 S10b, 2026-08-17: the D6 trust-surface constraint was discharged as behavioural pins plus a call-site comment, ledger untouched — the rule behind that call was living only in the plan file, which is deleted at plan close.)*

## Docstrings and inline comments

- **Auditor checks —** Public functions/classes carry docstrings `[D]` (lint-enforced where available); complex or counterintuitive logic with no explanatory comment `[J]`; comments that merely restate the code `[J]`.

## Forward promises in prose — future tense, a named owner, and a falsifier

- **Good looks like —** Any sentence describing a capability a **later change** will wire — docstring, comment, skill/README copy, index entry, ledger line, approval summary — rides the **future tense**, **names the change that makes it true**, and is backed by a **mechanical falsifier** (`testing.md` → *Forward promises need a tripwire* owns that half). An **abandoned** promise is rewritten, never left standing. **The mirror image fails the same way: a pointer to a ROUTING is a claim the routing EXISTS.** *"routed (backlog item N)"* · *"tracked as X"* · *"deferred to Y"* asserts a **present** fact about another file — the referent is written **before or in the same commit**, never after.
- **Auditor checks —** `[D]` Grep the diff's *prose* (docstrings, comments, `.md` copy, index entries, plan/approval text) for present-tense capability verbs — *is wired · consults · fires · surfaces · is visible at every …* — and ask of each: true **at the moment this change lands**, in a fresh clone? `[J]` If not, is it future-tense **and** does it name the change that wires it? `[D]` Does a falsifier exist for it? `[J]` **One correctly-hedged site is a signal, not a clean bill** — sweep every sibling that says the same thing. `[D]` For every *routed / tracked / deferred-to* citation the diff ADDS, open the target and find the entry: pointer and referent land together, or neither lands. `[D]` **When the diff EDITS a ledger, re-read the neighbours of the line it touched** — a status/remaining-work line in the same file is exactly what a land falsifies, and the file is already open. `[D]` **A hand-maintained field feeding an AUTOMATIC surface needs a falsifier.** When a human-typed value is republished by a mechanism — a header line a hook reads, a status a dashboard prints — the staleness is *published*, not merely stored: name the field, name the surface it feeds, and either DERIVE it from the authoritative state or pin it. *(Live and unfixed here: a plan's `Resumable from:` header is republished by `scripts/claugentic-session-advisor.py` into the SessionStart `additionalContext` an agent reads first — **no gate enforces it**, and at 0041's closing commit that line named Slice 10a while the plan stood at Slice 12b.)*
- **Incident —** 0041, three consecutive slices (S3 · S4 · S5, 2026-08-13/14): each shipped brand-new copy describing, in the present tense, a mechanism a **later slice of the same plan** would wire — a compensating control that did not exist, four sibling registrations beside one correctly-hedged one, and a gate docstring claiming a warning "is visible at every commit" before anything chained that gate. Review caught all three, which is the evidence that the missing rule was an **authoring** rule. *(S10b: three fixes shipped "routed (ROADMAP, 0041 S10b)" into engine comments and a permanent ledger while that entry was unwritten — written at Land, so the pointers resolve.)*

## Reach, not residence — where a capability LIVES is not where it is USABLE

- **Good looks like —** Every instruction to run, import or invoke something is scoped to where that thing is **in the reader's world**, not where it lives in yours. **Distribution membership and repo-local presence are two facts** — in the package/image/payload/monorepo vs on disk in the reading project — both stated wherever the difference is actionable. (Tense is *Forward promises* above; the axis **here** is location, so a sentence can be present-tense-true about the payload and false for every reader.) **Corollary — never invite a reader to substitute the tool's own copy.** A tool resolving its subject from its own install location (`__file__`, `argv[0]`, the image workdir) measures **its** tree, not theirs; the honest design takes the subject as an explicit argument and the verdict **names the subject it measured**. **The mirror direction SHRINKS work: where a defect LIVES is not who it REACHES.** Before spec'ing a fix, classify **every path the harm touches** against the distribution boundary — what the payload carries, what the reading project receives, what a generator re-creates there. A harm confined to stripped-or-regenerated paths has no audience outside the source repo, and the fix shrinks with it.
- **Auditor checks —** `[D]` Resolve every run/import instruction in reader-facing or shipped text **from a fresh clone of the reader's project** — does the path exist there? `[J]` Payload membership and repo-local presence stated as two facts wherever a reader could act on the difference? `[J]` Does any copy suggest pointing the tool's own copy at another tree? `[J]` Is a stated failure **symptom** the one the reader's deployment shape produces (installed vs dev checkout vs CI), or only the author's? `[D]` A correction applied "at all N sites" is a **class, not a count** — re-derive the site list by grep after the fix and quote it. **CLOSE the sweep on the RETIRED STRING, not on your site list**: name the exact phrase the change retires and assert **zero** across `git ls-files`. **Enumerate frontmatter in that corpus** — a skill's or agent's `description:` is a **capability surface, not prose**: the string a model reads to decide whether to load the tool at all, and it ships. **Wrapped lines hide members from a line-scoped grep — normalize before matching** (join blockquote `> ` and list continuations, e.g. `` `\s*\n\s*(?:>\s*|[-*]\s+)?` `` → one space) and adjudicate by hand. That normalization is a **SWEEP you read, never a gate**: as a standing predicate over prose its paragraph-scoped window fires on honest copy — measure the false-positive rate before proposing one, and record the refutation. `[J]` Resolve every **deictic** in shipped instruction text — *person* (*this repo*, *here*, *your*, *the current*) and *spatial* (*above*, *below*, *the next section*) — in the **reader's** frame; an agent executing the file binds it to the reader's project. **A block that MOVES carries its spatial deictics with it, and they are not verbatim-safe:** an instruction saying both *"move it verbatim"* and *"place it after X"* is jointly unsatisfiable once the block points at X, so the spec states which wins and what the internal words become.
- **Incident —** 0041 S6 (2026-08-14/15): a gate script was reclassified to ship, and **eight** shipped sentences then told adopters to run it. Measured in a scratch adopter project the command exited **2, `can't open file`**, and the plugin's own copy returned a verdict **about the plugin's own tree**; the slice had implemented a spec line that was itself wrong, so a spec-conformant diff was no defense. *(S12a: six pointer sites were re-derived by grep; the seventh — `skills/condense/SKILL.md:3`, a shipped `description:` still crediting a relocated procedure, in a frontmatter that had already shipped unparseable across v0.4.0/v0.4.1/v0.5.0 — surfaced only from a zero-result grep on the retired phrase. S9: an adopter note reading "a few references below resolve to the installed plugin" was moved above the two lines it corrected — byte-faithful, and false. S11, reversed: a leak framed as adopter-facing touched only stripped-or-regenerated paths, which deleted three deliverables from the slice before a line was written.)*

## Quantities in prose — the method, the boundary, and the arithmetic that closes

- **Good looks like —** Every measured number reaching a durable surface — CHANGELOG, ledger entry, acceptance criterion, review verdict, commit message — is **reproducible**: it names the **method** (the command, or the sum) and the **boundary** (base vs head vs the merge tree; which region; bytes vs characters). Measured **once and propagated**, never re-typed from memory at the next surface. A printed **decomposition evaluates** — the parts sum to the whole, signs included. And a **quantitative acceptance criterion is feasible under the same document's own constraints**: before the target is set, compute the ceiling its own *this stays* / *do not touch* clauses leave.
- **Auditor checks —** `[D]` For every numeral the diff ADDS to a durable surface, re-run the stated method and compare; **a precise-looking figure with no stated method is itself the finding** — neither you nor the next reader can adjudicate it. `[D]` Evaluate any printed decomposition (`A = B − C + D`) — check the **signs**, not only the terms. `[J]` Does each figure name its boundary? **Two figures for "the same" quantity are not automatically a contradiction** — base and head are different boundaries. `[D]` For each quantitative AC, compute the maximum reachable under every constraint the same spec states; if the target exceeds it, **the spec is the defect** (`docs/claugentic-WORKFLOW.md` → Stage 7, the spec-amendment path) — the diff delivers the ceiling, says so plainly, and no shipped surface claims the criterion was met. `[D]` **An ABSENCE is a measurement only if the search could have FOUND the thing.** Before publishing a negative grep — *"the phrase does not appear", "zero hits"* — prove the pattern against a **known-positive control** and confirm nothing truncated its input (`cut`/`head -c`, a line-scoped matcher over wrapped prose, a pattern that cannot cross the markdown emphasis the corpus uses). A zero from an unvalidated pattern is a claim about your command, not the corpus — the one wrong answer that reads as diligence. Sibling to *wrapped lines hide members from a line-scoped grep* under *Reach, not residence* above: one failure on membership, one on magnitude. `[J]` **Default to a LOCATOR over a count.** The locator rule under *Architecture-tree index currency* above is **not scoped to index entries** — it binds any durable prose restating a value another artifact owns (a verdict's "N sites", a plan's blast-radius figure, a ledger's roster count). Where the number is derivable, write the **derivation**; a count survives only as that rule's stated exception.
- **Incident —** 0041 S12a (2026-08-18): a relocation published **"6,037 bytes"** to `CHANGELOG.md` and to a **permanent** decisions shard, though no boundary of the change produces it — the measured net was **5,785**, and **the commit message already said so**. Same review: a decomposition printed `6,556 − 792 − 21` for a term that had *shrunk* (correct: `+ 21`), and 4,108 vs 4,087 for one region were called contradictory when they were base and head. And the SPEC subtracted a 4,108 B region it also ordered to **stay**, making its `>=10,000 B` criterion unreachable by **3,444 B** — the second consecutive slice whose criterion, not whose diff, was the defect. *(S12b: a spec note asserted a phrase **absent** from a file where it sits verbatim, from **two independently sufficient mechanical causes** — a pattern that could not cross the file's markdown bold, run against a line already truncated by `cut -c1-300`. The class fired **five** times in that slice, right after the slice that harvested the rule; four were fixed by deleting the number and writing the locator. What the rule lacked was a **default**.)*

## Change explainability (commit and PR narrative)

- **Good looks like —** Conventional Commits, and the message explains **why**. **And the message that LANDS is the one the shell delivered, not the one you typed** — a commit narrative is prose full of backticks, `$`, `!` and quotes, every one a metacharacter: inside double quotes a backticked span is *command-substituted away* and its output pasted in its place, silently, with the commit still exiting 0. A mangled message is permanent and un-gated — a commit message is outside every file-corpus scan by construction (`testing.md` → *A scan's CORPUS is part of its contract*).
- **Auditor checks —** Commit messages conventional and explaining motivation `[J]`; PR description covers what changed, why, and how to test it `[J]`. `[D]` Was the message delivered from a **file**, or as an inline `-m` string containing a backtick, `$(`, `$` or `!`? `[D]` Read the landed message back (`git log -1 --format=%B`) and diff it against the intended text — substitution damage is invisible at the call site and the exit status is 0 either way.
- **Incident —** 2026-08-18 (0041 S11): a land-stage commit message was handed to a shell inline and its backticked spans were command-substituted **out of the record** before git saw them — exit 0, found only by reading the message back. A second message from the same slice landed carrying literal HTML entities from a different lossy hop. Neither is recoverable without a history rewrite, and no gate anywhere reads a commit message.
