**First real-adopter feedback batch (2026-08-19, v0.5.3 in an external repo; every item verified by live repro against the SHIPPED bytes — apply as ONE commit, several span parity-pinned file pairs):**

- **The wrapper never tries the `py` launcher** — `for cand in python3 python` skips both gates (loudly, one stderr line — the "silent" half of the report was refuted) on a Windows box where only `py` is on PATH; **reproduced on the shipped bytes: both planted always-fail gates never ran, commit landed.** Fix: `py` as LAST candidate + notice text, in `.githooks/pre-commit` **and** its verbatim template in `skills/init/SKILL.md` (parity-pinned — same commit) + doctor's restated order + a py-only fixture pinning the gate RUNS. Also fix init's self-contradiction: `:89` says step-1's detected interpreter is "written into the hook"; `:601` (and the template) prove it is not.
- **init never stages what it delivers** — no `git add`, no instruction, so `git add -u`/`commit -a` commits the rewired wrapper WITHOUT the new gate script/config (reproduced: `M .githooks/pre-commit` staged, `??` on both new files). Teammates then get a loud per-commit SKIPPED notice, not a silent gate (that half refuted). Fix: step 9 report prints the exact `git add <paths>` from the groups it already enumerates + one clause warning that `-u`/`-a` misses untracked files. **Shared mode only** — solo's invariant is zero new tracked paths.
- **The wrapper-write path can emit CRLF on Windows** — shipped blobs are LF, but init has the model WRITE the wrapper from a template with no LF guard; reproduced: `write_text` → CRLF=62, and real dash (`/bin/sh` on Ubuntu) rejects it (`Syntax error: word unexpected`) while Git-for-Windows sh tolerates it — so the writer's machine works and the breakage lands on POSIX teammates. init's shared-mode `.githooks/** text eol=lf` gitattributes seed is the existing (prose-only, unverified) guard; solo mode has none and `.git/hooks/` is never git-normalized. Fix: write-with-LF instruction + post-write `

- **"An absent charter ≡ current behavior" is false on an inited repo** — the seeded literal-path cap makes deleting `docs/claugentic-CHARTER.md` an exit-1 (correct fail-loud; the error already names the one-line remedy verbatim). Fix is one sentence in the `_CHARTER.md` seed ("deleting it? also delete its caps line") + the same clause where WORKFLOW says absent ≡ default.
- **WARN noise, works-as-designed but polishable** — 4 breach WARNs × ~230 chars per commit; ~600 of 935 stderr bytes are the identical remediation clause repeated per line. Optional: factor it to ONE trailing line (stateless, no information loss). Reject WARN-once-per-N (needs state; silences a standing breach).
