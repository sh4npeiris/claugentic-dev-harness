## Standing tracks & later — human-owned (yours · never auto-touched by any fence)

This section is **hand-written and never regenerated** by any harness skill — the two backlog fences above are generated views, this is the durable record. Tangents land here, never silently into the current change.

### The two standing tracks — growing the libraries (ongoing · just-in-time)

The harness grows as it meets more codebases. Neither track is ever "done" — that's the right shape: additions are made when real use proves a gap, never speculatively.

| Track | How it grows |
|------|--------------|
| **Grow the role library** (`.claude/agents/`) — add specialist agents as real use surfaces gaps the starter set lacks. | The workflow delegates to specialists; when real work keeps hitting a job no existing role owns, that's the signal to add one (and register it in `plugin.json`, the WORKFLOW roster, and the architecture tree). |
| **Grow the standards catalog** (`docs/claugentic-standards/`) — author new quality modules and capability modules (Redis, queues, object-storage, …) as real projects pull them in. | A real audit or review that needs a bar the catalog doesn't carry is the signal to author it (conforming to `_TEMPLATE.md`, indexed in the catalog README). The catalog modernizes vibe-coded apps, not just cleans code. |

### Later — surfaced by real use

- **Agnostic `init` — *deferred sub-item only* (plan 0017 shipped v0.1.38).** The slices landed: scenario-based conditional hook wiring, a cheap-complete tree skeleton, the self-asserting CLAUDE.md authority clause, and non-destructive conflict/harvest prompts — unblocking the suite rollout. *Still deferred:* brace-glob / curated-tree gate tolerance — only needed if a repo ever wants the gate **on** over a brace-glob tree (gate-off covers "keep your own tree" today).
- **Doc-vs-behavior drift gate (candidate, surfaced by plan 0017 review).** A managed doc whose claim depends on behavior in another file (e.g. `docs/claugentic-WORKFLOW.md:113`'s "wired only when the tree-gate is enabled" ↔ `init`'s actual wiring) can silently over-claim — the same class as the retired phantom `SKILL.md:323` reference. No current gate catches it. Consider a standing check, alongside the skills-prose-namespace gate below.
- **Cross-surface "agents are namespaced" gate (plan 0016 follow-up).** `tests/workflows/agent-namespace.test.mjs` now pins that every `engine/*.js` spawn uses `nsAgent("…")`, and `cross-script.test.mjs` pins the helper byte-identical. The **skills-prose half is still unguarded**: a contributor could add a bare `spawn \`lens-reviewer\`` directive to a `skills/*/SKILL.md` and nothing deterministic would catch it (relies on orchestrator runtime resolution). Add a standing check that every imperative spawn directive in the skill prose carries the `claugentic-dev-harness:` prefix. *Minor related limit:* the engine guard's `CUSTOM_AGENTS` allowlist must be updated when a new bundled agent is added — fold that into the same gate so the allowlist can't silently fall out of sync.
