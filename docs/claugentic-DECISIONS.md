# Decisions

A **forward-looking maintainer's guide**: the standing decisions a future agent MUST know to safely improve the harness without re-breaking it or re-litigating settled choices. **Consult before revisiting a past choice** (see CLAUDE.md → Harness Discipline). This is **NOT an append-only history** — it is condensed periodically (the condensation pass, canonical in `docs/claugentic-WORKFLOW.md` → Definition of Done): superseded/settled entries merge into git history, hardened must-holds promote to `docs/claugentic-INVARIANTS.md`; keep an entry only if a future agent needs it to decide correctly. When in doubt, keep a constraint. For genuinely new decisions, append a dated one-liner at the top of the relevant section.

## Honesty positioning (the #1 rule)

- **Never let copy launder model judgment into apparent mechanical fact.** This is the core rule everything else serves. The honest enforcement split: the **architecture-tree check is the only hook-enforced gate**; `check_versions_synced.py` + the test suite + the doc-budget gate are **deterministic run-gates** (mechanical when run; running them is discipline); everything else — reviewer sign-offs, the diverse panel, the audit's finding re-checks, build mode's pauses — is **model-upheld** and must say so.
- **Verb discipline:** the harness *"attempts to / tries to re-check"* and *"tags the outcome"* — never *"verifies / proven / arrives with proof / guaranteed."* Success claims are **dimension-scoped** (*"sound on the audited dimensions"*), never "bug-free / perfect."
- **Check a claim from the surface that MAKES it, not just the referenced body.** A **capability / feasibility** claim (*"X calls Y", "zero change needed", "reachable from here", "the adopter just runs W"*) is only honest if the **caller** (a prose SKILL · a sandboxed engine script · an adopter's layout · the runtime) can actually reach and perform it; confirming the referenced implementation *exists and behaves* is **not** enough (a function can be sound in its body yet unreachable from the surface the copy says invokes it). **Fix (model-upheld, not a new gate):** `honesty-reviewer.md` requires tracing a feasibility claim to its caller; `lens-reviewer`/`synthesizer-gate` inherit the principle. A single CLEAN on a feasibility/trust claim is weaker than a second adversarial re-check — for a claim that *overturns* or *rests on* a prior reviewer's ground-truth, re-review rather than trust one pass.
- **The two senses of "independent":** claims of model-family independence / de-correlation about the judges are **forbidden** (same vendor → errors stay correlated; the honest claim is *"a different model family — a reduction of shared-blind-spot risk, NOT a guarantee"*). The **structural** sense — clean-context input-contract isolation ("independently re-checks") — is accurate and **preserved**. See INVARIANTS → the scrubbed-file set, which pins this in the files that must never regain the claim.
- **`[D]` vs `[J]`:** a deterministic-labeled check is only *proven* where the adopter has the relevant tool wired; otherwise it is reported as the model's judgment.
- The adopter-facing audit-backlog LEGEND must use the honest structural-independence framing (*"a separate clean-context agent that never saw the finder's reasoning — a reduction of rubber-stamping risk, not a mechanical guarantee"*), never the cross-model de-correlation copy. The three-state disclosure machinery STAYS (it degrades to the same-model floor); only over-claiming copy is forbidden — it goes MORE honest, never re-asserts de-correlation. The same honest copy also lives in the dormant cross-model run-report branch in `engine/audit.js` (test-pinned) — change both together.

## The deterministic gates

- **ruff scopes OUT the eval/ fixtures:** `pyproject.toml` `[tool.ruff] extend-exclude = ["eval"]` keeps ruff off the intentionally-defective material (the seeded-defect exam `eval/fixture-defects/` + measurement fixtures) — a linter would flag the **planted** defects by design (e.g. the bare `except:` that is the REL-1 answer-key entry), and they MUST NOT be "fixed." A per-line `# noqa` is forbidden — it betrays the fixture's no-self-labels contract. `eval/` is already dev-only (stripped) + outside pytest `testpaths`; ruff mirrors that. **`tests/` STAYS linted** (real harness code).
- **`init` solo / local-only mode (plan 0024 S4b):** an `init`-recorded mode trigger (AskUserQuestion, **default Shared** — silence/timeout/unavailable all → Shared) routes four divergences so a user dogfoods on a team repo with **zero new tracked paths, no committed-`.gitignore` edit, no shared git config** (teammate clones byte-identical): (a) managed paths → **`.git/info/exclude`**, never the committed `.gitignore`; (b) the pre-commit hook → **`.git/hooks/pre-commit`** (local), `core.hooksPath` left default — a non-default existing one is reported, not clobbered; (c) **skip the plugin self-reference / teammate prompt**; (d) the CLAUDE anchor → **`CLAUDE.local.md`**. Every solo-written path is fail-loud-guarded by `git check-ignore`. Mode recorded as `- Harness mode:`, read before prompting (a recorded `solo` short-circuits the shared branches — make-invalid-states-unrepresentable). One documented divergence, not an `init-solo` command; Shared mode unchanged.
- **Tree-gate altitude → commit-time, `init`-wired (plan 0024 S4a):** the gate runs from a git `pre-commit` hook (`.githooks/pre-commit` via `core.hooksPath`) `--staged`, NOT the per-action `PostToolUse`/`Stop` Claude Code hooks — once per `git commit`, local, **zero per-tool overhead**; the commit is the only point the tree must be correct + the agent is in-context to fix it. **Consistent with** (NOT mandated by) the official hook-cadence guidance (highest-cadence `PreToolUse`/`PostToolUse` + keep-SessionStart-fast — but no mandate against per-tool hooks). `init` wires it for a shared adopter **only when the gate is ON** (OFF → no hook, no hooksPath); **never-clobbers** a different existing `core.hooksPath` (reports + continues); writes **no** tree hooks into `.claude/settings.json` (only the plugin self-reference). The gate's only non-zero exit is 1. **No adopter CI** (next commit catches a miss).
- **One gate, one invariant (SRP siblings):** the tree-check owns the file index (presence · staleness · zero-coverage glob-drift); `check_versions_synced.py` owns the `plugin.json` ↔ `marketplace.json` version pair (one source of truth — every bump moves both, `plugin.json` authoritative). A new mechanically-checkable invariant gets a **sibling script, not an extension** of an existing one.
- **Fail loud, never fail-open:** every gate errors plainly on broken input (missing/garbled files, empty globs) — a gate that silently passes on its own breakage is the forbidden failure class. All gates carry hermetic tests; `python -m pytest` is a DoD gate.
- **Doc-budget gate — WARN band + load-profile-aware caps.** `check_doc_budgets.py` emits a WARN at ≥90% of budget (`WARN_RATIO`, printed, exit 0) so a ledger signals BEFORE it hard-breaks the build; only a strict excess is a breach (exit 1). Caps reflect load profile: `CLAUDE.md` tight (6K, always-loaded); `DECISIONS.md` 60K (read on-demand); ROADMAP 12K. The cap STAYS a forcing function — when the WARN fires, **run the condensation pass** (canonical procedure + keep/drop test in `docs/claugentic-WORKFLOW.md` → Definition of Done → *The condensation pass*); **never remove the limit** (the cap IS the trigger — removing it removes the pass).
  - **Grounding — the leanness *spirit* is official; the byte-cap *mechanism* is HARNESS-PROPRIETARY.** The Claude Code `memory` doc grounds *why* we keep CLAUDE.md lean + read the other ledgers on-demand: a **~200-line CLAUDE.md target** (*"Longer files consume more context and reduce adherence"*), **skills that load on demand**, **subagent context isolation**. **BUT the per-ledger BYTE budgets** (6K/60K/12K/20K) **+ WARN-band + condense-on-WARN are the harness's OWN mechanism, NOT official** — official gives a CLAUDE.md *line*-target only. Never launder them as "the official cap" (spirit official, caps ours). *Also official (grounds the #1 honesty rule, not the caps):* memory is *"context, not enforced configuration. To block an action … use a PreToolUse hook instead."*
- **Tree read-economy → condense now, shard later (plan 0024 S1).** The architecture tree is the one read-first-every-task large doc — the real recurring context tax (DECISIONS/ROADMAP are read-on-demand, not auto-loaded). Entries aim at a **~150-char working target** (what-it-is + when-to-open), `MAX_ENTRY_CHARS=450` the hard ceiling. Crammed rationale is **evicted** to DECISIONS/INVARIANTS or **dropped** (git history recovers it) — the tree points at the doc, never restates it. Directory **sharding** is the large-repo lever, **deferred** to ROADMAP.
- **The tree-check is language-incidental** — harness tooling that never parses project source; it stays Python with `INCLUDE_GLOBS` as the **single per-repo knob** (the valid-extension set is derived from it). Glob-drift detection uses a stable `SOURCE_EXTS` allow-list + the managed-stamp exclusion — **no per-stack registry** (an always-incomplete list re-introduces the rot it kills). Detection is mechanical; the glob *reset* is model-upheld (init's terminating self-correction).
- **The deterministic trust-gates for unwatched runs** (a land-gate hook · a secret-scan) are **not built** — and the harness says so rather than claiming them (asserting "cannot land red" before such hooks exist would be the over-claim the harness forbids); build-to-green is **a reduction of unwatched-run risk, never a substitute** for these unbuilt gates, and its decline names which unlock conditions are unmet (see Build mode). *(The red-first/characterization test-first enforcement hook was considered and DECLINED — 0035 rejected 2026-07-04; see the methodology line — model-upheld is the chosen posture, not a pending gate.)*
- **The gate scripts self-anchor to their own repo root at runtime (CWD-independent).** A `_repo_root()` helper derives the root from the script's own `__file__` (git `--show-toplevel` anchored to the script dir, with a fallback — **never** an absolute/hardcoded path, so it's portable across machines/adopters); `main()` chdirs to it at the entry boundary. **All user-facing output stays repo-relative** (no machine-path leak). The helper is **duplicated, not shared** (the copied `claugentic-check_architecture_tree.py` can't import a harness-repo module, so each gate is independently self-contained). Stdout/stderr are reconfigured to UTF-8 (em-dashes must not mojibake on Windows cp1252).
- **Code-analyzing gates compose with the project's own linters/analyzers — never rebuilt per language** (a harness-owned per-language analyzer is forbidden; the tree-check stays language-incidental for this reason).

- **Model-tier menu + advisor-awareness (plan 0031).** WORKFLOW *Model tiers* names the verified menu (`best`/`fable`/`opus`/`sonnet`/`haiku`/`opusplan`) — canonical there. Live rules: **NEVER hardcode Fable / never assume its availability** (access is conditional/temporary — prefer `best`, which auto-falls-back to Opus, or an explicit fallback chain); accuracy-first policy unchanged. **Advisor-AWARE:** the platform advisor is documented (WORKFLOW) as an **optional, flag-gated, experimental, Anthropic-API-only, model-upheld** accuracy lever for the gate/verify roles at decision points — a **reduction of single-model-blind-spot risk, NOT independent verification** (same vendor; see *the two senses of "independent"*). Distinct from the harness's own SessionStart `claugentic-session-advisor.py`.
- **Review is cross-review by separate specialist agents — independence of context and role, NOT of model.** Distinct roles + clean contexts, each on the most-capable available model (tier by auto-resolving alias — see WORKFLOW *Model tiers*). No different-model judge — the honest framing is **structural independence only.** Script runs pin `model: MODELS.judge`; prose runs use agents' `model:` frontmatter. *(An inert legacy cross-model token remains in the engine + test fixtures; fully removing the dormant machinery is a deferred YAGNI cleanup.)*
- **Same-model honesty after the cross-model judge was dropped:** every judge opens with a `RUNNING AS:` self-report naming its **model family**; on **any same-family run** the orchestrator applies the verbatim tag *"same-model review on this run — the judge and the builder are the same model family here."* A spawn error respawns with the default + the tag (**a gate role never becomes unspawnable**); an unrecognized family is *unresolved*, never asserted same-model. Wording lives once in `engine/*.js`'s `sameModelTag` + `KNOWN_FAMILIES` (test-pinned).
- **`finding-verifier` independence is structural:** it receives only `{claim, file:line, source module, confidence, exclude-set}` + a refute-first posture — never the finder's rationale; **a lens never verifies its own finding.**

## The audit (`/claugentic-dev-harness:audit`)

- **One thoroughness slider, three notches** (`quick` · `standard` · `thorough`), one uniform pipeline at every notch: **FIND → PRUNE → VERIFY → surface.** All relevant lenses run at *every* level — a lens is never dropped to make a level cheaper; the slider sets the **depth** each lens reads at (`focused` → `deep` → `exhaustive`). `thorough` (named-only, never auto-picked) also runs the **blind-spot sweep** (`lens-reviewer` whole-scope mode) + an **adversarial `yagni-sentinel` prune** — FIND and PRUNE at max, not bolt-ons.
- **The re-check is universal:** after the prune, the audit attempts to refute **every surfaced finding, all tiers, every level** (one `finding-verifier` per finding). Every backlog item shows one verification tag; the legend carries the not-a-mechanical-guarantee caveat. Identical re-sweeps are retired (**single look per `(module × dir)` cell**); recall rests on lens breadth + depth.
- **Deterministically bounded + resumable:** a finite cell set, one shared backstop `max-cells-per-run` cap (bounds cost + the orchestrator's synthesis context, not per-agent context), `PARTIAL` checkpoints with explicit done/pending cell lists. Findings are never count-capped or silently truncated.
- **Cell ordering is INTERLEAVED round-robin → no lens starvation.** `enumerateCells` iterates **dir-OUTER / module-INNER**, so a budget-limited prefix covers EVERY lens's top dir broad-then-deep — when `maxCellsPerRun ≥ lens count` every lens gets ≥1 cell and **whole-lens starvation is structurally impossible** (the ordering IS the per-lens floor; no separate floor pass). **The cap wins** (synthesis-context guarantee intact); a `maxCellsPerRun < lenses` run surfaces never-run lenses **loudly** via `lensCoverage`. Re-enumeration is a **pure function of input order**, so `doneCells` (subtracted next run) reproduces the original interleaved tail **exactly** — this **resume-determinism is the load-bearing invariant** (test-pinned). The **blindspot pseudo-cell stays strictly last.** `lensCoverage` distinguishes **ran-clean** (explicit CLEAN, 0 findings) from **never-ran** (budget-deferred / failed). **Deferred to ROADMAP (YAGNI):** auto-sizing `maxCellsPerRun` + hierarchical per-lens roll-up.
- **Fences are regenerate-don't-accumulate:** the `harness-audit:overview` / `harness-audit:backlog` fences are replace-only-inside, human-owned outside; **no script-generated noise inside a fence** (byte-identical re-runs apart from the orchestrator-stamped audit date). **"Sound on the audited dimensions"** is the explicit terminal signal when Tier 1+2 come back empty — a stop signal, not a treadmill.
- **Two backlog fences, each regenerate-independently (engineering + product):** the engineering audit writes `harness-audit:backlog`; product gap mode writes its **own** `harness-product:backlog` — running one **never** touches the other (prevents a `build` re-audit wiping the product backlog). The **renderer is reused, not forked** (same `renderBacklogFence`, only the marker differs — DRY). The product fence is a **re-derivable projection of the spec against current code** — the durable product layer is `docs/claugentic-PRODUCT_SPEC.md` + the human-owned ROADMAP, **not the fence**. **Cross-fence dedup is model-upheld at `build` triage**, not mechanical (the backlogs key in different namespaces). Product is **backlog-only** (engineering `harness-audit:overview` stays the single repo overview).
- **Fence-conventions are paired-or-explicitly-not:** any future fence addition must check **every** singular "the backlog"/"the fence" reference (PLAYBOOK, init, build-resume) and either pair it or record the asymmetry on purpose.
- **The "Application source present" predicate is defined once** (audit Phase 1), reused by `init` — a repo of only docs/config/harness scaffolding is "no application source" (a new-project on-ramp, not an audit target).
- **The eval (`eval/`) is a seeded-defect drift detector, not a quality guarantee.** `eval/BASELINE.md` is the single source of truth for the measurement procedure; the intentional seeded defects (`eval/fixture-defects/app/` standard audit, `eval/fixture-app/` QA run) **MUST NOT be "fixed"** — fixing them disarms the exam. The no-peeking contract is **prompt-scoped + canary-backstopped**, never a filesystem sandbox; `eval/` is repo-local, never copied.
- **The finder pipeline + SELECT-before-render gate** (canonical: WORKFLOW → *The finder pipeline*; the coverage invariant in `docs/claugentic-INVARIANTS.md` → SELECT re-render). The non-obvious constraints: **SELECT is model-upheld, NOT a mechanical gate**; **skip ≠ reject** (a non-tick is a per-run skip; explicit rejection appends to the rejected-memory fence, never inferred from a left-unchecked box); **commitment (not capture) triggers the plan** (selecting = the Stage-2 trigger); the agent-free **`renderOnly` fast-path** is the only render seam and coverage/run-report stay full-scope over it (the invariant); **OFFER-BUILD default = leave, never forced**; Bugs-as-3rd-source = build-TRIAGE, not the finder SELECT.
- **`doctor` — the harness-health finder + its treat-boundary (plan 0025 S7; canonical: `skills/doctor/SKILL.md`).** `doctor` checks the **harness's OWN** wiring/ledgers/plans (vs `audit` = your code vs standards), on the shared finder pipeline. **Diagnose is strictly READ-ONLY** — gate scripts by **per-script presence** (run a gate iff its script is present, else N-A) + plan-scan + init post-conditions + a report-only Stage-9 signal → a **transient** snapshot (NOT a fence) with honest **`[D]`** (exit code) vs **`[J]`** (model-upheld). **Treat fires ONLY on explicit approval, never silent**, and ONLY the **bounded ∧ reversible (git history) ∧ no-architectural-decision** set: delete a landed/cold plan · re-wire the pre-commit hook · apply a doc-condensation diff · tree hygiene. **The doc-condensation treat is safe ONLY because the diff is user-approved before apply (the approval IS the decision gate — NOT because condensation is decision-free).** Anything **substantive** → ROADMAP → commitment triggers the plan → OFFER-BUILD. **doctor REPORTS the Stage-9 "harvest likely skipped" signal; the active harvest is `retrospect-harvester`'s** (no double-build). **No durable doctor reject-memory** (a recurring health issue SHOULD recur — YAGNI).
- **The rejected-findings memory — a dropped audit finding stays dropped.** Dismissed findings live in the `<!-- harness-audit:rejected-findings -->` fence in `docs/claugentic-ROADMAP.md`, **OUTSIDE** the regenerate `harness-audit:backlog` fence (a re-audit must not wipe it; finders read it before rendering and skip listed findings). It is a **user override of model judgment, not a deletion of evidence** (product mode mirrors it via `<!-- product-critic:rejected-proposals -->`). Detail in WORKFLOW → finder pipeline.

## Build mode (`/claugentic-dev-harness:build`)

- **A thin orchestration layer** over the WORKFLOW pipeline + the audit's backlog — no new pipeline, agents, or state stores. The plain-English ask is the interface; a single named item is the fast path (no triage).
- **Decision-gated by default** (canonical: *workflow & roles* → Decision-gated autonomy): the watched run proceeds autonomously, STOPping only for the three classes (the concrete per-item stops — spec before any code · before land + irreversible — ARE those classes); reversible judgments are flagged-and-continued and **surfaced at the close-out**, plus the exception pauses (re-slice, item-failure with *"nothing partial landed"*, re-triage). **Build-to-green is the separate who-watches axis (unwatched, requestable):** eligibility = three unlock conditions as judgment-with-stated-evidence (CI runs the gates · a test baseline · an approved spec with testable criteria) **plus** script-only execution (`engine/build-item.js` — never a prose loop); unmet → a verbatim decline naming what's missing, then a watched run is offered.
- **The engine never touches git — `engine/build-item.js` contains no push/merge/land/git step by construction.** Every terminal status is a return-to-orchestrator (`green` → the before-land pause is the orchestrator's; `needs-irreversible`; `new-tier12` → re-triage, never folded silently; `not-green` at cap → "here is the residual", nothing partial landed; `blocked`). It iterates implement (`implementer` in a worktree) → deterministic gates (the pass/fail *decision* over reported exit codes is mechanical, never fail-open) → the Verify panel (`engine/verify.js`) → QA (`engine/qa.js`, when machine-checkable criteria exist) → fix, until green or cap.
- **The irreversible hard-stop set** (push to a shared remote **including `main`** — this repo admin-bypasses branch protection — deploy, data deletion, spend, external side-effects): stop, name the action + consequence, ask; **never proceed on silence.** **Never invent scope** — a discovered feature goes to the roadmap, not the worklist.
- **The loop:** confirmed ordered worklist → per-item engine → a **scoped re-audit over the touched `(module|dir)` cells** after each landed item (cross-file fallout is the closing full audit's — the harness has no dependency graph and claims none) → **re-triage on any new Tier-1/2** (safety over fatigue) → one `standard` closing audit → the terminal signal.
- **Resume derives, never stores:** the worklist reconstructs from **both backlog fences** (engineering + product) + plan files (`Spec'd` = awaiting a sitting · `Approved` = build when reached · unchecked boxes = in-flight · removed at Land = done); the picked *order* is re-confirmed (a 5-second re-confirm beats a third state store). **Approval is never inferred** — only an explicit `Status: Approved` counts.
- **Batch spec-approval is a requestable ask** (*"spec everything first"*), not a standing question — a passive tip line is the only as-we-go addition. The sitting is **roster-first** (scannable one-line roster; full triads beneath to drill into; approve/adjust/drop, drop unjudged) — the defense against relocating decision-fatigue inside the sitting. Interruption-honesty at the ask **and echoed at the sitting close**; a **file-level spec-currency check** before each item re-confirms if landed work touched its named files.

## Plugin identity & distribution

A test pins the object form so it can't regress.

- **Every harness-owned adopter-facing file carries a uniform `claugentic-` filename prefix in source AND adopters.** The managed docs (`docs/claugentic-*.md`), the standards catalog (`docs/claugentic-standards/`), and the tree-gate script (`scripts/claugentic-check_architecture_tree.py`) are **born prefixed** — so an adopter's own conventionally-named files can never collide, and skills/engines reference one set of names (`init` copies path-for-path, no transform). **Plugin-internal files stay clean** (`engine/*.js`, `.claude/agents/*`, in-flight plan FILES, `scripts/check_versions_synced.py`, `docs/RELEASE_CHECKLIST.md` — read-from-install / never-copied, no collision surface). `TREE_PATH` is a **fixed constant**; `INCLUDE_GLOBS` is the only per-repo knob. **Any new managed file must be born prefixed** — a managed file's name is part of its contract.
- **The genuine-managed predicate keys on the STABLE stamp prefix** `claugentic-dev-harness@<semver> managed — do not edit` (trailing clause version-variable; a REFRESH migrates it). Only **detection** loosens to the stable prefix — what `init` **writes** is unchanged (always the current full form). Both clobber-edge legs (path-in-the-managed-set + the full prefix on **line 1**; a bare token in prose doesn't match) stay mandatory — **never-clobber is not weakened.**
