# Decisions

A **forward-looking maintainer's guide**: the standing decisions a future agent MUST know to safely improve the harness without re-breaking it or re-litigating settled choices. **Consult before revisiting a past choice** (see CLAUDE.md → Harness Discipline). This is **NOT an append-only history** — it is condensed periodically (when the doc-budget WARN fires), merging superseded entries into git history, which holds the dropped build-history detail. When in doubt, keep a constraint. For genuinely new decisions, append a dated one-liner at the top of the relevant section.

## Honesty positioning (the #1 rule)

- **Never let copy launder model judgment into apparent mechanical fact.** This is the core rule everything else serves. The honest enforcement split: the **architecture-tree check is the only hook-enforced gate**; `check_versions_synced.py` + the test suite + the doc-budget gate are **deterministic run-gates** (mechanical when run; running them is discipline); everything else — reviewer sign-offs, the diverse panel, the audit's finding re-checks, build mode's pauses — is **model-upheld** and must say so.
- **Verb discipline:** the harness *"attempts to / tries to re-check"* and *"tags the outcome"* — never *"verifies / proven / arrives with proof / guaranteed."* Success claims are **dimension-scoped** (*"sound on the audited dimensions"*), never "bug-free / perfect."
- **Check a claim from the surface that MAKES it, not just the referenced body (2026-06-25, Stage-9 harvest of the `renderOnly` miss).** A **capability / feasibility** claim — *"X calls Y", "zero/no change needed", "the SKILL re-renders via Z", "reachable from here", "the adopter just runs W"* — is only honest if the **caller** (a prose SKILL · a sandboxed engine script · an adopter's layout · the runtime) can actually reach and perform it; confirming the referenced implementation *exists and behaves* is **not** enough (a function can be sound in its body yet unreachable from the surface the copy says invokes it). Worked example: the honesty-reviewer signed plan 0025 S4a's *"the SKILL calls `renderBacklogFence` with zero engine change"* CLEAN against the helper body, but the helper was **unreachable** from the sandboxed prose SKILL — false at the caller (caught on `plan-reviewer` re-review; see the renderOnly seam under the finder pipeline). **Fix (model-upheld, not a new gate):** `honesty-reviewer.md` bar item 7 + Method step 2 require tracing a feasibility claim to its caller; `lens-reviewer`/`architect-reviewer` inherit the principle (propagate into their prompts in `0026` §C if a code-side feasibility miss recurs — YAGNI until then). A single CLEAN on a feasibility/trust claim is weaker than a second adversarial re-check — for a claim that *overturns* or *rests on* a prior reviewer's ground-truth, re-review rather than trust one pass.
- **The two senses of "independent":** claims of model-family independence / de-correlation about the judges are **forbidden** (same vendor → errors stay correlated; the honest claim is *"a different model family — a reduction of shared-blind-spot risk, NOT a guarantee"*). The **structural** sense — clean-context input-contract isolation ("independently re-checks") — is accurate and **preserved**. See INVARIANTS → the scrubbed-file set, which pins this in the files that must never regain the claim.
- **`[D]` vs `[J]`:** a deterministic-labeled check is only *proven* where the adopter has the relevant tool wired; otherwise it is reported as the model's judgment.
- The adopter-facing audit-backlog LEGEND must use the honest structural-independence framing (*"a separate clean-context agent that never saw the finder's reasoning — a reduction of rubber-stamping risk, not a mechanical guarantee"*), never the cross-model de-correlation copy. The three-state disclosure machinery STAYS (it degrades to the same-model floor); only over-claiming copy is forbidden — it goes MORE honest, never re-asserts de-correlation. The same honest copy also lives in the dormant cross-model run-report branch in `engine/audit.js`, pinned by `tests/workflows/audit.test.mjs` — change both together.

## The deterministic gates

- **`init` solo / local-only mode (2026-06-24, plan 0024 S4b):** an `init`-recorded mode trigger (AskUserQuestion step 1, **default Shared** — silence/timeout/unavailable all → Shared) routes four divergences so a user dogfoods the harness on a team repo with **zero new tracked paths, no committed-`.gitignore` edit, no shared git config** (git status clean; teammate clones byte-identical): (a) managed docs/tree/tree-script paths → **`.git/info/exclude`** (per-clone, untracked), never the committed `.gitignore`; (b) the pre-commit hook → **`.git/hooks/pre-commit`** (local) with `core.hooksPath` left at default — only the pre-commit gate is the solo hook; a non-default existing `core.hooksPath` is reported, not clobbered; (c) **skip step 5c** (no plugin self-reference, no `.gitignore` negation, no teammate prompt — invisible to teammates); (d) the CLAUDE anchor → **`CLAUDE.local.md`** (gitignored). Step 9 emits a solo honesty line + a `git status`/`git diff -- .gitignore` verification claim, fail-loud-guarded by `git check-ignore` on every solo-written path. Mode recorded as `- Harness mode:`, read before prompting (a recorded `solo` short-circuits the shared branches — make-invalid-states-unrepresentable). DRY — one documented divergence, not an `init-solo` command. Shared mode unchanged.
- **Adopter `init` wires the pre-commit tree gate (2026-06-24, plan 0024 S4a):** `init` step 5b writes `.githooks/pre-commit` (the shipped wrapper) + runs `git config core.hooksPath .githooks` for a shared adopter when the gate is ON (gate OFF → no hook, no hooksPath); never-clobbers a different existing `core.hooksPath` (reports the conflict, continues). The dead `--hook` (Stop) / `--hook-write` (PostToolUse) modes + helpers + tests were retired in lockstep — the gate's only non-zero exit is 1. `init` writes **no** tree hooks into `.claude/settings.json` (only the plugin self-reference).
- **Tree-gate altitude → commit-time (2026-06-24):** the gate runs from a git `pre-commit` hook (`.githooks/pre-commit` via `core.hooksPath`) `--staged`, not the per-action `PostToolUse`/`Stop` Claude Code hooks — once per `git commit`, local, **zero per-tool overhead**; the commit is the only point the tree must be correct, and the agent is in-context then to fix it. `--staged` = index-scope (not unrelated untracked files). **No adopter CI** (next commit catches a miss; harness public CI unchanged).
- **One gate, one invariant (SRP siblings):** the tree-check owns the file index (presence · staleness · zero-coverage glob-drift); `check_versions_synced.py` owns the `plugin.json` ↔ `marketplace.json` version pair (one source of truth — every bump moves both, `plugin.json` authoritative). A new mechanically-checkable invariant gets a **sibling script, not an extension** of an existing one.
- **Fail loud, never fail-open:** every gate errors plainly on broken input (missing/garbled files, empty globs) — a gate that silently passes on its own breakage is the forbidden failure class. All gates carry hermetic characterization tests; `python -m pytest` is a DoD gate.
- **Doc-budget gate — WARN band + load-profile-aware caps.** `check_doc_budgets.py` emits a WARN at ≥90% of budget (`WARN_RATIO`, printed, exit 0) so a ledger signals BEFORE it hard-breaks the build; only a strict excess is a breach (exit 1). Caps reflect load profile: `CLAUDE.md` tight (6K, always-loaded); `DECISIONS.md` 60K (read on-demand); ROADMAP 12K. The cap STAYS a forcing function — when the WARN fires, **condense periodically** (merge superseded entries to git history); **never remove the limit** (that removes the condense trigger).
- **Tree read-economy → condense now, shard later (2026-06-24, plan 0024 S1).** The architecture tree is the one read-first-every-task large doc — the real recurring context tax (DECISIONS/ROADMAP are read-on-demand, not auto-loaded). Entries aim at a **~150-char working target** (what-it-is + when-to-open — the load-bearing navigation signal), `MAX_ENTRY_CHARS=450` the hard ceiling. Crammed rationale is **evicted** to DECISIONS/INVARIANTS or **dropped** (git history recovers it) — the tree points at the doc, never restates it. Directory **sharding** is the large-repo lever, **deferred** to ROADMAP (not built).
- **The tree-check is language-incidental** — harness tooling that never parses project source; it stays Python with `INCLUDE_GLOBS` as the **single per-repo knob** (the valid-extension set is derived from it). Glob-drift detection uses a stable `SOURCE_EXTS` allow-list + the managed-stamp exclusion — **no per-stack registry** (an always-incomplete list re-introduces the rot it kills). Detection is mechanical; the glob *reset* is model-upheld (init's terminating self-correction).
- **The deterministic trust-gates for unwatched runs** (a land-gate hook · a secret-scan · a characterization-tests-first hook) are **not built** — and the harness says so rather than claiming them (asserting "cannot land red" before such hooks exist would be the over-claim the harness forbids); build-to-green is **a reduction of unwatched-run risk, never a substitute** for these unbuilt gates, and its decline names which unlock conditions are unmet (see Build mode).
- **Both gate scripts self-anchor to their own repo root at runtime (CWD-independent).** A `_repo_root()` helper derives the root from the script's own `__file__` (git `rev-parse --show-toplevel` anchored to the script dir, with a `<script_dir>/..` fallback — **never** an absolute/hardcoded path, so it's portable across machines/adopters), and `main()` does `os.chdir(_repo_root())` at the entry boundary. **All user-facing output stays repo-relative** (no machine-path leak). The helper is **duplicated, not shared**, between `claugentic-check_architecture_tree.py` (copied to adopters) and `check_versions_synced.py` (harness-self gate): the copied gate can't import a harness-repo module, so each is independently self-contained. `_force_utf8_output()` reconfigures stdout/stderr to UTF-8 (em-dashes must not mojibake on Windows cp1252). `_repo_root` is the monkeypatch seam test fixtures pin.
- **Code-analyzing gates compose with the project's own linters/analyzers — never rebuilt per language.** A new gate composes with the adopter's existing lint/type/static-analysis tooling rather than a harness-owned per-language analyzer (the tree-check stays language-incidental for this reason).

## The verify/judge roles (skeptical clean-context review)

- **Review is cross-review by separate specialist agents — independence of context and role, NOT of model.** Distinct roles + clean contexts, each on the **most capable available model**. There is no different-model judge (the override model became unavailable); the honest framing is structural independence only. Models are picked by capability **tier** via auto-resolving aliases (**most capable** `opus` · **mid** `sonnet` · **fastest/cheapest** `haiku`), **never a pinned version**; default to the most capable model for anything needing judgment, incl. high-volume — **accuracy first, conservation second**; cheaper tiers only for mechanical work. Script runs pin `model: MODELS.judge` (most-capable tier); prose runs use agents' `model:` frontmatter. *(The engine `KNOWN_FAMILIES` + workflow-test fixtures carry an inert legacy cross-model token; fully removing the dormant cross-model machinery is a deferred YAGNI cleanup.)*
- **Same-model honesty after the cross-model judge was dropped:** every judge opens with a `RUNNING AS:` self-report naming its **model family** (never the vendor alone, never its role); the orchestrator compares it to the builder family and, on **any same-family run**, applies the verbatim tag: *"same-model review on this run — the judge and the builder are the same model family here."* On a spawn error: respawn with the default + the tag — **a gate role never becomes unspawnable**. A present-but-unrecognized family is reported as *unresolved*, never asserted same-model fact (the conservative trust floor). The wording lives once in `engine/*.js`'s `sameModelTag` + `KNOWN_FAMILIES`, pinned by `tests/workflows/cross-script.test.mjs`.
- **`finding-verifier` independence is structural:** it receives only `{claim, file:line, source module, confidence, exclude-set}` + a refute-first posture — never the finder's rationale; **a lens never verifies its own finding.**

## The audit (`/claugentic-dev-harness:audit`)

- **One thoroughness slider, three notches** (`quick` · `standard` · `thorough`), one uniform pipeline at every notch: **FIND → PRUNE → VERIFY → surface.** All relevant lenses run at *every* level — a lens is never dropped to make a level cheaper; the slider sets the **depth** each lens reads at (`focused` → `deep` → `exhaustive`). `thorough` (named-only, never auto-picked) also runs the **blind-spot sweep** (`blindspot-reviewer`) + an **adversarial `yagni-sentinel` prune** — FIND and PRUNE at max, not bolt-ons.
- **The re-check is universal:** after the prune, the audit attempts to refute **every surfaced finding, all tiers, every level** (one `finding-verifier` per finding). Every backlog item shows one verification tag; the legend carries the not-a-mechanical-guarantee caveat. A re-found false positive is still false — so identical re-sweeps are retired (**single look per `(module × dir)` cell**); recall rests on lens breadth + depth.
- **Deterministically bounded + resumable:** a finite cell set, one shared backstop `max-cells-per-run` cap (bounds cost + the orchestrator's synthesis context, not per-agent context), `PARTIAL` checkpoints with explicit done/pending cell lists. Findings are never count-capped or silently truncated.
- **Cell ordering is INTERLEAVED round-robin → no lens starvation (0025 step-2 audit fix).** `enumerateCells` iterates **dir-OUTER / module-INNER** (`m0×d0, m1×d0, …, m0×d1, …`), so a budget-limited `slice(0,N)` prefix covers EVERY lens's top dir broad-then-deep — when `maxCellsPerRun ≥ lens count` every configured lens gets ≥1 cell and **whole-lens starvation is structurally impossible** (the ordering IS the per-lens floor; no separate floor pass). **The cap wins**: the floor comes from the interleave, never from overriding the cap (the synthesis-context guarantee the cap protects is never silently busted); a `maxCellsPerRun < lenses` run surfaces the never-run lenses **loudly** via `lensCoverage`. Re-enumeration is a **pure function of input order** (no Set-iteration / sort dependence) → deterministic + stable, so `doneCells` (a set the next run subtracts) reproduces the original interleaved tail **exactly** — this **resume-determinism is the load-bearing invariant** (pinned by a dedicated test). The **blindspot pseudo-cell stays strictly last**. Per-lens `lensCoverage` (`ran-found N` / `ran-clean` / `pending`) distinguishes **ran-clean (explicit CLEAN, 0 findings)** from **never-ran** (budget-deferred / failed batch) so a reader confirms "every lens spoke" before prioritizing. **Deferred to ROADMAP (YAGNI):** auto-sizing `maxCellsPerRun` + hierarchical per-lens synthesis roll-up — built only when a real large repo exceeds the single-pass ceiling.
- **Fences are regenerate-don't-accumulate:** the `harness-audit:overview` / `harness-audit:backlog` fences are replace-only-inside, human-owned outside; **no script-generated noise inside a fence** (byte-identical re-runs apart from the orchestrator-stamped audit date). **"Sound on the audited dimensions"** is the explicit terminal signal when Tier 1+2 come back empty — a stop signal, not a treadmill.
- **Two backlog fences, each regenerate-independently (engineering + product):** the engineering audit writes `harness-audit:backlog`; product gap mode writes its **own** `harness-product:backlog` — running one **never** touches the other (the split prevents a `build` re-audit wiping the product backlog). The **renderer is reused, not forked** — both fences carry the same `renderBacklogFence` body (`engine/audit.js`); only the target marker differs (DRY). The product fence is a **re-derivable projection of the spec against current code** — the **durable** product layer is `docs/claugentic-PRODUCT_SPEC.md` + the human-owned ROADMAP area, **not the fence**. **Cross-fence dedup is model-upheld at `build` triage**, deliberately not mechanical: the two backlogs key findings in **different namespaces** (engineering `module×dir` vs product criterion-ids), so a mechanical key-match could never fire on a real semantic overlap. Product is **backlog-only — no product `overview` fence** (engineering `harness-audit:overview` stays the single repo overview).
- **Fence-conventions are paired-or-explicitly-not:** any future fence addition must check **every** singular "the backlog"/"the fence" reference (PLAYBOOK, init, build-resume copy) and either pair it or record the asymmetry on purpose.
- **The "Application source present" predicate is defined once** (audit Phase 1), reused by `init` — a repo of only docs/config/harness scaffolding is "no application source" (a new-project on-ramp, not an audit target).
- **The eval (`eval/`) is a seeded-defect drift detector, not a quality guarantee.** `eval/BASELINE.md` is the single source of truth for the measurement procedure; the intentional seeded defects (`eval/fixture-defects/app/` standard audit, `eval/fixture-app/` QA run) **MUST NOT be "fixed"** — fixing them disarms the exam. The no-peeking contract is **prompt-scoped + canary-backstopped**, never a filesystem sandbox; `eval/` is repo-local, never copied.
- **The finder pipeline + SELECT-before-render gate (2026-06-25, plan 0025 S4a–S6; documented in WORKFLOW → *The finder pipeline*).** The three finders (`audit` · `product` gap-mode · `doctor`) share ONE lifecycle — **`FIND → SELECT → PLAN → OFFER-BUILD → BUILD`** — so nothing is planned/spec'd/written to the backlog until the user picks it (anti-bloat). **SELECT is a model-upheld user action, NOT a mechanical gate:** the skill reads the finder's rejected-memory fence first (omit already-dismissed candidates), presents the rest as a **transient editable `- [ ]` checklist** (reuses the rendered backlog-item form — scales past AskUserQuestion's ~4; never persisted into the managed fence); the **checked subset** is rendered into the fence. **The `renderOnly` re-render seam (supersedes the falsified "ZERO engine change" claim):** a prose skill **cannot** re-render via `renderBacklogFence` — `engine/audit.js` is a sandboxed non-importable Workflow script and that helper is un-exported; string-dropping rendered blocks would leave a **stale recommendation line + a false terminal "sound" signal** (`renderRecommendation`/`TERMINAL_SIGNAL`) = dishonest. The seam: a minimal **agent-free `renderOnly` fast-path** in `engine/audit.js` (returns before `parseArgs`/the FIND/PRUNE/VERIFY pipeline + the `isGap` branch, serving audit + product gap-mode) — the skill filters `result.items` to the selected subset and re-invokes with `args.renderOnly = { ...result, items: selected }`; `renderOnlyResult` **validates the payload at the boundary** (fail loud on a non-object / non-array `items`) and re-renders via the renderer (the single source of the fence format). **★ INVARIANT — coverage/run-report stay FULL-SCOPE:** `lensCoverage`/`verification` handed to the renderer are the unfiltered full-audit values ("we looked at all of this; you chose to act on these") — NEVER recomputed over the selected subset (that would falsely claim "every lens spoke" about only the kept findings); holds automatically because only `items` is filtered. **Skip ≠ reject:** a non-tick is a per-run skip (may resurface, NOT durable); explicit rejection appends to the rejected-memory fence — a deliberate user override of model judgment, never inferred from a left-unchecked box. **Commitment, not capture, triggers the plan** (selecting = committing = the Stage-2 trigger; a Bug/Later one-liner stays planless until selected; trivial items skip the backlog). **PLAN/OFFER-BUILD:** a committed item gets its **full plan** via the Stage-2 architect-pass (2a→2b→2c→Stage-3 `plan-reviewer` gate) — **reviewed groundwork, NOT a quality guarantee; model-upheld** — while the **deep per-slice Spec stays JIT** in build (the plan precedes the slices, architecture-first; NOT deep-spec-everything-upfront). **★ Plan-volume bound:** build-now items planned one-at-a-time as the serial loop works them (≤1 fresh plan file at a time); backlog items get a one-line entry, planned JIT when a later `/build` reaches them — never dozens at once. **OFFER-BUILD** = AskUserQuestion "build now or leave?", **default = leave, offered never forced** (forced auto-build is a non-goal) — the finder→build continuity that ends the "finders dead-end" leak. The **Bugs-as-3rd-source reader is build-TRIAGE** (worklist assembly), NOT the finder SELECT (which gates the finder's own fresh `result.items`).
- **`doctor` — the harness-health finder + its treat-boundary (2026-06-25, plan 0025 S7; `skills/doctor/SKILL.md`).** `doctor` checks the **harness's OWN** wiring/ledgers/plans (vs `audit` = your code vs standards), on the shared finder pipeline. **Diagnose is strictly READ-ONLY** (runs the THREE existing gate scripts — `claugentic-check_architecture_tree.py` · `check_versions_synced.py` · `check_doc_budgets.py`, the latter already carrying the INVARIANTS cap; NO new gate/script + plan-scan landed/cold + init post-conditions + a report-only Stage-9 signal) → a **transient** green/WARN/breach snapshot (NOT a fence) with honest **`[D]`** (a gate's exit code) vs **`[J]`** (the cold-plan call, the Stage-9 signal, every treat decision — model-upheld). **Treat fires ONLY on explicit approval, never silent**, and ONLY the **bounded ∧ reversible (git history) ∧ no-architectural-decision** set: delete a landed/cold plan · re-wire the pre-commit hook · apply a doc-condensation diff · tree hygiene (add/drop/condense an entry). **The doc-condensation treat is safe ONLY because the diff is user-approved before apply (the approval IS the decision gate — NOT because condensation is decision-free).** Anything **substantive** → ROADMAP (harness-self Quality/Feature · adopter Later + `harness` tag, no new section) → commitment triggers the plan → OFFER-BUILD. **doctor REPORTS the Stage-9 "harvest likely skipped" signal; the active harvest is owned by `0026` §C5's `retrospect-harvester`** (named seam, no double-build). **No durable doctor reject-memory** (the report is transient; a recurring health issue SHOULD recur — YAGNI). No new hook, no new always-loaded doc, no new fence; skills are auto-discovered (no `plugin.json` roster edit); a new skill is a release-time version bump, not a per-slice one.
- **The rejected-findings memory — a dropped audit finding stays dropped.** A user-judged-wrong finding is recorded in a `<!-- harness-audit:rejected-findings -->`-fenced list in `docs/claugentic-ROADMAP.md`, **mirroring product spec mode's `<!-- product-critic:rejected-proposals -->` convention exactly** (create-on-first-use, one terse line, never stamped, user-owned) and **OUTSIDE** the regenerate-don't-accumulate `harness-audit:backlog` fence so a re-audit never wipes it. `audit` (Phase 3) and `build` (triage + scoped/closing re-audit) **read the fence before rendering and skip any listed finding**. It is a **user override of model judgment, not a deletion of evidence**: the user can clear a line when the code changes; the harness never silently second-guesses a recorded dismissal.

## Build mode (`/claugentic-dev-harness:build`)

- **A thin orchestration layer** over the WORKFLOW pipeline + the audit's backlog — no new pipeline, agents, or state stores. The plain-English ask is the interface; a single named item is the fast path (no triage).
- **Decision-gated by default** (canonical model in the *workflow & roles* section above): the watched run proceeds autonomously, STOPping only for the three classes — the concrete per-item stops (spec before any code = (a)/(b) · before land + irreversible = (c)) ARE those classes, refined; reversible judgments are flagged-and-continued and **surfaced at the close-out (step 8)**, plus the exception pauses (re-slice, item-failure with *"nothing partial landed"*, re-triage). **Build-to-green is the separate who-watches axis (unwatched, requestable):** eligibility = three unlock conditions checked as judgment-with-stated-evidence (CI runs the gates · a test baseline for the touched code · an approved spec with testable acceptance criteria) **plus** script-only execution (`engine/build-item.js` — never a prose loop); unmet → a verbatim decline naming what's missing, then a watched run is offered.
- **The engine never touches git — `engine/build-item.js` contains no push/merge/land/git step by construction.** Every terminal status is a return-to-orchestrator (`green` → the before-land pause is the orchestrator's; `needs-irreversible`; `new-tier12` → re-triage, never folded silently; `not-green` at the cap → "not green; here is the residual", nothing partial landed; `blocked`). It iterates implement (`implementer-architect` in a worktree) → deterministic gates (an agent runs the commands; the pass/fail *decision* over reported exit codes is mechanical — `gatesGreen`, never fail-open) → the Verify panel (`engine/verify.js` child workflow) → QA (`engine/qa.js`, when machine-checkable criteria exist) → fix, until green or the iteration cap.
- **The irreversible hard-stop set** (push to a shared remote **including `main`** — this repo admin-bypasses branch protection — deploy, data deletion, spend, external side-effects): stop, name the action + consequence, ask; **never proceed on silence.** **Never invent scope** — a discovered feature goes to the roadmap, not the worklist.
- **The loop:** confirmed ordered worklist → per-item engine → a **scoped re-audit over the touched `(module × dir)` cells** after each landed item (file-level; cross-file fallout is the closing full audit's — the harness has no dependency graph and claims none) → **re-triage on any new Tier-1/2** (safety over fatigue) → one `standard` closing audit → the terminal signal.
- **Resume derives, never stores:** the worklist reconstructs from **both backlog fences** (engineering + product) + plan files (`Spec'd` = awaiting a sitting · `Approved` = build when reached · unchecked boxes = in-flight · removed at Land = done); the picked *order* is re-confirmed (a 5-second re-confirm beats a third state store). **Approval is never inferred** — only an explicit `Status: Approved` counts.
- **Batch spec-approval is a requestable ask** (*"spec everything first"*), not a standing question — a passive tip line is the only as-we-go addition. The sitting is **roster-first** (scannable one-line roster; full triads beneath to drill into; approve/adjust/drop, drop unjudged) — the defense against relocating decision-fatigue inside the sitting. Interruption-honesty at the ask **and echoed at the sitting close** (what batch does *not* remove); the sunk-cost fact once, neutrally; a **file-level spec-currency check** before each item re-confirms if landed work touched its named files.

## The workflow & roles

- **Architect-pass "Architecture & holistic fit" plan section (2026-06-25, plan 0025 S2; shared with 0026 §C — authored ONCE here).** A required `## Architecture & holistic fit` section in `.claude/plans/TEMPLATE.md` — a **structural forcing function** countering "architecture is model-upheld ⇒ agents sometimes skip it": the template forces the section to EXIST, the Stage-2 draft must FILL it (for *substantial* work; trivial/lightweight may one-line or skip it — honors the effort-dial), and `plan-reviewer` AUDITS it is genuinely reasoned (checklist item 8). It captures **initial architect thoughts** (codebase fit: layering/module-placement/design-patterns/SOLID-SoC · product fit · quality dimensions to uphold **each mapped to its `docs/claugentic-standards/` module** · future-proofing), **NOT the deep per-slice Spec** (JIT in build). It is the **forward-pointer** to the Spec's *in-scope standards dimensions* line — names the dimensions; the Spec refines them per slice (no duplicated list — DRY). **Honesty: model-upheld + structurally-prompted, NOT a mechanical gate** (you can't mechanically grade architecture; you require the section + review it). **YAGNI-balanced** — `yagni-sentinel` guards gold-plating; the section frames what to uphold, not a mandate to build every abstraction.
- **Stage 2 → the 2a/2b/2c sub-process (2026-06-25, plan 0025 S3).** WORKFLOW Stage 2 (Plan) is three steps for *substantial* work — **2a draft** (plan mode + `Plan`, TEMPLATE-structured, architect-pass filled) · **2b specialist advisory deep-dive** · **2c incorporate** — with **Stage 3 (Review) unchanged as the gate**, formalizing the diverse-panel-at-Plan into a STANDARD Stage-2 step. **2b is bound to the SAME Stage-0 SUBSTANTIAL triggers** (security/trust boundary · shared contract/pattern/standard · ~8+ files · any trust/honesty surface) — a **trivial/lightweight plan stays 2a → Stage 3 with NO panel** (the panel does NOT run on every plan). The 2b panel = in-scope `docs/claugentic-standards/` lenses (relevance-gated) + `yagni-sentinel` + `honesty-reviewer` (+ `product-designer` if user-facing); it is **ADVISORY, builder-class — it CONTRIBUTES, does NOT gate** (model-upheld). **Same panel, two altitudes:** 2b reviews DESIGN (advisory); Stage 7 Verify reviews CODE (gate). **2b↔2c loop is bounded — 1 round default.** **PROSE-CONVENED — zero spawn-id/engine surface:** the `engine/verify.js` `lens-reviewer` *plan-design-review* MODE + its `agent-namespace`/`cross-script` pins are **DEFERRED to `0026` §C** (which rewrites `lens-reviewer`'s modes — authoring the mode twice is a guaranteed double-touch).
- **Decision-gated autonomy SUPERSEDES the binary checkpoint/build-to-green ladder (2026-06-25, plan 0025 S1).** The autonomy question is **"is this a real choice the user must make?"**, judged per moment, **model-upheld** (nothing mechanically forces a stop). **STOP (blocking) only for three classes: (a)** a genuine design fork · **(b)** a spec with a real trade-off to accept · **(c)** an irreversible/outward action (commit-to-shared · republish · delete user content · spend) — **class (c) is a HARD stop the FLAG path can NEVER absorb, even on a low-confidence call.** **RESEARCH-don't-ask:** a factual/technical uncertainty is resolved by cited research, never a user stop (stops are for preference/judgment, not facts). **FLAG (non-blocking, REVERSIBLE only):** a should-know judgment-call whose cost-if-wrong is reversible → one-line flag + chosen default + CONTINUE. **SURFACE all flags at the close** ("things to review"), distinct from the 0024 disposition (reversible mid-run judgment vs done/defer/reject of unbuilt items). A wrong "proceed" is **bounded by flag-and-surface for reversible calls only** — the irreversible class (c) is never absorbed by a flag. The three concrete build pauses (spec · before-land · irreversible) ARE the three STOP classes, refined. **build-to-green survives as the separate *who-watches-the-run* axis** (watched vs unwatched/engine-driven, earned per-repo).
- **Plan disposition + the in-flight scope-split + ROADMAP taxonomy (2026-06-24, plan 0024 S5):** a plan **completes and is deleted, gated only on the committed slice** — every remaining unchecked item gets a disposition at close: **done** (checked) · **defer** (a `ROADMAP` line, or move a substantial / externally-blocked remainder into a NEW plan + a roadmap line) · **reject** (a declined-decision DECISIONS line, dropped). A plan **never lingers `pending` on an external blocker** — defer-to-new-plan (or reject) and close now. Mid-build scope splits two ways (user's call): **(a) intrinsic** → fold into the plan + re-run the steps (the decomposition grows because it *is* the feature); **(b) out-of-scope** → ROADMAP, not plan-bloat (a defect → the durable `Bugs` section). **No tech-debt parking section — debt is structurally prevented (every slice lands complete; Verify audits the diff pre-land), model-upheld + reviewer-caught, NOT a mechanical guarantee;** existing adopter debt is the *audit's* domain. **ROADMAP taxonomy (KISS — only `Bugs` is new):** generated/regenerated = Overview · Quality (`harness-audit:backlog`) · Features (`harness-product:backlog`); durable human/agent-owned **outside both fences** = **Bugs** *(new)* · **Later/Ideas**; dismissed audit findings stay in the audit's wired `<!-- harness-audit:rejected-findings -->` fence (no second decorative heading — DRY). The `Bugs` section survives a re-audit **structurally** — it sits outside the `harness-audit:backlog` markers and the engines replace ONLY the text *between* their markers. `doctor`/harness-maintenance deferrals ride **Later** with a `harness` tag. (Canonical: WORKFLOW → Plan file lifecycle; mirrored in `skills/build/SKILL.md` + TEMPLATE.)
- **The diverse-panel trigger** (stated once in WORKFLOW Principles): a contested design fork OR a trust/honesty surface convenes `plan-reviewer`/`architect-reviewer` + `yagni-sentinel` + `honesty-reviewer` — plus `product-designer` when user-facing — at **every gate the change passes** (Plan and Verify). Model-upheld: the orchestrator convenes it. A lone reviewer can bless what a panel rejects.
- **Roster maps to distinct FUNCTIONS/POSTURES, not 1:1 to a label — same-posture work consolidates into a mode-dispatched agent (2026-06-25, USER-APPROVED; SUPERSEDES the rigid "SRP-separate, never a mode" framing below, for the `0026` §C merges).** SRP still keeps genuinely-DISTINCT postures separate (find ≠ refute ≠ gate ≠ generate ≠ critique — a single-posture prompt is more prescriptive). But splitting the SAME posture across two agent files is a DRY violation + context cost (duplicated prompts, extra spawn/lockstep surface) with **no independence benefit**: `plan-reviewer` + `architect-reviewer` are both integrate→verdict→loop (plan- vs code-altitude); `product-critic` + `product-designer` are discover→elevate on the **same artifact** (builder-class — no clean-context separation needed); `blindspot-reviewer` already FINDS like a lens (same `LENS_SCHEMA`). So §C consolidates: `plan-reviewer`+`architect-reviewer`→`synthesizer-gate` (two altitudes; must still serve its three caller contracts — plan-gate edit / verify-verdict `SYNTHESIS_SCHEMA` / audit items-cuts, slotting 1:1), `blindspot`→a `lens-reviewer` whole-scope mode, `product-critic`→a `product-designer` elevate mode — while the truly-distinct postures (`yagni-sentinel`·`honesty-reviewer`·`finding-verifier`·native-generate) stay separate. When §C lands, the two "never a mode" lines below condense to match.
- **Specialist roles are SRP-separate, never modes of each other** *(being superseded by the entry above for the §C merges — `blindspot`→lens mode, `product-critic`→designer mode):* `lens-reviewer` audits exactly one standards module; `blindspot-reviewer` audits the space between modules; `finding-verifier` refutes one claim; `yagni-sentinel` argues over-build; `honesty-reviewer` refutes copy (its bar embedded in the agent — no separate standards module). Agent prompts are **self-contained** — they cannot follow links at spawn, so the DoD gate list is deliberately duplicated inline in the builder/verifier agents (controlled, not drift).
- **The Definition of Done lives canonically in WORKFLOW** (deterministic gates vs reviewer sign-offs — the split is the honesty line); CLAUDE.md + the pipeline table point to it. The Verify effort-dial reuses the Stage-0 "substantial" triggers — no scoring formula.
- **Lens-coverage on the Verify side — "loud advisory + presence-check" (2026-06-24, plan 0026 §A; the full glob-driven mechanical completeness gate was REJECTED).** `verify.js` has a **mechanical presence-assertion** (`finalVerdict`): a NAMED `args.dimensions` lens that produced no usable result forces `CHANGES_REQUIRED` so the panel can never report all-green with one of its own named lenses missing. This is a **presence-check on the panel's OWN outputs — NOT a completeness gate over the diff** (no fs, no globs, no decision-reversal); it does **not** promote `load_scope` to a gate. Plus a **mechanical test-diff rule** (`validateArgs`): when the change touches tests (`files` matched by `isTestPath`, or an explicit `testDiff` boolean for the opaque-`diffRef` path) the `testing` lens is mandatory — absent ⇒ fail loud (a green suite can hide a loosened assertion). **`load_scope.globs` STAYS advisory.** The loud-advisory **selection/coverage-gap surfacing** (a relevant-but-unselected lens) is **model-upheld**, folded into §C's roster work.
- **The Product Excellence pass elevates the spec — `product-critic` proposes, the user decides.** Spec mode (`skills/product/SKILL.md`) gains an Excellence pass between draft and validate: `product-critic` is the SRP **elevate** counterpart to `product-designer` (designer *surfaces* the user's truth; critic *elevates* it — never a mode of it). It is **generative/proposing → builder-class** (not cross-model: the user is the verdict-giver, nothing gates on its output). It critiques **by method, not a dimension checklist** (forcing functions, incl. a **mandatory premise-challenge**); it **points at** `docs/claugentic-standards/product-ux.md` for conformance (no new module) and carries only the *delta*. **Voice is balanced/neutral**; **removals are encouraged.** Proposals are **questions, never spec content until adopted** (adopt/adapt/reject/defer) — extends, never violates, the designer's never-invent-scope rule. **Rejected proposals + a declined-pass marker** are remembered in a user-owned fence in `docs/claugentic-PRODUCT_SPEC.md`. **Deep-research informs, doesn't certify:** the session `deep-research` skill grounds a benchmark round with citations on demand; unavailable → an honest decline + critique-only fallback (benchmark claims tagged model-knowledge-not-verified). A **deferred** proposal lands in ROADMAP's human-owned area. Default-on every spec-mode run, skippable on ask; it raises the bar, never guarantees the spec is excellent.
- **`CLAUDE.md` (an adopter's `harness:` block) is the blessed home for durable repo context.** The hard-won structural/domain gotchas a fresh agent must read first — and record as it learns them — live here, dense and one-line; the architect-reviewer / honesty-reviewer Read-first lines point at it. **Model-upheld, never authoritative** — context to consult, not a gate.
- **Stage 9 is a finite harvest checklist the orchestrator runs at Land** (a manual discipline, not automation), including the lesson→gate step: a manual/lens catch a gate could have made becomes a roadmap gate item, not just a record.
- **Audit-backlog tags select the execution discipline** (the WORKFLOW tag→discipline table): a `refactor` on untested behavior-bearing code is characterization-tests-first — upheld by the implementer stopping and asking (no mechanical hook enforces this; never imply one).
- **Scope is tech-agnostic:** no cross-product suite layer (converge-on-plugin already propagates standards — the plugin version is the coordination signal), no stack-specific prescriptions in the harness (those stay a suite's own config).

## Plugin identity & distribution

- **The marketplace plugin `source` MUST be the documented object form `{ "source": "github", "repo": "<owner/repo>", "ref": "release" }` to pin the release branch — never the `"owner/repo@release"` string.** The `@ref` shorthand is valid ONLY on the `/plugin marketplace add <owner/repo@ref>` command, never as a plugin-entry `source` value; the string form makes Claude Code reject the plugin as an unsupported source type — an **uninstallable-plugin** regression (the v0.2.4 fix). `tests/test_check_versions_synced.py` pins the object form so it can't regress. (Verified against code.claude.com/docs/en/plugin-marketplaces.)
- **Plugin id `claugentic-dev-harness`**; skills `init` · `audit` · `build` · `product`; install via `/plugin marketplace add sh4npeiris/claugentic-dev-harness` → `/plugin install claugentic-dev-harness@sh4npeiris`. Public, **Apache-2.0**.
- **Every harness-owned adopter-facing file carries a uniform `claugentic-` filename prefix in source AND adopters.** The managed docs (`docs/claugentic-{WORKFLOW,PLAYBOOK,ENGINEERING_STANDARDS,PRODUCT_SPEC_TEMPLATE,ARCHITECTURE_TREE,ROADMAP,DECISIONS,PRODUCT,PRODUCT_SPEC}.md`), the standards catalog (`docs/claugentic-standards/`), and the gate script (`scripts/claugentic-check_architecture_tree.py`) are **born prefixed** — so an adopter's own conventionally-named files can never collide, and skills/engines reference one set of names (`init` copies path-for-path, no transform). **Plugin-internal files stay clean** (`engine/*.js`, `.claude/agents/*`, `.claude/plans/*`, `scripts/check_versions_synced.py`, `docs/RELEASE_CHECKLIST.md` — read-from-install / never-copied, no collision surface). `TREE_PATH` is a **fixed constant** (`docs/claugentic-ARCHITECTURE_TREE.md`); `INCLUDE_GLOBS` stays the only per-repo knob. **Any new managed file must be born prefixed** — a managed file's name is part of its contract.
- **The genuine-managed predicate keys on the STABLE stamp prefix** `claugentic-dev-harness@<semver> managed — do not edit` (trailing clause version-variable; a REFRESH migrates it). Only **detection** loosens to the stable prefix — what `init` **writes** is unchanged (always the current full form). Both clobber-edge legs (path-in-the-managed-set + the full prefix on **line 1**; a bare token in prose doesn't match) stay mandatory — **never-clobber is not weakened.**

Per-repo editable content lives outside the fences. Source modules stay pristine — the stamp is added on copy. A subagent *can* read plugin-bundled files by absolute path; the install path is version-stamped.
- **Bundled agents are spawned by their namespaced id `claugentic-dev-harness:<role>`** via the `nsAgent` helper (engine `*.js`) + namespaced spawn directives (skills `SKILL.md`); bare names resolve only when dogfooded with project-local `.claude/agents/`, so installed adopters would crash at the first spawn. Built-ins (`general-purpose`, `Explore`, `Plan`) stay bare. A source-level test (`tests/workflows/agent-namespace.test.mjs`) pins it.

The `INCLUDE_GLOBS` widening to `:(glob)engine/**/*.js` is **this-repo-only** (init's body-compare excludes the `INCLUDE_GLOBS` line; adopters have no `engine/` dir).
- **`claugentic-check_architecture_tree.py` is the one hybrid managed file (`INCLUDE_GLOBS` carve-out).** Its `INCLUDE_GLOBS = [ … ]` assignment is the single per-repo knob (`init` writes it per-adopter, re-derives on drift). So `init`'s body-compare **excludes that assignment on both sides** (an adopter with custom globs reads `CURRENT` when the rest matches — no false REFRESH); a `REFRESH` **re-injects the adopter's existing globs** rather than resetting them.

Idempotency at a fixed version is **model-upheld, dogfood-checked, not a wired gate** — claimed as *"converges / true no-op only when already at the installed version,"* never *"provable/mechanical."*
