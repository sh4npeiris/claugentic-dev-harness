## Honesty positioning (the #1 rule)

- 2026-06-23: **The audit LEGEND no longer claims cross-model review (v0.2.1).** With no different-model judge available, the all-opus judges are same-model — yet the adopter-facing audit-backlog LEGEND (`engine/audit.js`) still said a finding was *"re-checked by a different model family than the builder,"* a live over-claim in the harness's own output. Reworded to the honest structural-independence framing (*"a separate clean-context agent that never saw the finder's reasoning — a reduction of rubber-stamping risk, not a mechanical guarantee"*); the dormant cross-model run-report branch reworded likewise; the `audit.test.mjs` drift-pins updated. The three-state disclosure machinery STAYS (it already degrades to the same-model floor) — only the over-claiming copy changed: it goes MORE honest, never re-asserts de-correlation (consistent with the INVARIANTS scrubbed-set).
- **Never let copy launder model judgment into apparent mechanical fact.** The current honest split: the **architecture-tree check is the only hook-enforced gate**; `check_versions_synced.py` + the test suite are **deterministic run-gates** (mechanical when run; running them is discipline); everything else — reviewer sign-offs, the diverse panel, the audit's finding re-checks, build mode's pauses — is **model-upheld** and said so.
- **Verb discipline:** the harness *"attempts to / tries to re-check"* and *"tags the outcome"* — never *"verifies / proven / arrives with proof / guaranteed."* Success claims are **dimension-scoped** (*"sound on the audited dimensions"*), never "bug-free/perfect."
- **The two senses of "independent":** claims of model-family independence about the judges are **forbidden** (same vendor → errors stay correlated; the honest claim is *"a different model family — a reduction of shared-blind-spot risk"*). The **structural** sense — clean-context input-contract isolation ("independently re-checks") — is accurate and **preserved**.
- **`[D]` vs `[J]`:** a deterministic-labeled check is only *proven* where the adopter has the relevant tool wired; otherwise it is reported as the model's judgment.

## The deterministic gates

- 2026-06-23: **Doc-budget gate rebalanced — WARN band + load-profile-aware caps (v0.2.1).** `check_doc_budgets.py` now emits a WARN at ≥90% of budget (`WARN_RATIO`, printed, exit 0) so a ledger signals BEFORE it hard-breaks the build (the prior handicap was a surprise breach at the ceiling with no warning). `DECISIONS.md`'s cap is raised 40K→60K because it is read ON-DEMAND (consulted before re-litigating a past choice), not always-loaded like `CLAUDE.md` (kept tight at 6K); ROADMAP stays 12K. The cap STAYS a forcing function — when the WARN fires, condense periodically (merge superseded entries to git history); never *remove* the limit (that removes the very trigger that makes condensation happen). Only a strict excess is a breach (exit 1); a WARN never changes the exit code.
- **One gate, one invariant (SRP siblings):** the tree-check owns the file index (presence · staleness · zero-coverage glob-drift); `check_versions_synced.py` owns the `plugin.json` ↔ `marketplace.json` version pair (the two stamps are one source of truth — every bump moves both). New mechanically-checkable invariants get a sibling script, not an extension.
- **Fail loud, never fail-open:** every gate errors plainly on broken input (missing/garbled files, empty globs) — a gate that silently passes on its own breakage is the forbidden failure class. All gates carry hermetic characterization tests; `python -m pytest` is a Definition-of-Done gate.
- **The tree-check is language-incidental** — harness tooling that never parses project source; it stays Python with `INCLUDE_GLOBS` as the **single per-repo knob** (the valid-extension set is derived from it). Glob-drift detection uses a stable `SOURCE_EXTS` allow-list + the managed-stamp exclusion — **no per-stack registry** (an always-incomplete list re-introduces the rot it claims to kill). Detection is mechanical; the glob *reset* is model-upheld (init's terminating self-correction).
- **The deterministic trust-gates for unwatched runs** (a land-gate hook · a secret-scan · a characterization-tests-first hook) are **not built** — and the harness says so rather than claiming them (asserting "cannot land red" before such hooks exist would be the over-claim the harness forbids); build-to-green is **a reduction of unwatched-run risk, never a substitute** for these unbuilt gates, and its decline names exactly which unlock conditions are unmet (see Build mode).

## The verify/judge roles (skeptical clean-context review)

- 2026-06-22: **Review is cross-review by separate specialist agents, each on the most capable available model; the `fable` cross-model override is removed and the different-model-line de-correlation claim is dropped.** `fable` (a different Anthropic model line) was the judge override for a weak cross-model de-correlation; it became unavailable and the property was always thin (same vendor). Now review is **cross-review by separate specialist agents** (distinct roles + clean contexts), each on the **most capable available model** — the independence is of context and role, NOT of model. Models are picked by capability **tier** via auto-resolving aliases (**most capable** `opus` · **mid/cheaper** `sonnet` · **fastest/cheapest** `haiku`), never a pinned version; default to the most capable model for anything needing judgment (incl. high-volume — **accuracy first, conservation second**), cheaper tiers only for mechanical work. Script runs pin `model: MODELS.judge` = the most-capable tier; prose runs use the agents' `model:` frontmatter. The `RUNNING AS:` / `sameModelTag` machinery stays as an honest per-run reporter. *(The engine `KNOWN_FAMILIES` + workflow-test fixtures still carry the inert `fable` token; fully removing the cross-model machinery is a deferred YAGNI cleanup.)*
- **Every judge opens with a `RUNNING AS:` self-report naming its model family** (never the vendor alone, never its role); the orchestrator compares it to the builder family and, on **any same-family run**, applies the verbatim tag: *"same-model review on this run — the judge and the builder are the same model family here."* On a spawn error: respawn with the default + the tag — a gate role never becomes unspawnable. The comparison is model-upheld and stated as such. (A present-but-unrecognized family is reported as *unresolved*, never asserted same-model fact — the conservative trust floor; the wording lives once in `engine/*.js`'s `sameModelTag` + the `KNOWN_FAMILIES` source, pinned by `tests/workflows/cross-script.test.mjs`.)
- **`finding-verifier` independence is structural:** it receives only `{claim, file:line, source module, confidence, exclude-set}` + a refute-first posture — never the finder's rationale; a lens never verifies its own finding.

## The audit (`/claugentic-dev-harness:audit`)

- **One thoroughness slider, three notches** (`quick` · `standard` · `thorough`), one uniform pipeline at every notch: **FIND → PRUNE → VERIFY → surface.** All relevant lenses run at *every* level — a lens is never dropped to make a level cheaper; the slider sets the **depth** each lens reads at (`focused` → `deep` → `exhaustive`). `thorough` (named-only, never auto-picked) additionally runs the **blind-spot sweep** (`blindspot-reviewer` — the cross-cutting risk no single module-lens owns) and an **adversarial `yagni-sentinel` prune**; those are what FIND and PRUNE look like at max, not bolt-ons.
- **The re-check is universal:** after the prune, the audit attempts to refute **every surfaced finding, all tiers, every level** (one `finding-verifier` per finding). Every backlog item shows one verification tag; the legend carries the not-a-mechanical-guarantee caveat. A re-found false positive is still false — repeats can't substitute for adversarial re-checking, so identical re-sweeps were retired (**single look per `(module × dir)` cell**); recall rests on lens breadth + depth, honestly stated.
- **Deterministically bounded + resumable:** a finite cell set, one shared backstop `max-cells-per-run` cap (bounds cost and the orchestrator's synthesis context — not per-agent context), `PARTIAL` checkpoints with explicit done/pending cell lists. Findings are never count-capped or silently truncated.
- **Fences are regenerate-don't-accumulate:** the `harness-audit:overview` / `harness-audit:backlog` fences are replace-only-inside, human-owned outside; **no script-generated noise inside a fence** (byte-identical re-runs apart from the orchestrator-stamped audit date); all narration stays conversational. **"Sound on the audited dimensions"** is the explicit terminal signal when Tier 1+2 come back empty — a stop signal, not a treadmill.
- **Two backlog fences, each regenerate-independently (engineering + product):** the engineering audit writes `harness-audit:backlog`; product gap mode writes its **own** `harness-product:backlog` — running one **never** touches the other (the split fixes the cross-contamination where a `build` re-audit wiped the product backlog). The **renderer is reused, not forked** — both fences carry the same `renderBacklogFence` body (the criteria args-mode of `engine/audit.js`); only the target marker differs (DRY). The product fence is a **re-derivable projection of the spec against current code** (it regenerates, symmetric with the engineering fence as a projection of code against standards) — the **durable** product layer is `docs/claugentic-PRODUCT_SPEC.md` + the human-owned ROADMAP area, **not the fence**. **Cross-fence dedup is model-upheld at `build` triage**, deliberately not mechanical: the two backlogs key findings in **different namespaces** (engineering code-location/`module×dir` vs product criterion-ids), so a mechanical key-match could never fire on a real overlap (overlap is inherently semantic) — model-upheld triage-dedup is the **only coherent** design, not a lazy deferral. Product is **backlog-only — no product `overview` fence** (deliberate asymmetry: the engineering `harness-audit:overview` stays the single repo overview).
- **Stage-9 lesson — fence-conventions are paired-or-explicitly-not:** a singular-"the backlog"/"the fence" assumption had leaked into PLAYBOOK + init + build-resume copy. Any future fence addition must check **every** singular "the backlog"/"the fence" reference and either pair it or record the asymmetry on purpose.
- **The "Application source present" predicate is defined once** (audit Phase 1) and reused by `init` — a repo of only docs/config/harness scaffolding is "no application source" (the new-project on-ramp, not an audit target).
- **The eval (`eval/`) is a seeded-defect drift detector, not a quality guarantee.** `eval/BASELINE.md` is the single source of truth for the measurement procedure; the intentional seeded defects (`eval/fixture-defects/app/` for the standard audit, `eval/fixture-app/` for the QA run) **MUST NOT be "fixed"** — fixing them disarms the exam. The no-peeking contract (the answer keys stay outside the run's scope) is **prompt-scoped + canary-backstopped**, never a filesystem sandbox; `eval/` is repo-local, never copied to adopters.
- 2026-06-22: **The rejected-findings memory — a dropped audit finding stays dropped (plan 0021, restored).** When a user judges a surfaced finding wrong, the dismissal is recorded in a `<!-- harness-audit:rejected-findings -->`-fenced list in `docs/claugentic-ROADMAP.md`, **mirroring product spec mode's `<!-- product-critic:rejected-proposals -->` convention exactly** (same shape, reused): create-on-first-use, one terse line per dropped finding, never stamped, user-owned, and **OUTSIDE** the regenerate-don't-accumulate `harness-audit:backlog` fence so a re-audit never wipes it. `audit` (Phase 3) and `build` (triage + scoped/closing re-audit) **read the fence before rendering and skip any listed finding** — the same way `product-critic` never re-pitches a rejected idea. It is a **user override of model judgment, not a deletion of evidence**: the user can clear a line when the code genuinely changes; the harness never silently second-guesses a recorded dismissal.

## Build mode (`/claugentic-dev-harness:build`)

- **A thin orchestration layer** over the WORKFLOW pipeline + the audit's backlog — no new pipeline, agents, or state stores. The plain-English ask is the interface; a single named item is the fast path (no triage ceremony).
- **Checkpoint is the default rung:** three routine per-item pauses — the spec before any code · before land · before anything irreversible — plus exception pauses (re-slice, item-failure with *"nothing partial landed"*, re-triage). **Build-to-green is the requestable rung:** eligibility = three unlock conditions checked as judgment-with-stated-evidence (CI runs the gates · a test baseline for the touched code · an approved spec with testable acceptance criteria) **plus** script-only execution (`engine/build-item.js` — never a prose loop); unmet → a verbatim decline naming exactly what's missing, then checkpoint is offered. The cross-model judge is wired but is a risk reduction, not a guarantee.
- **The build-to-green engine (`engine/build-item.js`) contains no push/merge/land/git step by construction** — every terminal status is a return-to-orchestrator (`green` → the before-land pause is the orchestrator's; `needs-irreversible`; `new-tier12` → re-triage, never folded silently; `not-green` at the cap → "not green; here is the residual", nothing partial landed; `blocked`). It iterates implement (`implementer-architect` in a worktree) → deterministic gates (an agent runs the gate commands; the pass/fail *decision* over the reported exit codes is the mechanical part — `gatesGreen`, never fail-open) → the Verify panel (the `engine/verify.js` child workflow) → QA (`engine/qa.js`, when machine-checkable criteria exist) → fix, until green or the iteration cap.
- **The irreversible hard-stop set** (push to a shared remote **including `main`** — this repo admin-bypasses branch protection — deploy, data deletion, spend, external side-effects): stop, name the action + consequence, ask; never proceed on silence. **Never invent scope** — a discovered feature goes to the roadmap, not into the worklist.
- **The loop:** confirmed ordered worklist → per-item engine → a **scoped re-audit over the touched `(module × dir)` cells** after each landed item (file-level; cross-file fallout is owned by the closing full audit — the harness has no dependency graph and claims none) → **re-triage on any new Tier-1/2** (the chosen safety-over-fatigue trade) → one `standard` closing audit → the terminal signal.
- **Resume derives, never stores:** the worklist reconstructs from **both backlog fences** (engineering + product) + plan files (`Spec'd` = awaiting a sitting · `Approved` = build when reached · unchecked boxes = in-flight, possibly several · removed at Land = done, git history keeps it); the picked *order* is re-confirmed (a 5-second re-confirm beats a third state store). **Approval is never inferred** — only an explicit `Status: Approved` counts.
- **Batch spec-approval is a requestable ask** (*"spec everything first"*), not a standing question — a passive tip line is the only as-we-go addition. The sitting is **roster-first** (a scannable one-line roster; full triads beneath to drill into; approve/adjust/drop, drop unjudged) — the defense against relocating decision-fatigue inside the sitting. Interruption-honesty at the ask **and echoed at the sitting close** (what batch does *not* remove); the sunk-cost fact once, neutrally; a **file-level spec-currency check** before each item pauses to re-confirm if landed work touched the spec's named files.

- 2026-06-22: **Both gate scripts now self-anchor to their own repo root at runtime — CWD-independent, completing the hook fix below (v0.1.40).** The `${CLAUDE_PROJECT_DIR}` command fix (next entry) made the hook *find/launch* the right script, but the script's INTERNAL path logic was still CWD-relative: `TREE_PATH`, every `_git` call, and the staleness `Path.exists()` all resolved against the process CWD. A Stop hook launches the gate from a directory that isn't the repo root → `TREE_PATH.exists()` is False → `evaluate()` short-circuits to "… is missing" (false red); worse, if the CWD is inside a *different* git repo, `git ls-files` silently scans the wrong repo. **Fix:** a `_repo_root()` helper derives the root from the script's own `__file__` (git `rev-parse --show-toplevel` anchored to the script dir, with a `<script_dir>/..` fallback — **never** an absolute or hardcoded path, so it's portable across machines/adopters), and `main()` does `os.chdir(_repo_root())` at the entry boundary (covers `--hook`/`--hook-write`/plain — all route through `main()`). All existing relative logic then resolves correctly with no other edits, and **all user-facing output stays repo-relative** (`TREE_DISPLAY` + git-emitted paths unchanged → no machine-path leak). Applied identically to **both** `claugentic-check_architecture_tree.py` (copied to adopters) and `check_versions_synced.py` (harness-self gate); the `_repo_root` helper is duplicated, not shared — the copied gate can't import a harness-repo module, so each script is independently self-contained (DRY-across-deploy-boundaries doesn't apply). Secondary fix in the same pass: `_force_utf8_output()` reconfigures stdout/stderr to UTF-8 so the em-dash in messages stops mojibaking to `�` on Windows (cp1252 stdout decoded as UTF-8 by the hook consumer). Regression tests lock CWD-independence (run from outside the repo root + from inside an unrelated git repo → still correct) and the no-absolute-path-leak invariant. `_repo_root` is the monkeypatch seam the test fixtures pin so `main()`'s chdir stays in the scratch repo.
