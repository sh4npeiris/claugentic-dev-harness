# Honesty positioning (the #1 rule)

Part of the decisions ledger — index & filing rule: `docs/claugentic-DECISIONS.md`. Do not link this file from outside the index.

- **Never let copy launder model judgment into apparent mechanical fact.** The core rule everything else serves. The honest enforcement split: the **architecture-tree and doc-budget checks are the hook-enforced pair** — but only **where the pre-commit wrapper is wired** (a gate-off repo, or a machine with no working Python, has neither; 0041 S7); `check_versions_synced.py` + `check_shipped_content.py` + the test suite are **deterministic run-gates** (mechanical when run; running them is discipline); everything else — reviewer sign-offs, the diverse panel, the audit's finding re-checks, build mode's pauses — is **model-upheld** and must say so.
- **Verb discipline:** the harness *"attempts to / tries to re-check"* and *"tags the outcome"* — never *"verifies / proven / arrives with proof / guaranteed."* Success claims are **dimension-scoped** (*"sound on the audited dimensions"*), never "bug-free / perfect."
- **The register attaches to the surface that ASSERTS a capability — not to every sentence that instructs or commits to one** (0041 S8, 2026-08-17). A *description* of what the harness does (a skill's `description:`, a manifest, a README headline) carries its register **at the claim**: `/build`'s "it stops before anything irreversible" now reads "*(a discipline this skill instructs — model-upheld, never a mechanical gate)*". An *imperative* ("stop, name the action, ask") and the agent's own mid-run *commitment* to the user ("anything irreversible still stops") cannot launder judgment into mechanism — they enact the rule, so the register belongs on the rule's authoritative statement (`skills/build/SKILL.md` → *Guardrails*, pointing at WORKFLOW → *Decision-gated autonomy*). So: hedge every new assertion; do **not** re-sweep instruction/commitment copy. **And SPLIT a part-mechanical register, never blanket-hedge (R2-c):** `engine/audit.js`'s pitch reads *"pause points the engine enforces; judging "irreversible" is model-upheld"* — a blanket *model-upheld* tag would under-claim real mechanism, which misdescribes the wiring exactly as over-claiming does.
- **Over-scoped claim + out-of-scope siblings → DELETE the quantifier, don't add the caveat** (0041 S8 R2-a, 2026-08-17). README's "run on every commit" was falsified by the unwired `pre-merge-commit`; both lenses prescribed a merge caveat, the adjudicated fix was "run at commit time" — a caveat at one surface contradicts the five unswept sibling *every commit* sites, a non-quantified surface cannot. Operational form lives in `honesty-reviewer.md` (Method 4).
- **Check a claim from the surface that MAKES it, not just the referenced body.** A **capability / feasibility** claim (*"X calls Y", "zero change needed", "reachable from here"*) is only honest if the **caller** (a prose SKILL · a sandboxed engine script · an adopter's layout · the runtime) can actually reach and perform it; confirming the referenced implementation *exists and behaves* is **not** enough. **Fix (model-upheld, not a gate):** `honesty-reviewer.md` traces a feasibility claim to its caller; `lens-reviewer`/`synthesizer-gate` inherit it. A single CLEAN on a feasibility/trust claim is weaker than a second adversarial re-check — for a claim that *overturns* or *rests on* a prior reviewer's ground-truth, re-review rather than trust one pass.
- **The two senses of "independent":** claims of model-family independence / de-correlation about the judges are **forbidden** (same vendor → errors stay correlated; the honest claim is *"a different model family — a reduction of shared-blind-spot risk, NOT a guarantee"*). The **structural** sense — clean-context input-contract isolation ("independently re-checks") — is accurate and **preserved**. See INVARIANTS → the scrubbed-file set, which pins this in the files that must never regain the claim.
- **`[D]` vs `[J]`:** a deterministic-labeled check is only *proven* where the adopter has the relevant tool wired; otherwise it is reported as the model's judgment.
- The adopter-facing audit-backlog LEGEND must use the honest structural-independence framing (*"a separate clean-context agent that never saw the finder's reasoning — a reduction of rubber-stamping risk, not a mechanical guarantee"*), never the cross-model de-correlation copy. The three-state disclosure machinery STAYS (it degrades to the same-model floor); over-claiming copy is forbidden — it goes MORE honest, never re-asserts de-correlation. The same copy also lives in the dormant cross-model run-report branch in `engine/audit.js` (test-pinned) — change both together.
- **In the run-level cross-model fold, absence is a shorter ARRAY — never a null ENTRY** (0041 S10a D2, 2026-08-17). `engine/build-item.js`'s three call sites push an explicit `null` to mean *"this child ran and did NOT confirm a different family"*; `crossModelClaim` filtered nulls out, so one confirming family beside a deliberate non-confirming null reported **`confirmed`** — an over-claimed cross-model review on the disclosure surface. `sameModelTag()` already maps null/empty to the conservative floor, so the fix is to **drop the filter**, not to special-case. **Never re-add a filter over `judgeFamilies`:** a child that did not run contributes nothing by pushing nothing.
- **A published FIGURE is a claim — measured once, propagated, never re-typed (0041 S12a, 2026-08-18).** A relocation published an underivable **6,037 B** to `CHANGELOG.md` and to a permanent shard while the commit message carried the measured **5,785**: the honest number existed and did not reach the published surfaces. Precision is itself a claim of measurement, so a figure with no stated method or boundary (base · head · merge tree) cannot be adjudicated by anyone.
