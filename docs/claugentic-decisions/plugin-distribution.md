# Plugin identity & distribution

Part of the decisions ledger — index & filing rule: `docs/claugentic-DECISIONS.md`. Do not link this file from outside the index.

- **The marketplace plugin `source` MUST be the documented object form `{ "source": "github", "repo": "<owner/repo>", "ref": "release" }` to pin the release branch — never the `"owner/repo@release"` string.** The `@ref` shorthand is valid ONLY on the `/plugin marketplace add <owner/repo@ref>` command, never as a plugin-entry `source` value; the string form makes Claude Code reject the plugin as an unsupported source type — an **uninstallable-plugin** regression (the v0.2.4 fix). A test pins the object form so it can't regress.
- **Plugin id `claugentic-dev-harness`**; skills `init` · `audit` · `build` · `product` · `doctor` · `condense`; install via `/plugin marketplace add sh4npeiris/claugentic-dev-harness` → `/plugin install claugentic-dev-harness@sh4npeiris`. Public, **Apache-2.0**.
- **Every harness-owned adopter-facing file carries a uniform `claugentic-` filename prefix in source AND adopters** (managed docs, the standards catalog, the tree-gate script are **born prefixed**) — so an adopter's own conventionally-named files can never collide, and skills/engines reference one set of names (`init` copies path-for-path, no transform). **Plugin-internal files stay clean** (`engine/*.js`, `.claude/agents/*`, in-flight plan FILES, `scripts/check_versions_synced.py`, `docs/RELEASE_CHECKLIST.md` — read-from-install / never-copied, no collision surface). `TREE_PATH` is a **fixed constant**; `INCLUDE_GLOBS` is the only per-repo knob. **Any new managed file must be born prefixed** — a managed file's name is part of its contract.
- **Managed-stamp + fences + the genuine-managed predicate.** Every copied file carries a first-line version-stamped managed stamp; stable HTML-comment fences mark replace-only-inside regions (the adopter's CLAUDE.md `harness:managed` block; the audit's ROADMAP fences) — per-repo editable content lives outside the fences, source modules stay pristine (the stamp is added on copy). **The genuine-managed predicate keys on the STABLE stamp prefix** `claugentic-dev-harness@<semver> managed — do not edit` (trailing clause version-variable). Only **detection** loosens to the stable prefix — what `init` **writes** is unchanged (always the current full form). Both clobber-edge legs (path-in-the-managed-set + the full prefix on **line 1**; a bare token in prose doesn't match) stay mandatory — **never-clobber is not weakened.**
- **Bundled agents are spawned by their namespaced id `claugentic-dev-harness:<role>`** via the `nsAgent` helper (engine `*.js`) + namespaced spawn directives (skills `SKILL.md`); bare names resolve only when dogfooded with project-local `.claude/agents/`, so installed adopters would crash at the first spawn. Built-ins (`general-purpose`, `Explore`, `Plan`) stay bare. A source-level test pins it.
- **`plugin.json`'s `agents` array stays EXPLICIT (all 9 listed) — a footgun to preserve, NOT "simplify" (0036).** An explicit array **replaces** (does not augment) Claude Code's default `.claude/agents/` auto-scan, so dropping/mis-editing it silently excludes an agent — keep it explicit and complete. **Authoring-audit outcome (0036 — do-not-re-litigate):** a self-authoring audit vs the real Claude Code docs found the harness **strongly aligned** and **refuted 5 of 6 surfaced gaps**; the one survivor (adopter tree-gate-timing note) landed as a PLAYBOOK edit.
- **Engine scripts (`engine/*.js`) distribute by read-from-install-path, never copied.** Adopters invoke `${CLAUDE_PLUGIN_ROOT}/engine/<name>.js` — a runtime artifact read in place (no managed-stamp, no refresh surface); dogfooding uses the repo-local copy. **The dir is named `engine/`, not `workflows/`, specifically so Claude Code doesn't auto-register the scripts as `[dynamic workflow]` slash-commands** (an undocumented behavior of a plugin-root `workflows/` dir). The `INCLUDE_GLOBS` widening to `:(glob)engine/**/*.js` is **this-repo-only** (adopters have no `engine/` dir).
- **Engine scripts are ASCII-only (plan 0029 → 0.3.1).** `engine/*.js` must carry no non-ASCII codepoint: a strict adopter permission handler rejects non-ASCII as "control characters" and silently demotes the engine path to prose-fallback. The audit **cell-key delimiter (`|`)** and **status-line separator (` - `)** are LOAD-BEARING (parsed/round-tripped through the audit resume contract) — any change is atomic across producer/parser/serializer/SKILL-resume/tests. Mechanically guarded by `check_shipped_content.py` Pass C (HARD, exact codepoint check over shipped `*.js`). Honest scope: Pass C is exact/mechanical but does not make the whole release/init contract fully content-enforced.
- **`claugentic-check_architecture_tree.py` is the one hybrid managed file (`INCLUDE_GLOBS` carve-out).** Its `INCLUDE_GLOBS = [ … ]` assignment is the single per-repo knob (`init` writes it per-adopter, re-derives on drift). So `init`'s body-compare **excludes that assignment on both sides** (an adopter with custom globs reads `CURRENT` when the rest matches — no false REFRESH); a `REFRESH` **re-injects the adopter's existing globs** rather than resetting them.
- **`init` is version-aware, codebase-agnostic, and non-destructive (upsert-to-installed, RESTAMP-free, prose-decided).** Re-running converges the repo to the installed version: each managed file is `CREATE`/`REFRESH`/`CURRENT`/`USER_FILE` by `init`'s judgment (genuine-managed predicate; stop-if-ambiguous; no oracle script). Content-identical copies stay byte-untouched (**no RESTAMP**). **Per-file upsert only — `init` never deletes.** No 3-way merge of a user-edited managed file (installed wins, git is the recovery net); user-owned docs stay create-if-absent. Idempotency at a fixed version is **model-upheld, dogfood-checked, not a wired gate** — claimed as *"converges / true no-op only when already at the installed version,"* never *"provable."*
- **Tree provisioning is scenario-based (the codebase-agnostic on-ramp):** FRESH (no tree, no source) → minimal tree + gate ON; MATURE-NO-TREE → a **cheap-complete skeleton** (`git ls-files` ∩ globs → one `- \`path\`` line per file, path-derived one-liner, **no per-file content reads**) + gate ON; MATURE-WITH-TREE → a **two-option prompt** (Replace / Keep-mine-gate-off). **Hooks are wired only when the tree-gate is ON.** **Skeleton format is dictated** — markdown headings + backtick-prose `- \`path\`` lines, **NEVER ` ``` `-fenced** (a fence is stripped and desyncs presence-matching). Brace-glob / ASCII-diagram parsing is deferred (YAGNI).
- **Gate-off ⇒ `INCLUDE_GLOBS = []` is adopter-owned.** A re-`init` **must NOT re-derive globs** for a `keep-gate-off` repo (else the gate silently turns back on against the locked choice). The choice is recorded as a single `- Architecture tree:` line (keyed on the label), read **before** the prompt. **Exactly one such line exists at all times** — appended on first write, then **rewritten in place** only when on-disk tree state forces a different outcome (**on-disk wins**); a settled re-run rewrites nothing. This is the **only** recorded-choice line that gets rewrite-on-override (the `Run the app:` line stays append-once).
- **Replace is a confirmed user-file overwrite, git-recoverable only.** The mature-with-tree "Replace with a harness skeleton" option is the only `init` path that overwrites a user-owned file; it proceeds **only** on explicit AskUserQuestion confirmation — never on silence/default/timeout/unavailable (those fall back to Keep-mine-gate-off). Stage-9 names it: *"your previous tree is in git history (uncommitted is unrecoverable)."*
- **Non-destructive adoption — authority-via-CLAUDE.md replaces deletion.** The managed fence carries a static **authority + conflict-resolution clause** (harness docs authoritative; other `.md` are project/domain content not process authority; harness wins on conflict; follow-the-harness-and-ask when unsure) — framed **honestly as model-upheld** (no mechanical file-hiding; `CLAUDE.md` is the always-loaded anchor + "ask" is the valve). `init` **surfaces** a competing way-of-work doc via a high-precision **name** allow-list (non-managed `WORKFLOW.md`-class, `.cursorrules`, `AGENTS.md`, etc.; **`CLAUDE.md` never flagged**) and offers **harvest / leave** — **never delete**. Recorded via one reviewed-line → no re-prompt.
- **Managed docs are adopter-aware.** Copied WORKFLOW/PLAYBOOK/standards-README must not carry harness-self references that read as broken in an adopter: the DoD's **deterministic gates** mean the adopter's OWN lint/type/test (not the harness self-test); `.claude/agents/` + `engine/*.js` are **plugin-resident** (resolved at spawn/run, not repo-local dirs); standards modules are **editable source** in the plugin but **managed copies** in an adopter (edit the plugin, re-init to propagate); the tree-check is hook-wired only when the gate is on; `load_scope.globs` is **advisory**. Fix at SOURCE so re-init propagates the corrected copies.
- **`init` seeds the harness's plugin self-reference into the adopter's committed `.claude/settings.json`** — `extraKnownMarketplaces` + `enabledPlugins` + a `!.claude/settings.json` gitignore negation if needed (never un-ignoring `settings.local.json`). A cloned adopter repo then prompts teammates to install the harness (closes the team-distribution gap). Never-clobber; runs regardless of the tree-gate.
- **`init` requires no "fresh chat."** Claude Code **hot-reloads `.claude/settings.json`**, so the tree hook enforces the moment `init` writes it. `CLAUDE.md` is read once at session start (a skill can't force a re-read), so new harness instructions load on `/clear`/`/compact`/next-session. `init` **adopts the workflow in-session** and **suggests** `/clear` for the cleanest standing setup, **never mandating a restart**.
- **The bundled SessionStart advisor hook uses a portable `python3 … || python …` launcher** so the greeting fires on python3-only machines. Safe **only because the advisor is fail-safe (always exit 0)** — the `||` fallback never double-fires on a real error. The tree-check hook stays a wrapper that resolves `python3 || python` once and **probes** it (0041 S5): the gate's exit code propagates, while **infrastructure failure passes by design** — missing/broken interpreter or missing gate script loudly (one stderr line), broken git silently. **All hook commands use the rooted form — `${CLAUDE_PROJECT_DIR}`-rooted (adopter tree-check) / `${CLAUDE_PLUGIN_ROOT}`-rooted (bundled advisor) — never a bare relative path** (hook cwd is not guaranteed to be the repo root).
- **Advisor off-switch + nuanced audience-split** (0024 S3; grown 0041 S3): `CLAUDE_HARNESS_ADVISOR=off` mutes the advisor to `{}` (fail-safe to silent), read at the env boundary so the renderer stays PURE (dependency-inversion — it takes an `enabled` flag, never reads the env). Audience-split: agent-facing `additionalContext` (with its disclaimer) fires ONLY on the in-flight-plan **resume** branch and is built from the recommendation ALONE; the promotional nudges (open-backlog / PARTIAL-rerun / no-product-spec) **and the 0041-S3 currency clauses** (docs-behind-plugin skew · landed/cold plan count) are user-facing `systemMessage`-ONLY. Currency mechanics (0041 S3, all deliberate): the plugin-version read is **`__file__`-anchored, never the CWD** (an adopter repo has no `.claude-plugin/`) · `COLD_DAYS = 30` is a **constant, not config** (YAGNI) · the version compare is numeric-segments-only and **skips rather than guesses** on any other form (a false "you are stale" costs trust) · on an over-cap line the clause budget is **reserved** — the ellipsis lands in the resume summary, never on a clause.
- **Adopter build-scanner incident (data-insights-hub, 2026-07; recorded 0041 S5).** A build-time content scanner with broad globs (Tailwind `content`) ingested the managed `docs/` and crashed the adopter's build. `init`'s report carries a prose caution naming the class (Tailwind/UnoCSS globs · docs indexers · SSG/codegen over `**/*.md`) — exclude `docs/`. Deliberately prose; no config-sniffing (YAGNI).
