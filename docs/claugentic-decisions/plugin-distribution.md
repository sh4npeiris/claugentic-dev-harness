# Plugin identity & distribution

Part of the decisions ledger — index & filing rule: `docs/claugentic-DECISIONS.md`. Do not link this file from outside the index.

- **The marketplace plugin `source` MUST be the object form `{ "source": "github", "repo": "<owner/repo>", "ref": "release" }` to pin the release branch — never the `"owner/repo@release"` string.** `@ref` is valid ONLY on the `/plugin marketplace add` command; as a `source` value it makes Claude Code reject the plugin as an unsupported source type — an **uninstallable-plugin** regression. Test-pinned.
- **Plugin id `claugentic-dev-harness`** — public, **Apache-2.0**; skill + agent roster in `.claude-plugin/plugin.json`, install steps in `README.md`.
- **Every harness-owned adopter-facing file is BORN with the `claugentic-` filename prefix, in source AND in adopters**: an adopter's own conventionally-named files can never collide, and skills/engines reference one set of names (`init` copies path-for-path, no transform). **Plugin-internal files stay clean** (`engine/*.js`, `.claude/agents/*`, plan FILES, harness-self scripts/docs — read-from-install / never-copied, no collision surface). `TREE_PATH` is a **fixed constant**; `INCLUDE_GLOBS` is the only per-repo knob. A managed file's name is part of its contract.
- **Managed-stamp + fences + the genuine-managed predicate.** Every copied file carries a first-line version-stamped managed stamp; stable HTML-comment fences mark replace-only-inside regions (CLAUDE.md's `harness:managed` block; the audit's ROADMAP fences) — editable per-repo content lives outside them; source modules stay pristine (stamp added on copy). **Detection keys on the STABLE stamp prefix** `claugentic-dev-harness@<semver> managed — do not edit` (trailing clause version-variable); what `init` **writes** is always the current full form. Both clobber-edge legs — path-in-the-managed-set AND the full prefix on **line 1** (a bare token in prose doesn't match) — stay mandatory: **never-clobber is not weakened.**
- **Bundled agents spawn by their namespaced id `claugentic-dev-harness:<role>`** (`nsAgent`) — bare names resolve only in a project-local `.claude/agents/` dogfood. **Namespaced is what we WRITE — since 0041 S10b, not the only id TRIED:** an **engine** spawn that *throws* retries ONCE bare (name derived, never a literal); a namespace retry is never a model respawn. Built-ins (`general-purpose`, `Explore`, `Plan`) stay bare; tests pin both ids.
- **`plugin.json`'s `agents` array stays EXPLICIT and COMPLETE — a footgun to preserve, NOT "simplify" (0036).** An explicit array **replaces** (does not augment) Claude Code's default `.claude/agents/` auto-scan, so dropping or mis-editing an entry silently excludes that agent. (0036 also audited the harness against the real Claude Code docs and found it strongly aligned — **do-not-re-litigate**.)
- **Engine scripts (`engine/*.js`) distribute by read-from-install-path, never copied** — adopters invoke `${CLAUDE_PLUGIN_ROOT}/engine/<name>.js`, a runtime artifact read in place (no managed-stamp, no refresh surface); dogfooding uses the repo-local copy. **The dir is named `engine/`, not `workflows/`, specifically so Claude Code doesn't auto-register the scripts as `[dynamic workflow]` slash-commands** (an undocumented `workflows/`-dir behavior). The `:(glob)engine/**/*.js` globs widening is **this-repo-only**.
- **Engine scripts are ASCII-only (0029).** `engine/*.js` must carry no non-ASCII codepoint: a strict adopter permission handler rejects non-ASCII as "control characters" and silently demotes the engine path to prose-fallback. Guarded by `check_shipped_content.py` Pass C — exact and mechanical over shipped `*.js`, while the wider release/init contract stays un-enforced. The audit cell-key delimiter's own must-hold lives in `docs/claugentic-INVARIANTS.md`.
- **`claugentic-check_architecture_tree.py` is the one hybrid managed file.** Its `INCLUDE_GLOBS` assignment is the single per-repo knob (`init` writes it per-adopter, re-derives on drift), so `init`'s body-compare **excludes that assignment on both sides** (custom globs still read `CURRENT` — no false REFRESH) and a `REFRESH` **re-injects the adopter's existing globs** rather than resetting them.
- **`init` is version-aware, codebase-agnostic, non-destructive (upsert-to-installed, RESTAMP-free, prose-decided).** Re-running converges the repo to the installed version: each managed file is `CREATE`/`REFRESH`/`CURRENT`/`USER_FILE` by `init`'s judgment (genuine-managed predicate; stop-if-ambiguous; no oracle script). Content-identical copies stay byte-untouched (**no RESTAMP**). **Per-file upsert only — `init` never deletes.** No 3-way merge of a user-edited managed file (installed wins; git is the recovery net); user-owned docs stay create-if-absent. Idempotency at a fixed version is **model-upheld, dogfood-checked, not a wired gate** — say *converges*, never *provable*.
- **Tree provisioning is scenario-based (the codebase-agnostic on-ramp):** FRESH → minimal tree + gate ON; MATURE-NO-TREE → a **cheap-complete skeleton** (`git ls-files` ∩ globs, path-derived one-liners, **no per-file content reads**) + gate ON; MATURE-WITH-TREE → a **two-option prompt** (Replace / Keep-mine-gate-off). **Hooks are wired only when the tree-gate is ON.** **Skeleton format is dictated** — markdown headings + backtick-prose `- \`path\`` lines, **NEVER ` ``` `-fenced** (a fence is stripped and desyncs presence-matching). Brace-glob / ASCII-diagram parsing deferred (YAGNI).
- **Gate-off ⇒ `INCLUDE_GLOBS = []` is adopter-owned.** A re-`init` **must NOT re-derive globs** for a `keep-gate-off` repo (else the gate silently turns back on against the locked choice). The choice lives in **exactly one** `- Architecture tree:` line, read **before** the prompt — appended on first write, then **rewritten in place** only when on-disk tree state forces a different outcome (**on-disk wins**); a settled re-run rewrites nothing. It is the **only** recorded-choice line with rewrite-on-override (`Run the app:` is append-once).
- **Replace is a confirmed user-file overwrite, git-recoverable only.** The mature-with-tree "Replace with a harness skeleton" option is the only `init` path that overwrites a user-owned file: it proceeds **only** on explicit AskUserQuestion confirmation — never on silence/default/timeout/unavailable (those fall back to Keep-mine-gate-off) — and Stage-9 says so (*"uncommitted is unrecoverable"*).
- **Non-destructive adoption — authority-via-CLAUDE.md replaces deletion.** The managed fence carries a static **authority + conflict-resolution clause** (harness docs are process authority, other `.md` is project/domain content; harness wins on conflict; ask when unsure), **honestly model-upheld** — no mechanical file-hiding; `CLAUDE.md` is the always-loaded anchor and "ask" is the valve. `init` **surfaces** a competing way-of-work doc via a high-precision **name** allow-list (non-managed `WORKFLOW.md`-class, `.cursorrules`, `AGENTS.md`; **`CLAUDE.md` never flagged**) and offers **harvest / leave** — **never delete**. One reviewed-line record → no re-prompt.
- **Managed docs are adopter-aware.** Copied WORKFLOW/PLAYBOOK/standards-README must carry no harness-self reference that reads as broken in an adopter: the DoD's **deterministic gates** mean the adopter's OWN lint/type/test; `.claude/agents/` + `engine/*.js` are **plugin-resident**; standards modules are **editable source** in the plugin but **managed copies** in an adopter; the tree-check is hook-wired only when the gate is on. Fix at SOURCE so re-init propagates. **Shipped ROLE FILES and SKILLs read in the adopter's frame too** — state a premise **inline**, never pointing at a `CLAUDE.md`/ledger section the reader's repo may not have (0041 S9).
- **A shipped skill never hands the reader a `.claude/agents/<role>.md` path** (2026-08-19). The harness's agents are **plugin-resident** — an adopter's repo has no such file, so the pointer dangles for exactly the person the skill is written for; name the role by its `claugentic-dev-harness:<role>` id, which resolves for them. **Closure is the retired STRING, never a site list** (the first sweep missed sites a refuter then found): `grep -rn '\.claude/agents/' skills/` must return only `skills/doctor/SKILL.md`'s already-caveated harness-self line(s) — two at closure, one since the 2026-08-19 thinning de-duplicated a sibling (strictly tighter). `README.md` documents the plugin's own structure — deliberately out of scope.
- **`init` seeds the harness's plugin self-reference into the adopter's committed `.claude/settings.json`** — `extraKnownMarketplaces` + `enabledPlugins` + a `!.claude/settings.json` gitignore negation if needed (never un-ignoring `settings.local.json`), so a cloned adopter repo prompts teammates to install the harness. Never-clobber; runs regardless of the tree-gate.
- **`init` requires no "fresh chat."** Claude Code **hot-reloads `.claude/settings.json`**, so the tree hook enforces the moment `init` writes it; `CLAUDE.md` is read once at session start (a skill can't force a re-read), so new harness instructions load on `/clear`/`/compact`/next-session. `init` adopts the workflow in-session and **suggests** `/clear`, **never mandating a restart**.
- **The bundled SessionStart advisor hook uses a portable `python3 … || python …` launcher** so the greeting fires on python3-only machines — safe **only because the advisor is fail-safe (always exit 0)**, so the `||` fallback never double-fires on a real error. The tree-check hook instead resolves `python3 || python` once in a wrapper and **probes** it (0041 S5): the gate's exit code propagates, while **infrastructure failure passes by design** — missing/broken interpreter or missing gate script loudly (one stderr line), broken git silently. **All hook commands use the rooted form** — `${CLAUDE_PROJECT_DIR}` (adopter tree-check) / `${CLAUDE_PLUGIN_ROOT}` (bundled advisor), never a bare relative path (hook cwd is not the repo root).
- **Advisor off-switch + audience-split** (0024 S3; grown 0041 S3): `CLAUDE_HARNESS_ADVISOR=off` mutes the advisor to `{}` (fail-safe to silent), read at the env boundary so the renderer stays PURE (it takes an `enabled` flag). Agent-facing `additionalContext` fires ONLY on the in-flight-plan **resume** branch and is built from the recommendation ALONE; every promotional and currency nudge is user-facing `systemMessage`-ONLY. Currency mechanics in `scripts/claugentic-session-advisor.py` are deliberate: the plugin-version read is **`__file__`-anchored, never the CWD** (an adopter repo has no `.claude-plugin/`) · the compare **skips rather than guesses** on any non-numeric form (a false "you are stale" costs trust) · `COLD_DAYS` stays a constant, not config (YAGNI).
- **Broad build-time content globs must exclude the managed `docs/`** (adopter incident 2026-07; 0041 S5): a scanner with Tailwind-`content`-class globs ingested the managed docs and crashed the adopter's build. `init`'s report carries a prose caution naming the class (Tailwind/UnoCSS globs · docs indexers · SSG/codegen over `**/*.md`). Deliberately prose; no config-sniffing (YAGNI).
