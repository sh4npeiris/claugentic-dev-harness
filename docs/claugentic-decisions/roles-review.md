Don't-re-break: **craft-floor calibration** favors concrete craft guidance over auditor-scannability (motion ratios/bands/béziers stay `[J]`); design-sync-generic is one optional model-upheld source (never flagship/required); runtime-felt-observation = OPT-IN, never default (ROADMAP experience-craft track, with the `transition`-state enum).

Model-upheld: the orchestrator convenes it. A lone reviewer can bless what a panel rejects.
- **Roster maps to distinct FUNCTIONS/POSTURES, not 1:1 to a label — same-posture work is a MODE, not a new agent file** (canonical: WORKFLOW → Roles). Distinct POSTURES stay separate (find ≠ refute ≠ gate ≠ generate ≠ critique); splitting the SAME posture across two files is a DRY violation with no independence benefit — so `synthesizer-gate` = 3 caller contracts, `lens-reviewer` has a whole-scope mode, `product-designer` an elevate mode. Roster = **exactly the tracked `.claude/agents/*.md` set** — no count is restated here; it is pinned three ways (the doc ↔ `git ls-files` ↔ `plugin.json:agents`) in `tests/test_adopter_pointer_integrity.py`, added 2026-08-18 (0041 S12b) because the canonical roster had silently dropped two shipped agents. Agent prompts are **self-contained** — they cannot follow links at spawn, so the DoD gate list is deliberately duplicated inline in the builder/verifier agents (controlled duplication, not drift).
- **`runtime-qa` is a real agent at the DRIVE step ONLY (0026 §C5a).** The QA driver (the one spawn that runs the app + verifies a criterion) is the `runtime-qa` specialist (`engine/qa.js` drive spawn); **boot + teardown STAY bare `"general-purpose"`** (mechanical lifecycle). `tools: *`. Posture: READ-ONLY on source · NON-DESTRUCTIVE · push the safety/negative paths · ONE required intent-vs-behavior judgment, surfaced through the EXISTING `DRIVER_SCHEMA` fields — **no schema change, no synthetic `expect`s.** It **attempts + tags** (never "proves the app correct"); an undrivable criterion is `notCheckable`, never a fake pass.
- **Lens-coverage on the Verify side — "loud advisory + presence-check" (0026 §A; the full glob-driven mechanical completeness gate was REJECTED).** `verify.js` has a **mechanical presence-assertion**: a NAMED `args.dimensions` lens that produced no usable result forces `CHANGES_REQUIRED` — the panel can't report all-green with one of its own named lenses missing. This is a **presence-check on the panel's OWN outputs, NOT a completeness gate over the diff** (does not promote `load_scope` to a gate). Plus a **mechanical test-diff rule**: a test-touching change MUST include the `testing` lens (a green suite can hide a loosened assertion) — absent ⇒ fail loud. **`load_scope.globs` STAYS advisory;** relevant-but-unselected-lens surfacing is **model-upheld.**
- **The Product Excellence pass elevates the spec — `product-designer` elevate mode proposes, the user decides** (canonical: `skills/product/SKILL.md`; folded the former `product-critic` here). It is **generative/proposing → builder-class** (nothing gates on its output); critiques **by method, not a checklist** (incl. a **mandatory premise-challenge**); points at `product-ux.md` (no new module). Proposals are **questions, never spec content until adopted** (adopt/adapt/reject/defer) — extends, never violates, the never-invent-scope rule; **rejected proposals + a declined-pass marker** persist in a user-owned fence in `docs/claugentic-PRODUCT_SPEC.md`; a **deferred** one lands in ROADMAP. **Deep-research informs, doesn't certify** (unavailable → honest decline + critique-only fallback; benchmark claims tagged model-knowledge-not-verified). Default-on, skippable on ask; it raises the bar, never guarantees the spec is excellent.
