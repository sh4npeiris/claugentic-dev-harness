- **The tree-check is language-incidental** — harness tooling that never parses project source; it stays Python with `INCLUDE_GLOBS` as the **single per-repo knob** (the valid-extension set is derived from it). - **The deterministic trust-gates for unwatched runs** (a land-gate hook · a secret-scan) are **not built** — and the harness says so rather than claiming them (asserting "cannot land red" before such hooks exist would be the over-claim the harness forbids); build-to-green is **a reduction of unwatched-run risk, never a substitute** for these unbuilt gates, and its decline names which unlock conditions are unmet (see Build mode). *(The red-first/characterization test-first enforcement hook was considered and DECLINED — 0035 rejected 2026-07-04; see the methodology line.)*
- **The gate scripts self-anchor to their own repo root at runtime (CWD-independent).** A `_repo_root()` helper derives the root from the script's own location — **never** an absolute/hardcoded path, so it's portable across machines/adopters; **all user-facing output stays repo-relative** (no machine-path leak). The helper is **duplicated, not shared** (the copied tree-check can't import a harness-repo module — each gate is independently self-contained). Stdout/stderr are reconfigured to UTF-8 (em-dashes must not mojibake on Windows cp1252).
- **Warn-and-pass hook posture (user-decided 2026-08-13, 0041 S5).** Infrastructure failure never blocks a commit: broken git passes **silently** (no repo to report into); a missing/broken interpreter (probed `python3` then `python`, floor 3.7) or a missing gate script skips **loudly** (one stderr line) and passes. Only a gate that RAN and failed — or crashes once started — aborts. Advisory on interpreter-less machines (doctor's interpreter-health row = Slice 6). A chained gate's advisory output rides **stderr** — the wrapper eats stdout (see INVARIANTS).
