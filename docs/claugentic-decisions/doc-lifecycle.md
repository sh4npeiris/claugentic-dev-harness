- **Escape-valve ladder + per-repo caps config (0038 S3).** When condensation genuinely can't reach the band (all-live content), the ordered recourse is **(1) promote to home** (INVARIANTS/CLAUDE.md — respecting THEIR caps, a cascade not a loop) → **(2) a RECORDED cap-bump** (raise the file's cap + a dated DECISIONS line — a `[J]` recorded decision, NEVER a mechanical ceiling-raise; git holds the prior cap) → **(3) shard = LAST resort**, built and climbed here (plan 0040: index + `docs/claugentic-decisions/*.md`); for an adopter it stays the optional last resort, one caps-config key per shard (`skills/doctor/SKILL.md` owns that procedure). **Rung 2 was deliberately SKIPPED here:** a recorded cap-bump is the right answer for a *log* (entries supersede, so condensation reclaims bytes) and a treadmill for a *rule-book* (entries persist by design and the post-condense floor trends upward) — bumping defers, it does not resolve. **The INDEX's own recourse IS rung 2**: a routing table is all-live, cannot itself be sharded, and growth-by-new-shards legitimately raises its cap. The principle the rung encodes: **bound what an agent READS per consult, not what the harness KNOWS.** Canonical: WORKFLOW → *The escape-valve ladder*. **DRY — exactly one cap source per repo:** `.claude/claugentic-doc-budgets.json` (reader-contract owned by `skills/doctor/SKILL.md`) is **per-repo and repo-owned, and the release ships NO live copy** — an adopter never inherits harness-tuned numbers; the harness's own caps live in its **tracked** copy and the gate only READS it. **Do not delete that file on the strength of the sentence above:** an absent config is a silent no-op exit 0, so removing it disarms the gate everywhere while staying green locally (un-ignored in `.gitignore`, pinned tracked by a test).
- **Setting a NEW cap: pick the band, never the measurement (2026-08-12, 0041 Stage-3 R2).** Rung 2 forbids an *unrecorded* cap raise; the same act hides in choosing a **first** cap for a newly-budgeted file. **Cap-at-current-size is a ceiling-raise wearing the other face** — and so is any cap the file already sits at 90-99% of: it lands green and **WARNs on the next append**, making every later edit a forced condensation, which is the ceiling-blessing this ladder exists to prevent. **Rule: the cap is chosen so the file lands at ~80% of it, and the condensation work to get there rides the same slice as the cap.** Declined and do-not-re-propose: capping a file at its measured size "to stop the bleeding." **Second half, from the WORKFLOW counter-example (corrected 2026-08-18, 0041 S12b):** pairing a cap with a hard condensation AC in the same slice was specced and then **measured impossible** — the full density-lever list shed less than the AC demanded and would have landed *above* the new cap's WARN line, i.e. permanent WARN on day one. The AC was **withdrawn as unreachable, not quietly missed**; the recourse is the next entry. Never let a condensation AC stand in for arithmetic the cap cannot support — the AC is what breaks first. **And size a NEW cap against the file's measured GROWTH RATE, not today's bytes:** WORKFLOW grew ~1,149 B/slice across the eleven slices *preceding* the one chartered to cut it, which is what made the target unreachable. **Applies to adopter seeding too**, which is precisely why a day-one-over case needs the `reportOnly` grace flag rather than a bigger number.
