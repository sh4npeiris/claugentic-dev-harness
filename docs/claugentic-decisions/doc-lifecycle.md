- **Adopter doc-lifecycle trigger + operator (0038).** The adopter's doc-budget trigger is **`/doctor`'s config-driven advisory** (reads `.claude/claugentic-doc-budgets.json`, skip-when-absent, `[D]` byte / `[J]` "condense soon" — an advisory, **NOT a gate/hook**), replacing the stripped `check_doc_budgets.py` WARN an adopter's repo can't produce. **`/condense`** is the executable condensation operator (classify-first anti-footgun — landed-records are the PRIMARY target, never preserved; no cut-decider; reuses `/doctor`'s user-approved-diff apply-path; **accept-floor = clear the WARN with headroom**, ~80% reached only when absorbable settled bulk exists). - **Escape-valve ladder + per-repo caps config (0038 S3).** When condensation genuinely can't reach the band (all-live content), the ordered recourse is **(1) promote to home** (INVARIANTS/CLAUDE.md — respecting THEIR caps, a cascade not a loop) → **(2) a RECORDED cap-bump** (raise the file's cap + a dated DECISIONS line — a `[J]` recorded decision, NEVER a mechanical ceiling-raise; git holds the prior cap) → **(3) shard = LAST resort — BUILT and CLIMBED (decided 2026-07-16, landed 2026-07-30, plan 0040)**: the harness sharded its OWN decisions ledger (index + `docs/claugentic-decisions/*.md`); for an adopter it stays the optional last resort (one caps-config key per shard — `skills/doctor/SKILL.md` owns that procedure). **Rung 2 was deliberately SKIPPED here:** a recorded cap-bump is the right answer for a *log* (entries supersede, so condensation reclaims bytes) and a treadmill for a *rule-book* (entries persist by design and the post-condense floor trends upward) — bumping defers, it does not resolve. **The INDEX's own recourse IS rung 2**: a routing table is all-live, cannot itself be sharded, and growth-by-new-shards legitimately raises its cap — different content class, different rung. The principle the rung encodes: **bound what an agent READS per consult, not what the harness KNOWS.** Canonical: WORKFLOW → *The escape-valve ladder*. **DRY — exactly one cap source per repo:** the caps config `.claude/claugentic-doc-budgets.json` (reader-contract owned by `skills/doctor/SKILL.md`) is **adopter-owned / adopter-created — the harness ships NO live copy** (its own caps are `DOC_BUDGETS` in `check_doc_budgets.py`; a live config here would be a second cap source). - **Setting a NEW cap: pick the band, never the measurement (2026-08-12, 0041 Stage-3 R2).** Rung 2 forbids an *unrecorded* cap raise; the same act hides in choosing a **first** cap for a newly-budgeted file. **Cap-at-current-size is a ceiling-raise wearing the other face** — and so is any cap the file already sits at 90-99% of: it lands green and **WARNs on the next append**, making every later edit a forced condensation, which is the ceiling-blessing this ladder exists to prevent. **Rule: the cap is chosen so the file lands at ~80% of it, and the condensation work to get there rides the same slice as the cap.** Declined and do-not-re-propose: capping a file at its measured size "to stop the bleeding." *Worked case:* `docs/claugentic-WORKFLOW.md` measured 83,383 B; relocation alone leaves 73,590 B, so a 70,000 B cap **breaches on landing** and any cap that clears it (≥74 KB) parks the file at permanent WARN — resolved by pairing the 70,000 B cap with a hard ≤ 56,000 B condensation AC in the same slice, never by sizing the cap to the file. **Applies to adopter seeding too**: a seeded cap is subject to this rule, which is precisely why the day-one-over case needs the `reportOnly` grace flag rather than a bigger number.
