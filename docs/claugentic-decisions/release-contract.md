# Release contract

Part of the decisions ledger — index & filing rule: `docs/claugentic-DECISIONS.md`. Do not link this file from outside the index.

- **Release/init consistency contract** — canonical in INVARIANTS §*release strips ⇒ init recreates ⇒ nothing dangles*, test-pinned. The ledger-side delta: nothing SHIPPED may run a harness-self gate without adopter-awareness, and doctor gets that from **per-script presence** — run a gate iff its script is present, else N-A; no separate adopter flag.
- **Binary assets SHIP and are SKIPPED from the shipped-content text scan** (the README ships `docs/diagrams/*.png`): `check_shipped_content` skips a shipped file whose suffix is in `BINARY_EXTENSIONS` — a binary asset has no text for any pass. The skip is by KNOWN-BINARY EXTENSION ONLY; a non-binary-extension file that fails to UTF-8-decode is genuine corruption and STILL fails loud. The condensation-trigger test reuses this reader (one source for the skip).
- **The ship/strip manifest is a class-annotated dict (0034).** `build_release.DEV_ONLY_PATH_CLASSES` (`path -> recreate-class`) is the **single authored semantics** of the dev-only partition (its `classify()`/`is_dev_only()`/`recreate_class()` accessors and the `DEV_ONLY_FILES` keys-alias all derive from it). **Six classes, one per entry (exhaustive):** `init-seed` · `init-gen` · `recreate-on-demand` (a NON-init mechanism recreates it; the class IS its own recreatability attestation) · `self-gate` · `config` · `dangle` (RELEASE_CHECKLIST — never recreated). `DEV_ONLY_DIRS` stays OUT of the classes (`recreate_class` returns `None` for a dir-swept path).
- **A file leaves the strip manifest by DELETION, never by a class rename (0041 S6, 2026-08-14).** The policy is **default-include**, so deleting a path's line IS the ship — there is no "ships" class to switch to; **any** class value keeps it stripped, and an *unrecognized* one additionally falls through to Pass A.a's dangling-basename scan, hard-failing every shipped doc that mentions it. **Zero gate-code edits:** `HARNESS_SELF_SCRIPTS`, `dangling_paths()` and Pass D's loops re-derive from the manifest — hand-editing a derived set breaks the single-source design. (That is how the doc-budget gate shipped; the caps are per-repo DATA it only reads, and no caps config = a quiet exit-0 no-op.) **Cost, accepted:** the basename leaves Pass A.b's caveat scan, so no gate flags stale "harness-self / stripped" copy about it; `tests/test_shipped_condensation_trigger.py` pins only the inverse (no shipped line caveats this gate away). The caps CONFIG stays `init-gen`/stripped; init seeds an adopter's own (0041 S7, create-if-absent).
- **Ship-class ≠ DELIVERY, and the harness's own copy is born-prefixed (0041 S6–S7).** Payload membership does not put a script in an adopter's repo — adopter invocation needs an `init` DELIVERY step; substituting the plugin's own copy is refuted by construction, since `_repo_root()` anchors on `__file__` and so measures the HARNESS's tree (a verdict about the wrong repo). Resolved COPY-WITH-RENAME: the harness's copy is `scripts/claugentic-check_doc_budgets.py`. **The repo-side rename was forced, not cosmetic:** the wrapper template and the shipped hook are pinned run-logic-identical, so ONE chain line must name ONE path in both repos — divergence breaks the parity pin, a prefixed line over an unprefixed repo copy prints a SKIPPED notice on every harness commit forever, and a try-both fallback would run an adopter's unrelated script as a commit gate. The scans in `tests/test_shipped_condensation_trigger.py` keep matching the **bare** `check_doc_budgets.py` token (released CHANGELOG history spells the old path; the prefixed name contains the bare one).
- **Referential-closure gate (0034 — Pass D), hand-lists derived.** `check_shipped_content.py`'s 3 partition sets (`_RECREATED`/`HARNESS_SELF_SCRIPTS`/`_DANGLE_EXCLUDED`) are **derived** from `build_release.recreate_class` (no second hand-list). **Pass D** asserts `NEEDS ⊆ HAS` — every stripped adopter-relevant path is producible/recreatable via its class's HAS source — mechanizing that INVARIANT (prose-only before). **Do-not-re-litigate:** `recreate-on-demand` (INVARIANTS/PRODUCT/PRODUCT_SPEC) is satisfied VIA the class, **NOT** by claiming `init` produces it. **Honest scope:** pins referential closure, NOT that the release is *correct* / "fully" content-enforced; force-push + eval-drift stay `[J]`; honor the `INCLUDE_GLOBS` carve-out.
- **Single-command release build (0034; its publish half is superseded below).** `python scripts/build_release.py --apply [--bump <version>]` is the ONE build path; it prepares, prints the gated command, and **never tags and never pushes, at either call site** (do-not-re-break). The guards to know before editing it: `--bump` writes BOTH manifests from one arg by a **targeted version-field replace** (both-or-neither, idempotent, one-line diff; **never** a `json.dumps` reflow); version-must-increase is a semver **ordinal** anchored on the latest `vX.Y.Z` **tag**; the build **copies + stages the bumped manifests into the built worktree**, since building from committed HEAD would ship the OLD version (test-pinned); and the built stripped tree is validated from OUTSIDE it (`--root <tmp>` from the dev checkout — the build strips `scripts/`+`tests/`). `check_versions_synced.py` stays a SEPARATE gate. **Honest scope:** the guards *reduce* risk; the eval-drift/BASELINE check stays `[J]`.
- **Shipped-content scanner + seed-migration (three durable rules; contract in WORKFLOW DoD gate 5 + INVARIANTS).** (a) `scripts/check_shipped_content.py` is the sibling-script (see *One gate, one invariant*) collapsing the stripped-path grep + the namespace scan, importing `build_release.classify()` as the one ship source-of-truth. (b) The valid namespace set = **agent basenames ∪ skill basenames ∪ `{update}`** (FS-derived; the prefix names both agent-spawn ids AND slash-commands, so a roster-only set false-fails on command tokens). (c) Underscore-prefix `_X.md` = the **one-time-seed** convention, kept OUT of the managed-set table so REFRESH can't clobber a filled ledger (never-clobber = two guards).
- **Release base-ancestry guard:** anchor on current `origin/main` (`git fetch` first) + run the `git range-diff` drop-check before tagging; `build_release.py --apply` mechanically refuses a stale base — broadened to catch a direct NON-merge push, after one silently dropped merged work — at BOTH call sites (the local prepare and the workflow's publish job — hence `release.yml`'s explicit `origin/main` fetch). **That guard is REVERSE inclusion** (`origin/main` ⊆ HEAD), so it does NOT establish the tagged commit is *on* main — `release.yml`'s gates job adds the forward check (`git merge-base --is-ancestor "$GITHUB_SHA" origin/main`), which is what makes "tag only what landed" a gate rather than a habit. The `release`-branch force-push is the workflow's (leased); **no human command *in the flow* pushes it** (model-upheld — see the publisher note below). Restoring dropped work is a **HYBRID selective file-by-file restore, never a `git merge`**, and an honesty-sensitive one starts its scrubbed-file set from `main` so a forbidden claim cannot return (canonical in INVARIANTS).
- **2026-08-12 — CI PUBLISHES (0041 S2); supersedes the publish half of the 0034 entry above.** **Which act is gated:** the human's ONE act is `git tag vX.Y.Z && git push origin main vX.Y.Z` (class-(c), user-gated); `.github/workflows/release.yml` (`on: push tags v*`; least-privilege `permissions`, with `contents: write` on the `publish` job only, which `needs: gates`) then re-runs every gate at the tagged commit — including the tag↔`plugin.json` match and `claude plugin validate --strict` — and only on green invokes **`build_release.py --apply`** (never hand-rolled YAML build/push logic), pushes `release` under a lease-equivalent fetch-and-compare, and creates the Release. **The version guard inverts, narrowly:** `_version_increase_error` demands strictly-greater at prepare time but allows **equal iff `v<new>` points at HEAD** (the publish-time run); equal anywhere else stays refused. **Burned-version recovery:** the tag precedes publishing, so a red run SPENDS that version — **bump forward to the next patch; a tag is never reused** (deleting the failed tag is the outward, user-gated exception). **Honest scope:** the **content** publishes only on green, but `marketplace.json` (the catalog's advertised version, on `main`) is written at prepare time — a failed run leaves an advertised-but-unserved version until the re-run lands. "The workflow is the only publisher" is **tooling-upheld, not enforced**: `release` carries no protection rule, so a restrict-push ruleset is what would make it mechanical (see INVARIANTS). The local red-CI preflight is **advisory** (warn-only; silent-skip without `gh`/network) — `release.yml` is the gate. **Aborted prepare:** no tag and no push, but the rebuilt local `release` branch + bumped manifests remain. Test-pinned: `tests/test_release_workflow.py` + `tests/test_build_release.py`.
- **2026-08-19 — an OS-gated CI step must have its matrix leg pinned.** `if: runner.os == 'X'` fires only if the job's matrix still carries an X leg. Drop the leg and the step SKIPS while the job still reports **success** — and `publish` needs only `gates` to succeed. That silently voids the release's three Linux-only guards: the on-main ancestry check (the authorization gate), the CLI install, and `claude plugin validate --strict`. Pinned by `tests/test_release_workflow.py` → `TestGateParity::test_every_os_gated_step_still_has_a_leg_to_run_on`, which derives BOTH sides from the file (no step name, no `ubuntu-latest` literal), so a rename or a legitimate restructure stays green and only a can-never-fire condition goes red. Mutation-verified. **Third instance of the green-test/deleted-guard class: a guard is unpinned until a mutation makes its test go red.**
- **An accreting ledger gets a doc-budget row even when read on-demand, not auto-loaded** (0024 — INVARIANTS; the caps config carries the number): the gate is its only growth-bound.
- **Declined 2026-08-12 (0041 S2) — do not re-propose without new evidence: SHA-pinning the release pipeline's floating deps.** `claude plugin validate --strict` installs fresh per run (`npm install -g @anthropic-ai/claude-code`, including inside the credentialed `publish` job), and `actions/*@vN` majors are mutable. **Deliberate:** a pinned validator validates yesterday's manifest rules — worse validation than a moving one — and the pin treadmill costs more than it buys on a public repo whose deps fail loud in `ci.yml` on `main` first; recorded as an **accepted risk** in `docs/RELEASE_CHECKLIST.md` → Honest scope. Declined with it: an action-major floor registry (`MIN_ACTION_MAJORS` — could only fail on an act nobody performs, and went stale silently) and a `concurrency:` group on `release.yml` (the lease already makes two parallel tag runs safe-and-loud). Dependabot (`github-actions`) is the open alternative → ROADMAP.
