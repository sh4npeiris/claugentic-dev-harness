# Release contract

Part of the decisions ledger — index & filing rule: `docs/claugentic-DECISIONS.md`. Do not link this file from outside the index.

- **Release/init consistency contract** (canonical in INVARIANTS): what the release strips that's adopter-relevant, `init` must (re)create/manage; nothing SHIPPED may reference a stripped-uncreated file or run a harness-self gate without adopter-awareness (doctor uses **per-script presence** — run a gate iff its script is present, else N-A; no separate adopter flag). Test-pinned.
- **Binary assets SHIP and are SKIPPED from the shipped-content text scan:** the README ships `docs/diagrams/*.png` flow diagrams. `check_shipped_content` skips a shipped file whose suffix is in `BINARY_EXTENSIONS` (a module `frozenset` — images/fonts/archives/media) — a binary asset has no text for any pass. The skip is by KNOWN-BINARY EXTENSION ONLY; a non-binary-extension file that fails to UTF-8-decode is genuine corruption and STILL fails loud (contract preserved). The condensation-trigger test reuses this reader (single source of the skip contract).
- **The ship/strip manifest is a class-annotated dict (0034 Slice 1).** `build_release.DEV_ONLY_PATH_CLASSES` (`path -> recreate-class`) is the **single authored semantics** of the dev-only partition (`classify()`/`is_dev_only()`/`recreate_class()` derive from it; `DEV_ONLY_FILES` is a keys-alias for back-compat). **Six classes, one per entry (exhaustive partition):** `init-seed` · `init-gen` · `recreate-on-demand` (a NON-init mechanism recreates it; the class IS its own recreatability attestation) · `self-gate` · `config` · `dangle` (RELEASE_CHECKLIST — never recreated). `DEV_ONLY_DIRS` stays OUT of the classes (`recreate_class` returns `None` for a dir-swept path). **Provable no-op:** a test pins the shipped set byte-identical across the frozenset→dict change.
- **Referential-closure gate (0034 S3 — Pass D) + hand-lists derived (S2).** `check_shipped_content.py`'s 3 partition sets (`_RECREATED`/`HARNESS_SELF_SCRIPTS`/`_DANGLE_EXCLUDED`) are **derived** from `build_release.recreate_class` (no second hand-list). **Pass D** asserts `NEEDS ⊆ HAS` — every stripped adopter-relevant path is producible/recreatable via its class's HAS source — mechanizing the prose-only *release strips ⇒ init recreates ⇒ nothing dangles* INVARIANT. **Do-not-re-litigate:** `recreate-on-demand` (INVARIANTS/PRODUCT/PRODUCT_SPEC) is satisfied VIA the class, **NOT** by claiming `init` produces it. **Honest scope:** pins referential closure, NOT that the release is *correct* / "fully" content-enforced; force-push + eval-drift stay `[J]`; honor the `INCLUDE_GLOBS` carve-out.
- **Single-command release + hardening guards (0034 S4–S10).** `python scripts/build_release.py --apply --bump <version>` is the ONE entry point: preconditions (broadened stale-base — catches a direct NON-merge push to `origin/main`) → `--bump` writes BOTH manifests from one arg via a **targeted version-field replace** (one-line diff, both-or-neither, idempotent; **never** `json.dumps` reflow) → version-must-increase (semver **ordinal**, anchored on the latest `vX.Y.Z` **tag**) → build (the `--apply` build **copies + stages the bumped manifests into the built worktree** so the release advertises the version it ships — building from committed HEAD would carry the OLD version; test-pinned) → validate the built stripped tree (`check_shipped_content.py --root <tmp>` from the dev checkout — the built tree strips scripts/tests, so it's validated from OUTSIDE) → mechanized drop-check (`origin/main`-not-`HEAD` ⊆ strip-set) → commit build → **STOP + print** the gated `git tag / push --force-with-lease / push tag`. **Do-not-re-break:** the `vX.Y.Z` tag is created ONLY at publish (in the printed command), **never in `--apply`** — an aborted/declined run leaves **zero side effects** (no tag, no push). **One-time prereq:** a retroactive **`v0.3.1` bootstrap tag** must exist (tag history stops at `v0.2.0`) or the version guard would wave through a `0.3.0` downgrade. `check_versions_synced.py` stays a SEPARATE gate. **Honest scope:** "one command up to a single human-gated push," **NOT** fully automated — force-push + the eval-drift/BASELINE check stay `[J]`; the guards *reduce* risk, none makes the release "correct"/"fully enforced." Marketplace-ref repoint deferred (ROADMAP); `RELEASE_CHECKLIST.md` is a thin wrapper.
- **Shipped-content scanner + seed-migration (the three durable rules; contract in WORKFLOW DoD gate 5 + INVARIANTS).** (a) `scripts/check_shipped_content.py` is the sibling-script (see *One gate, one invariant*) collapsing the stripped-path grep + the namespace scan (imports `build_release.classify()` as the one ship source-of-truth). (b) The valid namespace set = **agent basenames ∪ skill basenames ∪ `{update}`** (FS-derived — the `claugentic-dev-harness:` prefix names both agent-spawn ids AND slash-commands, so a roster-only set false-fails on command tokens). (c) Underscore-prefix `_X.md` = the **one-time-seed** convention, kept OUT of the managed-set table so REFRESH can't clobber a filled ledger (never-clobber = two guards).
- **Release base-ancestry guard:** anchor on current `origin/main` (`git fetch` first) + run the `git range-diff` drop-check before any `@release` force-push; `build_release.py --apply` mechanically refuses a stale base (which once silently dropped merged work), force-push stays checklist-gated. Restoring dropped work uses a **HYBRID selective file-by-file restore, never a `git merge`**; any honesty-sensitive restore starts the scrubbed-file set from `main` so a forbidden claim cannot return (see INVARIANTS).
