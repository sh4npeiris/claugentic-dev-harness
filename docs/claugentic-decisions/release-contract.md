# Release contract

Part of the decisions ledger — index & filing rule: `docs/claugentic-DECISIONS.md`. Do not link this file from outside the index.

- **Release/init consistency contract** (canonical in INVARIANTS): what the release strips that's adopter-relevant, `init` must (re)create/manage; nothing SHIPPED may reference a stripped-uncreated file or run a harness-self gate without adopter-awareness (doctor uses **per-script presence** — run a gate iff its script is present, else N-A; no separate adopter flag). Test-pinned.
- **Binary assets SHIP and are SKIPPED from the shipped-content text scan:** the README ships `docs/diagrams/*.png` flow diagrams. `check_shipped_content` skips a shipped file whose suffix is in `BINARY_EXTENSIONS` (a module `frozenset` — images/fonts/archives/media) — a binary asset has no text for any pass. The skip is by KNOWN-BINARY EXTENSION ONLY; a non-binary-extension file that fails to UTF-8-decode is genuine corruption and STILL fails loud (contract preserved). The condensation-trigger test reuses this reader (single source of the skip contract).
- **The ship/strip manifest is a class-annotated dict (0034 Slice 1).** `build_release.DEV_ONLY_PATH_CLASSES` (`path -> recreate-class`) is the **single authored semantics** of the dev-only partition (`classify()`/`is_dev_only()`/`recreate_class()` derive from it; `DEV_ONLY_FILES` is a keys-alias for back-compat). **Six classes, one per entry (exhaustive partition):** `init-seed` · `init-gen` · `recreate-on-demand` (a NON-init mechanism recreates it; the class IS its own recreatability attestation) · `self-gate` · `config` · `dangle` (RELEASE_CHECKLIST — never recreated). `DEV_ONLY_DIRS` stays OUT of the classes (`recreate_class` returns `None` for a dir-swept path). **Provable no-op:** a test pins the shipped set byte-identical across the frozenset→dict change.
- **Referential-closure gate (0034 S3 — Pass D) + hand-lists derived (S2).** `check_shipped_content.py`'s 3 partition sets (`_RECREATED`/`HARNESS_SELF_SCRIPTS`/`_DANGLE_EXCLUDED`) are **derived** from `build_release.recreate_class` (no second hand-list). **Pass D** asserts `NEEDS ⊆ HAS` — every stripped adopter-relevant path is producible/recreatable via its class's HAS source — mechanizing the prose-only *release strips ⇒ init recreates ⇒ nothing dangles* INVARIANT. **Do-not-re-litigate:** `recreate-on-demand` (INVARIANTS/PRODUCT/PRODUCT_SPEC) is satisfied VIA the class, **NOT** by claiming `init` produces it. **Honest scope:** pins referential closure, NOT that the release is *correct* / "fully" content-enforced; force-push + eval-drift stay `[J]`; honor the `INCLUDE_GLOBS` carve-out.
- **Single-command release build + hardening guards (0034 S4–S10; publish step superseded by the 2026-08-12 CI-publishes entry below).** `python scripts/build_release.py --apply [--bump <version>]` is the ONE build path: preconditions (broadened stale-base — catches a direct NON-merge push to `origin/main`) → `--bump` writes BOTH manifests from one arg via a **targeted version-field replace** (one-line diff, both-or-neither, idempotent; **never** `json.dumps` reflow) → version-must-increase (semver **ordinal**, anchored on the latest `vX.Y.Z` **tag**) → build (the `--apply --bump` build **copies + stages the bumped manifests into the built worktree** so the release advertises the version it ships — building from committed HEAD would carry the OLD version; test-pinned) → validate the built stripped tree (`check_shipped_content.py --root <tmp>` from the dev checkout — the built tree strips scripts/tests, so it's validated from OUTSIDE) → mechanized drop-check (`origin/main`-not-`HEAD` ⊆ strip-set) → commit build → **STOP + print** the gated command. **Do-not-re-break:** the script itself **never tags and never pushes**, at either call site. **One-time prereq:** a retroactive **`v0.3.1` bootstrap tag** must exist (tag history stops at `v0.2.0`) or the version guard would wave through a `0.3.0` downgrade. `check_versions_synced.py` stays a SEPARATE gate. **Honest scope:** the guards *reduce* risk; none makes the release "correct"/"fully enforced," and the eval-drift/BASELINE check stays `[J]`. Marketplace-ref repoint deferred (ROADMAP).
- **Shipped-content scanner + seed-migration (the three durable rules; contract in WORKFLOW DoD gate 5 + INVARIANTS).** (a) `scripts/check_shipped_content.py` is the sibling-script (see *One gate, one invariant*) collapsing the stripped-path grep + the namespace scan (imports `build_release.classify()` as the one ship source-of-truth). (b) The valid namespace set = **agent basenames ∪ skill basenames ∪ `{update}`** (FS-derived — the `claugentic-dev-harness:` prefix names both agent-spawn ids AND slash-commands, so a roster-only set false-fails on command tokens). (c) Underscore-prefix `_X.md` = the **one-time-seed** convention, kept OUT of the managed-set table so REFRESH can't clobber a filled ledger (never-clobber = two guards).
- **Release base-ancestry guard:** anchor on current `origin/main` (`git fetch` first) + run the `git range-diff` drop-check before tagging; `build_release.py --apply` mechanically refuses a stale base (which once silently dropped merged work) at BOTH call sites — the local prepare and the workflow's publish job, which is why `release.yml` fetches `origin/main` explicitly. **That guard is REVERSE inclusion** (`origin/main` ⊆ HEAD), so it does NOT establish the tagged commit is *on* main — `release.yml`'s gates job adds the forward check (`git merge-base --is-ancestor "$GITHUB_SHA" origin/main`), which is what makes "tag only what landed" a gate rather than a habit. The `release`-branch force-push is now the workflow's (leased); **no human command *in the flow* pushes it — model-upheld, since `release` is not branch-protected** (a restrict-push ruleset would make it mechanical). Restoring dropped work uses a **HYBRID selective file-by-file restore, never a `git merge`**; any honesty-sensitive restore starts the scrubbed-file set from `main` so a forbidden claim cannot return (see INVARIANTS).
- **2026-08-12 — CI PUBLISHES (0041 S2); supersedes the publish half of the 0034 entry above.** The release shape is now *prepare locally → push one tag → the workflow publishes*. **Which act is gated:** the human's ONE act is `git tag vX.Y.Z && git push origin main vX.Y.Z` (class-(c), user-gated); `.github/workflows/release.yml` (`on: push tags v*`, workflow-level `permissions: contents: read` with `contents: write` granted to the `publish` job only, `needs: gates`) then re-runs the full suite + node tests + the four gate scripts + the tag↔`plugin.json` match + `claude plugin validate --strict` at the tagged commit, and only on green invokes **`build_release.py --apply`** (never hand-rolled YAML build/push logic) and pushes `release` under a lease-equivalent fetch-and-compare + creates the GitHub Release. **The version guard inverts, narrowly:** `_version_increase_error` still demands strictly-greater at prepare time, but allows **equal iff `v<new>` points at HEAD** (the publish-time run) — equal at any other commit stays refused. **Burned-version recovery:** the tag now precedes publishing, so a red run SPENDS that version — **bump forward to the next patch; a tag is never reused** (deleting the failed tag is the outward, user-gated exception). **Honest scope:** the plugin **content** publishes only on green, but `marketplace.json` (the catalog's advertised version, on `main`) is written at prepare time — a failed run leaves an advertised-but-unserved version until the re-run lands. Offline publishing is retired from the flow — but "the workflow is the only publisher" is **tooling-upheld, not enforced**: `release` carries no protection rule (verified 2026-08-12), so a restrict-push ruleset is what would make it mechanical (see INVARIANTS). The local red-CI preflight is **advisory** (warn-only; silent-skip without `gh`/network) — `release.yml` is the gate. **Aborted-prepare side effects, stated exactly:** no tag and no push, but the rebuilt local `release` branch + bumped manifests remain (the old unqualified "zero side effects" is retired). Test-pinned: `tests/test_release_workflow.py` (workflow shape) + `tests/test_build_release.py` (guard semantics, printed command).
- **INVARIANTS gets a doc-budget row (20K)** (0024 S3): an *accreting* ledger (sibling to DECISIONS) whose only growth-bound is this gate — budgeted because it accretes, even though read **on-demand**, not auto-loaded. WARN@90% + breach@100% + condense-on-WARN apply for free.
- **Declined 2026-08-12 (0041 S2) — do not re-propose without new evidence: SHA-pinning the release pipeline's floating deps.** `claude plugin validate --strict` runs from `npm install -g @anthropic-ai/claude-code`, resolved fresh per run (including inside the credentialed `publish` job), and `actions/*@vN` majors are mutable. **Deliberate:** a pinned validator validates yesterday's manifest rules — worse validation than a moving one — and a SHA-pin treadmill costs more than it buys on a public repo whose deps fail loud in `ci.yml` on `main` first. Recorded as an **accepted risk** in `docs/RELEASE_CHECKLIST.md` → Honest scope. Also declined in the same pass: an action-major floor registry (`MIN_ACTION_MAJORS` — could only fail on an act nobody performs, and went stale silently) and a `concurrency:` group on `release.yml` (the lease already makes two parallel tag runs safe-and-loud; serializing changes semantics for no demonstrated need). Dependabot (`github-actions` ecosystem) is the open alternative → ROADMAP.
