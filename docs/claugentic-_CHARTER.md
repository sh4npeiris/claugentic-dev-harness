# Engineering charter — the living per-work-type methodology record

**This file is OPTIONAL and defaults-safe. Leave it empty and nothing changes** — every
kind of work you haven't recorded here falls back to the harness's default per-work
judgment. Nothing in it is required; there is **no "pick your methodology" gate**.

The harness fits the approach to the **nature of the work at hand**, per work-item, from
its toolbox of established practices (`docs/claugentic-WORKFLOW.md` → *Choosing the approach
for the work at hand — the methodology toolbox*, which holds the *when each fits* rationale —
this file does **not** restate it). This record captures the approach the project has
**settled on per kind of work**, so the choice stays consistent as the same kind of work
recurs. Five behaviors:

- **RECORD** — the first time a kind of work comes up and the fitting approach is judged
  (from the toolbox), write that mapping here (one entry, `work-type → chosen approach +
  brief rationale`).
- **APPLY** — when the same kind of work recurs, follow the recorded approach, so the
  project stays consistent across agents and sessions.
- **ADAPT** — a genuinely different work-nature is **not** forced into a recorded approach;
  judge what fits *that* work from the toolbox and record THAT for its type (no golden
  hammer).
- **GROW** — update an entry **in place** if a recorded approach proves wrong for that type
  (with a brief rationale). This is a record that learns, not an append-only log.
- **UPHOLD** — consistency **within** a work-type, adaptivity **across** work-types.

Each recorded approach is a **revisable default, not a mandate** — the prior to start from,
always overridable by a better fit that then updates the entry. Recorded **per work-TYPE,
update-not-append**: one bounded entry per kind of work, revised in place — never a line per
work-item.
